# Протокол relay gate4.ai, версия 1

Один TCP-порт (443). Relay читает SNI из ClientHello, не завершая рукопожатие:

| SNI | Что делает relay |
|---|---|
| `<домен relay>` | завершает свой TLS и отдаёт HTTP API (ниже) |
| `<device-id>.<домен relay>` | пробрасывает сырой TCP (вместе с уже прочитанным ClientHello) в новый yamux-поток туннеля устройства; TLS завершает устройство |
| имя из `--route host=addr` | пробрасывает сырой TCP (вместе с ClientHello) на `addr`; TLS, в том числе ACME TLS-ALPN-01, завершает бэкенд. Так на том же порту живёт сайт (`gate4.ai`). Имена relay и устройств маршрутом занять нельзя. С `--route host=addr,proxy` перед ClientHello бэкенд получает заголовок PROXY protocol v2 с настоящим адресом клиента; без него бэкенд видит все соединения с адреса relay — фильтровать по IP за relay нельзя |
| иное | сбрасывает соединение |

Если устройство офлайн, relay ждёт его туннель до 30 с (`HoldFor`), затем сбрасывает соединение; очереди нет, и ждать одно устройство могут не больше 32 соединений — лишние сбрасываются сразу. Неизвестные `device-id` сбрасываются сразу.

Пределы (флаги `gate4ai-relay`): одновременных TCP-соединений — 20 000 всего (`--max-conns`) и 256 с одного адреса (`--max-conns-per-ip`, IPv6 — сеть /64), лишние сбрасываются сразу. Проброс (устройство или маршрут) без данных в обе стороны дольше 10 минут закрывается. Соединение HTTP API: keep-alive без запросов — 2 минуты, тело запроса — 15 с, ответ — 30 с (кроме `/tunnel`: там keepalive yamux, 15 с).

## Аутентификация устройства

Запросы устройства несут заголовки `Authorization: Bearer <token>` и `X-Gate4ai-Device: <device-id>`. Relay хранит только хэш токена.

## HTTP API

| Метод и путь | Тело | Ответ |
|---|---|---|
| `POST /api/devices` | — | `{"device_id","token","host"}`; `403`, если регистрация закрыта; `429` — превышен лимит регистраций (5 в сутки с адреса, IPv6 — /64, `--reg-per-ip`; 500 в сутки всего, `--reg-per-day`); `503` — достигнут предел устройств (`--max-devices`) |
| `GET /tunnel` (WebSocket) | — | туннель: бинарные сообщения WebSocket — поток `net.Conn`; поверх него yamux, **устройство — yamux-сервер**, relay открывает потоки; `401` при неверных данных |
| `POST /api/acme/txt` | `{"name":"_acme-challenge.<device-id>.<домен>","value":"…"}` | ставит TXT; `403` для чужого имени; `400`, если `value` не base64url или длиннее 255 байт (значение ACME DNS-01 — 43 символа). На имя хранится не больше 2 значений: новое вытесняет самое старое. TXT, поставленные устройством с перерывом больше 10 минут, — разные заказы сертификата; заказов на устройство не больше 3 в сутки (`--cert-orders-per-device`), сверх — `429` |
| `DELETE /api/acme/txt` | то же | удаляет TXT |
| `POST /api/witness` | `{"seq":n,"head":"<64 hex>","ts":"RFC 3339","sig":"<128 hex: подпись Ed25519>"}` | `200`; `409`, если `seq` меньше уже принятого (признак переписывания журнала) или равен ему с другим `head`; тот же `seq` с тем же `head` — повтор, `200` без изменений; `400` при `seq` < 1, `head` не 32 байтах hex или `sig` не 64 байтах hex. Подпись relay не проверяет (открытого ключа журнала у него нет), проверяет её владелец журнала. Хранятся последние 1000 чекпоинтов устройства; чаще одного в 10 с (запас 60) — `429` |
| `GET /api/witness/{device-id}` | — | только с данными самого устройства (заголовки выше; иначе `401`): принятые чекпоинты `[{"seq","head","ts","sig","received_at"}]`, последние 1000 |
| `GET /api/health` | — | `{"ok":true}` |

## DNS

Relay — авторитетный DNS своей зоны: `A`/`AAAA` для `<домен>` и `*.<домен>` указывают на relay, `TXT _acme-challenge.<device-id>.<домен>` — значения, поставленные устройством через API. Запросы вне зоны — `REFUSED` (не открытый резолвер).

`CAA` у любого имени зоны — `issue` для каждого CA из `--caa` (по умолчанию `letsencrypt.org`; несколько через запятую — например, запасной CA для `relay.acme_ca` устройств; пустое значение — записей CAA нет, выпускать может любой CA).

Против отражённых атак: ответ по UDP не больше буфера клиента — 512 байт без EDNS0, иначе размер из EDNS0, но не больше 1232 байт; что не влезло, отрезается с битом `TC`, и клиент повторяет запрос по TCP. Запросы по UDP с одного адреса (IPv6 — /64) — не больше 50 в секунду (запас 100), сверх — без ответа.

`SOA` и `NS` (`ns1.<домен>`) — только у вершины зоны; для остальных имён и типов без записей — пустой ответ (NODATA) с `SOA` зоны в authority. По ним ACME-клиент устройства находит зону и её авторитетные серверы, проверяя `TXT`: если `SOA` отдаётся у каждого имени, зоной считается само `_acme-challenge.<device-id>.<домен>` без `NS`, сертификат устройства не выпускается и устройство не подключается. Родительская зона делегирует `<домен>` на `ns1.<домен>` (с glue-записью на адрес relay).

## Совместимость

Изменения протокола — только обратно совместимые в пределах версии 1; клиент устройства (`relayclient` в ядре) и relay выпускаются независимо.
