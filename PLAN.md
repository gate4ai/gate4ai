## Этап 23. ABI v2: семантика результата и аргументов как в MCP (решение человека 2026-10-15)

Коннектор не становится MCP-сервером: ABI остаётся границей песочницы (статический подписанный манифест, функции хоста, без сессий и уведомлений). Из MCP берём формы данных, чтобы MCP Front отдавал их без перекодирования.

- [x] Аргументы: `args` → `input_schema` — подмножество JSON Schema (object, string/number/integer/boolean, array, вложенные object, enum, format, default, minimum/maximum, maxLength, minItems/maxItems; лишних полей нет), порядок полей сохраняется (YAML и JSON); `Normalize` — рекурсивно; CLI: вложенные объекты и массивы объектов — JSON в значении флага; skill — пример по схеме; метки недоверенных аргументов — по всем вложенным строкам
- [x] Результат: `ExecResult` → `content[]` (text, image, resource, resource_link) + `structured`; `output_schema` в манифесте; хост проверяет блоки и `structured` по схеме (`abi.CheckResult`), иначе `invalid_result`; `result_ref`, `evidence`, `source` остаются своими
- [x] MCP Front: `outputSchema` (ответ gate4ai, результат коннектора — в `result`) для действий с `output_schema`; первый блок — ответ gate4ai, за ним блоки коннектора в форме MCP; блоки недоверенных действий — `_meta["gate4.ai/untrusted"]`; секреты маскируются и в текстовых блоках
- [x] Статусы проверки по connector-architecture.md: коннектор — `verified` / `not_confirmed` / `verify_after` (+ `verify_after_s` у `execute`), ошибка `verify` — «проверить не удалось»; хост — `pending` / `unverified`
- [x] Коннекторы v4: `files` (изображения — image, прочие двоичные — resource, обрезанный двоичный — ошибка), `browser` (скриншот — image агенту и доказательство), `mail`; манифест с `args` — понятная ошибка «ABI v1, пересоберите»
- [x] connector-architecture.md (раздел «Близость к MCP»), README sdk-go, architecture.md

- **Web UI (этап 25, 2026-10-15):** самонастройка через агента — обычное действие `gate4ai.change_policy` встроенного коннектора `gate4ai` под обычной политикой (решение человека: «такая же политика, как остальные»): по умолчанию подтверждение в любом канале; секреты не задаются. Спецификация 0.5 согласована и внесена (D1, D3). Обе правки спецификации (D1, D3 в [docs/ui-plan.md](docs/ui-plan.md)) согласованы человеком 2026-10-15 и внесены. Структурные правки из Web UI сериализуют конфигурацию заново и теряют комментарии YAML (как `relay register`); YAML-вкладка комментарии сохраняет. Поля настроек коннектора выводятся из `${setting:…}` в возможностях манифеста плюс подсказки для официальных коннекторов в ядре; схема настроек в манифесте — предложение для sdk-go (D8).
- **UX CLI (этап 24, 2026-10-15):** stdout остаётся JSON (спецификация, «Машиночитаемый вывод»); поля `hint` и `detail` только добавлены, подсказки человеку — в stderr и только при терминале, пустые состояния — в stderr всегда. Вывод для человека (решение человека 2026-10-15, спецификация обновлена): если stdout — терминал, списки и состояние владельца — таблицей, ошибки — текстом в stderr без JSON; `--json`, `GATE4AI_OUTPUT=json` — JSON, `GATE4AI_OUTPUT=table` и `approvals list --table` — таблица и вне терминала. Результаты действий и ответы команд-изменений (`agents token`, `policy set` и т. п.) остаются JSON. `gate4ai ui` запускает daemon сам, только если stdin и stderr — терминал и нет `--print`; скрипты получают прежнюю ошибку с кодом 6. Daemon в фоне — отдельная сессия (setsid; на Windows DETACHED_PROCESS), вывод — `<home>/daemon.log`. Автозапуск: systemd user unit с `Restart=on-failure` и `StartLimitBurst` (второй экземпляр не крутится по кругу), `service install` сначала останавливает daemon, запущенный руками; на Windows ключ Run вызывает `gate4ai daemon start` (окно консоли мелькает при входе); трей в автозапуск добавляется, но сразу не запускается (может быть уже запущен). Установщик daemon по-прежнему не запускает без `GATE4AI_START=1` (вопрос Y/n из UX-ONBOARDING не сделан: в `curl | sh` stdin занят скриптом). Магазин в начальной конфигурации — ключ registry из README. Трей: русский при русской локали (`GATE4AI_LANG`, `LC_ALL`, `LC_MESSAGES`, `LANGUAGE`, `LANG`), иначе английский, как CLI. Остановка daemon — `POST /v1/shutdown` только владельцу по сокету.
- **ABI v2 (этап 23, 2026-10-15):** коннектор не MCP-сервер, из MCP взяты только формы данных. Порядок полей схемы — порядок объявления (флаги CLI, skill). Необязательный вложенный объект без значения — пустой объект без заполнения полей (иначе обязательные поля внутри него не дали бы его опустить). `output_schema` необязательна; без неё `structured` любой формы. В MCP `outputSchema` объявляется только при `output_schema` коннектора и описывает весь ответ gate4ai (результат — `result`), потому что агенту нужны статус и `verified` рядом с результатом. - **Вебхук Telegram:** опция; по умолчанию long polling (README, «Approval Service»).
- **SQLite:** `modernc.org/sqlite` (чистый Go, без cgo) — проще кросс-сборка под три ОС.
- **Ошибка в условии CEL (fail-closed):** если `when` не вычислилось (нет аргумента, неверный тип), правило `deny`/`ask` считается сработавшим, `allow` — нет; ошибка видна в объяснении решения.
- **Переменные условий:** аргументы действия — на верхнем уровне (`to`, `path`, `amount`, как в README), плюс `provenance`, `counters`, `lists`, `now`, `hour`, `weekday`, `agent`, `action`, `args`. Имена проверяются по манифестам при сохранении политики; неизвестный список `lists.x` — ошибка.
- **Счётчики:** `counters.spent_today` — сумма денежных действий всех агентов за сутки; `actions_today` / `amount_today` — по агенту и действию. Лимиты профиля (`limits: per_day / amount_per_day`) — сахар, разворачиваемый в deny.
- **`domain_matches`:** `*.example.com` — только поддомены, сам `example.com` перечисляется отдельно; только http/https, URL с userinfo не совпадает. `glob` раскрывает `~` и схлопывает `..` до сравнения.
- **Обязательства решения:** объединение `obligations` правил, давших итоговый эффект.
- **Сроки хранения и цепочка:** по истечении срока квитанция не удаляется, а редактируется (тело стирается, хэш и `prev_hash` остаются) — цепочка и чекпоинты продолжают сходиться; доказательства удаляются файлом (crypto-shredding).
- **Шифрование журнала:** индекс (время, агент, действие, решение, хэши) — открыто; тело квитанции — XChaCha20-Poly1305 с ключом `audit.aead` из keychain, AD = id квитанции. Доказательства — age X25519, идентичность `audit.age` в keychain. Ключ устройства Ed25519 — `device.ed25519`.
- **Экспорт:** tar.gz с `receipts.jsonl`, `checkpoints.jsonl`, `evidence/<sha256>` (расшифрованными, чтобы проверка шла без ключей устройства), `public_key.txt`, подписанной описью `manifest.json`/`manifest.sig`; с паролем весь архив шифруется age (scrypt).
- **Краткий хэш:** `#` + первые 8 hex-символов; `show` ищет по хэшу квитанции, хэшу превью подтверждения или id.
- **Два сокета:** сокет владельца (`gate4ai.sock`, 0600, проверка собеседника по uid) и сокет агентов (`agent.sock`, нужен токен агента). Предъявленный токен всегда делает собеседника агентом — права владельца по токену не получить. В песочницу монтируется только агентский сокет.
- **Действия от владельца:** человек на хосте вызывает действия с `--as <агент>` — применяется профиль этого агента; политика и журнал те же.
- **Windows:** проверка собеседника на named pipe — security descriptor `D:P(A;;GA;;;<SID пользователя>)` + `FILE_FLAG_FIRST_PIPE_INSTANCE` (go-winio); отдельная проверка PID не делается. Кросс-сборка проверяется в CI, запуск на Windows не тестировался.
- **Метки происхождения (эвристика):** из результатов действий с `untrusted: true` извлекаются адреса, ссылки, реквизиты; значение в аргументе помечается `untrusted_content`, если встречалось в недоверенном контенте и не входит ни в один список `lists.*`.
- **Хранилище ключей:** системный keychain (go-keyring); если он недоступен (headless Linux без Secret Service) — файл `keys.json` 0600 с предупреждением (`--keystore`).
- **Коды выхода CLI:** 0 ok, 1 прочая ошибка, 2 `denied_by_policy` (и отказ/таймаут подтверждения), 3 `pending_approval`, 4 `verification_failed`, 5 неверные аргументы/неизвестное действие, 6 daemon недоступен («устройство офлайн»). Алиас `mail` → коннектор `email`.
- **Подключение remote MCP (OAuth 2.1):** согласие владельца — одноразовый код подключения (8 символов, 10 минут), который владелец получает локально (`gate4ai agents connect <агент>`, Web UI); код определяет агента и профиль. Публичные клиенты (PKCE S256 обязателен), динамическая регистрация, access 1 ч, refresh 30 дней с ротацией; `agents revoke` отзывает все токены агента.
- **Streamable HTTP:** ответы — `application/json` на каждый POST (без SSE-потоков: серверных уведомлений нет); `Mcp-Session-Id` выдаётся, но не обязателен. Имена инструментов: `email.send` → `email_send`, плюс `gate4ai_status`. Публичный обработчик (MCP + OAuth) не содержит API владельца.
- **Desktop-уведомления:** только сообщают (notify-send / osascript / PowerShell toast); решение — в трее, Web UI, CLI (`gate4ai approvals approve`) или Telegram. Отказы политикой тоже показываются уведомлением («user notified»).
- **Кнопки Telegram:** `callback_data` = действие + id запроса + первые 12 символов одноразового секрета запроса; бот принимает нажатия и команды только от `owner_id`. Токен бота — алиас в Vault, при смене конфигурации бот перезапускается.
- **Почта:** действия `list`, `read` (без пометки прочитанным), `draft`, `send`; входящие помечены `untrusted`. Проверка отправки — поиск по Message-ID в «Отправленных» (SPECIAL-USE `\Sent`, затем известные имена), с повторами. Если провайдер не кладёт письма в «Отправленные» сам — `sent_copy: client`, метод проверки честно называется `smtp_accepted+client_copy`. `tls: none` разрешён только для localhost.
- **Файлы:** `read`, `list`, `append` (только дописывает, создаёт файл в разрешённой папке), `write` (класс write → по умолчанию ask). Папки `roots` — это `capabilities.files` коннектора; проверяет их хост (функции `fs_*`) после раскрытия `~`, `..` и симлинков; бинарные файлы не читаются. Чтение файлов не помечается как недоверенное (свои заметки).
- **Браузер:** только чтение (`read`, `screenshot` элемента как доказательство, `extract` по инструкции с моделью пользователя). Список `allowed_domains` — это `capabilities.browser.domains` коннектора; хост проверяет его до и после редиректов — в дополнение к политике. Настройки движка (engine, model, model_key, chrome_path, profile_dir, cdp_url) — в разделе `browser:` конфигурации: браузерный воркер — служба хоста, коннектор — тонкий WASM-модуль. Движок по умолчанию — Stagehand Go SDK v4 (`ConnectLocalBrowser`, `SelfHeal` выключен, Act не используется); `engine: cdp` — прямой CDP без LLM. Chrome запускается с выделенным профилем, `--remote-debugging-port=0`, `--enable-unsafe-extension-debugging`, не headless.
- **Relay:** один порт 443: по SNI `relay.<домен>` relay терминирует свой TLS (туннель `/tunnel`, API регистрации, ACME TXT, свидетель), а `<device-id>.<домен>` — пробрасывает сырой TCP в yamux-поток устройства без расшифровки. Устройство — yamux-сервер, relay открывает потоки. Регистрация открытая (`POST /api/devices` → id + токен); токен устройства — в Vault (`@relay.token`). Офлайн-устройство: relay держит соединение до 30 с, затем сбрасывает. Неизвестные id сбрасываются сразу.
- **ACME DNS-01:** relay — авторитетный DNS своей зоны (A/AAAA на себя для всех устройств, TXT `_acme-challenge.<id>`); устройство ставит TXT только для своего имени через API relay (libdns-провайдер для certmagic). Для разработки — `relay.self_signed: true` и `relay.ca_file`.
- **Свидетель:** relay хранит (seq, head, ts, sig) чекпоинтов и отвергает уменьшение seq (признак переписывания журнала).
- **Публичный адрес и issuer OAuth** берутся из Host запроса (`https://<device-id>.<домен>`).
- **Web UI:** слушает только loopback (`--ui 127.0.0.1:7431`); вход — одноразовая ссылка (2 мин) от daemon по сокету владельца (`gate4ai ui`, трей), сессия 12 ч в HttpOnly SameSite=Strict cookie; защита: проверка Host (DNS rebinding), Origin и CSRF-токен на POST, CSP и запрет фреймов. Редактор политик — YAML с проверкой схемы (ошибки со строками), симулятор, версии и откат; конструктор условий из блоков — вне MVP.
- **Трей (решение человека, 2026-10-14):** Go вместо Tauri, в репозитории ядра, отдельным бинарником `gate4ai-tray` (`cmd/gate4ai-tray` — меню на fyne.io/systray; `internal/front/tray` — состояние, решения, вход в Web UI, уведомления: D-Bus на Linux, osascript на macOS, toast на Windows). Ходит в сокет владельца через тот же Go-клиент, что и CLI, поэтому команда `gate4ai tray-state` удалена; решения записываются с каналом `tray`. Отдельный бинарник, а не подкоманда: на macOS systray требует cgo (ядро остаётся `CGO_ENABLED=0` и кросс-собирается), на Windows трей собирается с `-H windowsgui` без окна консоли. Трей под macOS собирает задача `tray-darwin` в release.yml на macOS-раннере; без cgo под darwin собирается заглушка. Меню пересобирается, только когда меняется список запросов. README и gate4ai/CLAUDE.md обновлены по просьбе человека; репозиторий `gate4ai/tray` и каталог `tray/` удалены.
- **Egress Proxy:** HTTP(S)-прокси на loopback (и шлюзе docker0 для контейнеров) с учётными данными на каждый запуск (TCP без аутентификации не используется). `sandbox.allow_domains` профиля — сразу, `sandbox.ask_domains` — через pipeline как внутреннее действие `egress.connect` (политика, подтверждение, квитанция), остальное — deny. Подстановка секретов (`egress.secrets`: домен, заголовок, заглушка, алиас Vault): для этих доменов HTTPS расшифровывается локальным CA, выданным песочнице (`SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`, …); остальные домены — слепой туннель. Журнал соединений — `gate4ai egress`.
- **`egress` — внутренний коннектор:** доступен политике любого профиля, скрыт из каталогов, агент вызвать его не может (только daemon с флагом Internal).
- **`gate4ai run`:** запуск = агент из конфигурации (его профиль) + отдельный токен `run:<id>` и отдельный агентский сокет, отзываются по завершении. Шаблоны: claude-code, codex, openclaw, hermes, aider; иначе команда после `--`. В рабочую папку кладутся SKILL.md и (для Claude Code) `.mcp.json`. Окружение хоста передаётся без переменных, похожих на секреты. Флага `--profile` нет: профиль задаётся агентом в конфигурации.
- **Настройки sandbox-runtime** сгенерированы по известной схеме srt (`network.allowedDomains/allowUnixSockets/httpProxyPort`, `filesystem.denyRead/allowWrite`); с реальным srt не проверялись. Docker Sandboxes: `docker sandbox run --workspace … <agent>` — по документации, вживую не проверялось.
- **Секреты (этап 12):** решения человека от 2026-10-13 — в secret-architecture.md: три уровня (ядро без протоколов аутентификации, auth-модули WASM со значениями и выходом только к адресу привязки, коннекторы без значений); заголовок ставится целиком; формы заполняет ядро через CDP, вход атомарный; `account` и профиль Chrome на экземпляр браузера; значения — в `vault.age`. README и connector-architecture.md приведены к ней по просьбе человека (2026-10-13).

- **Зависимость ядра от relay — только в тестах и только через workspace:** `go.mod` ядра не содержит `require github.com/gate4ai/relay`, пока модуль не опубликован (`go mod tidy` без workspace его не найдёт); после публикации relay (этап 20, человек) добавить require с тегом. Протокол relay дублируется типами на стороне клиента (`witnessCheckpoint`), общего кода нет.
- **ABI v1 без Extism:** wazero напрямую и свой минимальный ABI (экспорты `gate4ai_alloc/manifest/execute/verify`, один импорт `host_call` + `host_result`, всё в JSON) — проще, без зависимости, одинаково для любого языка с WASI; Extism (connector-architecture.md) можно надстроить позже, если понадобятся его PDK для Rust/JS. Go-коннекторы — стандартный Go (`GOOS=wasip1`, `-buildmode=c-shared`, `//go:wasmexport`), проверено прототипом. Расхождение с connector-architecture.md.
- **Переход коннекторов на слоты — в рамках ABI v1, без v2:** новые функции хоста (`conn_open`, `conn_open_plain`, `conn_write_secret`, `secret_*`, `http_request` с `auth`/`capture`) добавляются, `mail` переводится на `conn_open`, затем `tls_dial` со схемами входа и плейсхолдеры `{{secret:@alias}}` удаляются. Сторонних коннекторов нет, ломать совместимость не для кого; `files` и `browser` не меняются. Решение человека от 2026-10-13.
- **Функции хоста и проверка возможностей — в sdk-go (Apache-2.0):** `hostfuncs` + `capability` + `netauth` используются и хостом, и тестовым хостом коннекторов (`hosttest`), поэтому тесты коннекторов идут через те же проверки, что и в продакшене. Службы хоста (Vault, браузерный воркер, KV) подключаются интерфейсами.
- **Соединения коннектора:** `tls_dial` открывает хост; для `imap` хост сам выполняет STARTTLS и LOGIN и отдаёт модулю синтетическое приветствие `* PREAUTH`, для `smtp` — EHLO/STARTTLS/AUTH PLAIN, модуль начинает с MAIL FROM. `conn_read` ждёт данных не дольше 200 мс, модуль опрашивает и уступает планировщику: в WASM один поток, и долгий блокирующий вызов хоста остановил бы читающую/пишущую горутины (go-imap). `tls: none` и `http` — только loopback.
- **`http_request`:** хост выполняет запрос сам по allowlist возможностей (не через Egress Proxy — та же проверка, без лишнего прокси), редиректы не выполняет (3xx уходит модулю, следующий запрос снова проверяется), секрет в URL запрещён, значения подставленных секретов вырезаются из ответа и логов.
- **money в манифесте:** действие класса money обязано указывать `verify` (метод проверки самого коннектора), иначе манифест не проходит проверку. Проверку действием другого коннектора человек отменил 2026-10-15.
- **Отложенная проверка пока не делается (решение человека 2026-10-15):** `verify_after` даёт статус `pending` и сообщение агенту «отправлено, не подтверждено»; вызов `verify` по расписанию, повторы и `limits.verify_deadline_s` — позже.
- **WASM-хост:** один wazero-runtime на коннектор (лимит памяти — свойство runtime), общий кэш компиляции на диске (`<home>/cache/wasm`: первая компиляция Go-модуля ~3 с, вызов ~25 мс), новый экземпляр модуля на каждый вызов (нет состояния между вызовами, сбой одного вызова не ломает следующий). Модуль может импортировать только `gate4ai` и WASI (без файлов, сети, окружения; время, сон и случайные числа — да). KV коннектора — JSON-файл `<home>/connectors/data/<имя>/kv.json` с квотой.

Пароль вместо алиаса в настройках коннектора отклоняется при вызове (`not a vault alias`).

- **Подписи магазина — Ed25519, а не Sigstore/cosign:** пакет `.g4c` (tar.gz: manifest.yaml, connector.wasm, package.json с дайджестом и подписью издателя), индекс registry подписан ключом registry (`index.json.sig`). С `--config` и на существующей установке ничего не ставится. Решение человека от 2026-10-17.
- **Коннектор при установке — в профиль `default` с `ask`:** после установки или обновления любого коннектора daemon добавляет его в профиль `default` (если профиль есть — владелец мог его убрать) и пишет правило `ask` (`<коннектор>-<действие>-ask`) на каждое действие без правила в этом профиле, в том числе класса `read`. Правила владельца не трогаются, умолчания классов в спецификации не меняются; ведущий комментарий политики при этой правке сохраняется. Решение человека от 2026-10-17.
- **Разделение:** `scripts/split.sh` — `git subtree split` для компонентов; ядро — копия истории через `git filter-branch` без выделенных каталогов и `go.work`, LICENSE во всех коммитах заменён на FSL (ранняя история под AGPL не публиковалась, правообладатель один). Организационный репозиторий `gate4ai/.github` лежит в `github-org/` (`.github/` занят CI ядра). Модули до публикации не содержат `require` друг на друга — проверка split собирает каждый репозиторий с временным `go.work` только из его зависимостей; так нашлись недостающие зависимости в `go.mod` sdk-go и gate4ai-mail. После разделения тесты ядра, собирающие коннекторы из исходников, пропускаются; сквозная проверка на настоящих коннекторах остаётся в монорепозитории.
- **Проверка секретов:** `scripts/secret-scan.sh` — шаблоны приватных ключей и токенов (AWS, GitHub, Slack, Google, OpenAI/Anthropic, Telegram) по всей истории; если установлен gitleaks, запускается и он. В этой среде gitleaks нет — прогнан только встроенный сканер (чисто).
- **ТБанк (этап 26), вход:** `browser_login` и слоты учёток ещё не сделаны (этап 12), поэтому в банк человек входит сам один раз в выделенном профиле Chrome gate4ai («запомнить устройство»); коннектор учёток не видит, при форме входа (`id.tbank.ru`) возвращает `auth_failed` с подсказкой. Код из SMS / push при подтверждении операции коннектор не вводит: операция не подтверждается, ошибка `auth_failed` (источник «человек» из secret-architecture.md — вместе с этапом 12).
- **ТБанк, сценарии:** API для физлиц у банка нет, песочницы для личного кабинета тоже — работаем через страницу кабинета. Тексты элементов в `connectors/tbank/scenario.go` взяты по публичному интерфейсу и на живом кабинете не сверены (агенту доступ к сайту банка закрыт); элементы ищутся по подписи, а не по классам сборки. Расхождение даёт ошибку «T-Bank page changed … nothing was sent» до кнопки подтверждения.
- **ТБанк, комиссия:** любая ненулевая комиссия на экране подтверждения — отказ без отправки: человек подтверждал сумму без комиссии. Разрешить комиссию — отдельный аргумент, когда понадобится.
- **ТБанк, «СБП по номеру карты»:** в кабинете это перевод по номеру карты (`card_transfer`), СБП работает по телефону; действие названо по сути.
- **`browser_act` и «наблюдённое действие»:** действие принимается по CSS-селектору и тексту элемента (без естественного языка); проверка, что селектор взят из `observe`, и режим «секрет на странице» — вместе с `browser_fill_secret` (этап 12).

- **Коннектор из папки (этап 27):** собирает CLI, а не daemon: у daemon своё окружение (запущен службой, без `go.work` и `GOFLAGS` разработчика), а сборка коннектора часто зависит от локального workspace (например, коннектор на невыпущенной версии sdk-go). Сборка в daemon из `dir:` — только запасной путь для обновления без CLI. Установка из папки всегда «своя сборка» (как `--dev`): пакет без подписи, предупреждение и согласие на возможности — как у `.g4c --dev`.

- **Этап 28 (2026-10-17):** (1) страница браузера для `service_call` — одна на корневой вызов и освобождается по `end_call`, без явного `session_id`: потребителю не нужно управлять сессией, утечек нет; (2) внешней проверки итогового адреса в daemon нет — смысл `params` знает только поставщик, а нативный пакет и так доверенный; (3) Go-клиент поставщика генерирует потребитель из копии манифеста поставщика (`contracts/<имя>.yaml`): теги коннекторов (`v4`) — не semver, отдельный Go-модуль клиента пришлось бы версионировать отдельно; (4) настройки браузерной службы переезжают из раздела `browser` в `connectors.browser`, ключ модели — через `reveal`; daemon один раз переносит старый раздел новой версией конфигурации.
