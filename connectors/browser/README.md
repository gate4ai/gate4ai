# Коннектор «Браузер» для gate4.ai

Браузерный воркер в выделенном профиле настоящего Chrome (CDP, Stagehand) — нативный пакет (`runtime: native`): отдельный процесс под надзором хоста [gate4ai](https://github.com/gate4ai/gate4ai). Работает без песочницы, с правами пользователя, поэтому магазин принимает нативные пакеты только от gate4.ai.

- **Агенту без сеанса:** `read` (текст страницы), `screenshot` (снимок элемента — доказательство), `extract` (данные по инструкции, модель задаёт владелец) на сайтах из настроек: `allowed_domains` или режим `blocklist` с `blocked` (адреса этого компьютера и локальной сети закрыты всегда). Итоговый адрес проверяется и после редиректов. Каждый такой вызов открывает временную вкладку того же профиля Chrome (те же cookies) и закрывает её после действия: открытый сеанс агента (страница, адрес, состояние) не меняется, поэтому `read` работает и при открытом сеансе. Одновременно — не больше 4 временных вкладок; сверх этого вызов ждёт до 5 с и получает `limit_exceeded` с альтернативой (`get --session <id> --url …` или `open --session <id> --url …` в своём сеансе).
- **Агенту в сеансе** (исследовать сайт, писать по нему коннектор): `open` без `session` начинает сеанс и возвращает его id (переход ждёт до 5 с, пока сеть успокоится, иначе `still_loading: true`; `wait_for_selector` / `wait_for_text` / `wait_for_url` у `open`, `observe` и `reload` — дождаться нужного блока или адреса до `timeout_ms` (по умолчанию 10 с, до 60 с): не дождались — `not_found` с состоянием страницы (`url`, `title`, `ready_state`, `pending_requests`, начало текста), страница ушла на страницу или сайт входа — сразу `redirected`), дальше на той же странице — `observe` (текст; `selector` — только внутри элемента, `elements: true` — видимые поля, кнопки и ссылки (`kind`) с однозначным CSS-селектором — по `data-testid`, `name`, `placeholder`, `aria-label`, несгенерированному `id`, иначе короткий путь от ближайшего такого предка; у полей — начало значения (200 символов), `value_length` и `checked`, у пароля значения нет; ссылки рекламных и трекинговых сетей (adfox, doubleclick, yclid…) и кнопки в рекламных блоках не показываются; самописные виджеты — элементы с обработчиком click / mousedown, `cursor: pointer`, ролями `option` / `listbox` / `combobox`, `[tabindex]` — тоже, а иконки без текста внутри них (крестик выбранного значения) — с `icon: true` и именем из aria-label, title или текста рядом; `kinds: [fields, buttons, links]` — только эти виды; `outline: true` — структура контейнеров), `act` (класс `write`, по селектору и видимому тексту — самый внутренний видимый элемент с этим текстом среди элементов по селектору и вложенных в них; не найден — ответ называет видимые элементы с этим текстом и их селекторы: `click` — как мышью: pointerdown, mousedown, pointerup, mouseup, click; `fill` — заменить значение поля, `append` — дописать в конец, `paste` — заменить вставкой как из буфера обмена: событие `paste` с `text/plain`, редакторы сами разбирают Markdown; `value` — до 262144 символов (256 КБ), из CLI длинный текст — `--value_file`; ответ — `value` с длиной, началом (1000 символов) и концом (200) итогового значения; `press` — клавиша или сочетание: Enter, Tab, Escape, Backspace, Delete, Space, Home, End, PageUp, PageDown, стрелки, a–z, 0–9 с модификаторами Ctrl, Shift, Alt, Meta (`Ctrl+A` — выделить всё, `Ctrl+Z` / `Ctrl+Y` — отмена и повтор, `Ctrl+Enter`, `Shift+Tab`); системный буфер обмена не используется — он общий с человеком, `Ctrl+C` / `Ctrl+X` / `Ctrl+V` отклоняются; `wait`; `expect_selector` / `expect_text` / `expect_url_change` — без ожидаемого результата ответ `not_found`, а не ok), `reload` — перезагрузить страницу (адрес проверяется снова), `handoff {session, message, until_url_change | until_selector, timeout_ms}` — передать страницу человеку: хост уведомляет его (Web UI → Подтверждения, рабочий стол, Telegram, push) словами агента и ждёт, пока он сам сделает шаг в окне Chrome (вход без учётки, капча, SMS) — до смены адреса (по умолчанию) или появления элемента, не дольше 9 минут; ответ — `done` или `timeout`, уведомление уходит только после проверки сеанса, `network` (fetch / XHR страницы к разрешённым сайтам по CDP Network — метод, адрес, статус, начало ответа JSON; `all_sites` — и к чужим; токены, пароли, ответы входа и `redact_params` скрыты, тела запросов не пишутся, странице ничего не подменяется), `get` / `head` (класс `read`) и `post` / `put` / `patch` / `delete` (класс `write`) — запрос к API сайта изнутри страницы сеанса (cookies и origin пользователя; `url` — по списку сайтов до и после редиректов, запрос с эффектом редиректу не следует; `headers` — JSON-объект, `body` — до 262144 символов; ответ — `status`, `url`, `headers` без cookies и авторизации, `json` или `body` с `content_type`, `size`, `truncated`; токены и `redact_params` скрыты, как в `network`; квитанция — метод, адрес, статус, размер), `page_extract`, `page_screenshot` (PNG в `content` и доказательства; ответ — `url`, `selector`, `size`; CLI пишет PNG в файл `--out`, путь — `result.file`); страница не HTML (JSON, текст) в `read` и `observe` — тело как прислал сервер (`body`, `content_type`, без просмотрщика Chrome); `close` освобождает страницу и коротко отвечает `{session, closed: true, steps: N}`: `steps: true` — список шагов (действие, аргументы без пустых, статус), `save_steps: true` — полная запись в файл `browser-steps/<сеанс>.json` каталога данных gate4ai (`steps_file`) — фикстура для `hosttest.Replay` (`close --all` — все сеансы этого агента в этом клиенте (сессия Claude Code, процесс агента — `ExecRequest.Client`), если id потерян; сеансы других агентов и других клиентов того же агента он не трогает; идущее действие отменяется). Сеанс привязан к агенту, который его открыл: другой агент с тем же id получает «сеанс закрыт или неизвестен»; свой закрытый сеанс отвечает, кто, когда и почему его закрыл (`browser.close`, `close --all`, простой, Chrome закрыт или упал). У каждого сеанса и каждой страницы коннектора — своя вкладка (первая — стартовая вкладка Chrome), не больше 4 одновременно; сверх этого `open` ждёт 5 с (`wait_for_browser: 10m` — до 9 минут в очереди) и получает `busy` — чьи сеансы, с какого времени, когда закроются по простою; `read` / `screenshot` / `extract` без `session` работают во временной вкладке. Сеанс без действий закрывается через 10 минут; прерванный вызов прерывается и в пакете.

  У каждого действия сеанса — срок целиком, включая переход: `timeout_ms` (у `act` — плюс `expect_timeout_ms`), иначе 45 с (`handoff` — свой срок, `page_extract` — 3 минуты); по истечении — `timeout` с состоянием страницы. Пока действие идёт, другой вызов того же сеанса через 5 с получает `session_blocked` (какое действие и с какого времени), а не висит. JS-диалоги (`Page.javascriptDialogOpening`, при движке Stagehand — через отдельное подключение CDP к вкладке): `beforeunload` при `open` / `reload` принимается — переход попросил вызывающий; alert / confirm / prompt (и `beforeunload` от клика) прерывают действие ответом `dialog_open {type, message}`, и до ответа все действия отвечают им сразу; ответ — `dialog {session, accept | dismiss, text}`. Во временных вкладках диалоги закрываются сами. Адрес проверяется после стабилизации: тихий вход через SSO не обрывает страницу. Одноразовые коды и токены в адресах (`?code=…`, `#access_token=…`, в том числе после `login` / `fill_secret`) в ответах и шагах скрыты.
- **Политика:** шаблон правила `browser.*` (и `*`) не покрывает `post` / `put` / `patch` / `delete`, `login` и `fill_secret` — их разрешает только правило, которое называет действие; без него они спрашивают владельца.
- **Вход по учётке** (`credentials` в конфигурации gate4ai): `login {session, account}` вводит поля учётки (константы и секреты Vault) на открытой странице входа и отправляет форму — `logged_in`, `submitted` или `still_on_login`; `fill_secret {account, field, selector}` — одно поле без отправки (для коннекторов входа), `source: human` — код, который ввёл человек. Поле задаёт владелец: `selector` вызывающего заменяет селектор поля учётки только у коннектора входа этой учётки (`via`); если владелец селектор не задал — вызывающий выбирает поле, но только `input[type=password]`; иначе `bad_request`. Значения хост передаёт пакету только в этих действиях; они не попадают в ответ, шаги сеанса, ошибки и лог. Проверки до ввода: origin страницы — из `bind` учётки (`wrong_origin`), поля найдены, видимы и нужного типа — секрет только в `input[type=password]`, если у поля нет `type: text` (`form_mismatch`). После ввода секрета страницу нельзя читать (`observe`, `network`, `page_extract`, `page_screenshot`, `fill` — `secret_on_page`) до перехода верхнего документа; `click`, `press`, `wait` и `fill_secret` работают, но `text` в ответе `act` пустой, а `text` / `expect_text` / `wait_for_text` не сопоставляются со значениями полей и текстом редактируемых элементов. Значение поля пароля не отдаётся и не сопоставляется никогда. Страница может быть на сайте входа доступной учётки вне списка сайтов (редирект на вход её не закрывает), а ответы `open` / `observe` / `network` там подсказывают `login_required`. Учётку со сложным входом (`via`) ведёт коннектор входа — его вызывает хост.
- **Другим коннекторам** (`service_call`, контракт 1): `open`, `observe`, `act`, `dialog`, `page_extract`, `page_screenshot`, `login`, `fill_secret` (учётка — алиас или слот коннектора). Страница — одна на корневое действие агента (своя вкладка), сайты — `params` вызывающего (`{mode, domains, blocked}`), после каждого действия адрес проверяется снова. Клиент — `gate4ai contract gen manifest.yaml`.

Сеанс записывает шаги `reload` и `handoff` так же, как остальные; проверка хоста перед уведомлением (`precheck`) шагом не считается. Лимит вызова пакета — 600 с (`limits.timeout_s`): дольше всех ждёт `handoff`.

## Установка

```sh
gate4ai connectors install browser                 # из магазина gate4.ai (ставится и сам при первом запуске)
# или своя сборка под этот компьютер:
gate4ai connectors install . --dev
```

Настройки — `connectors.browser` в конфигурации gate4ai: `allowed_domains`, `mode`, `blocked`, `engine` (stagehand | cdp), `cdp_url`, `chrome_path`, `profile_dir`, `model`, `model_key` (алиас Vault: значение хост передаёт пакету по `capabilities.reveal`), `max_text_chars`, `redact_params` (параметры адресов и поля JSON с личными идентификаторами сайта — `network` их скрывает).

Chrome запускается с `--disable-blink-features=AutomationControlled` (иначе с портом отладки `navigator.webdriver = true`, и антифрод сайтов видит автоматизацию), одной вкладкой (вкладки сеансов открываются от неё); для `engine: stagehand` — ещё с `--remote-allow-origins=*` (расширению Stagehand нужно подключиться к DevTools; порт слушает только 127.0.0.1). Если окно Chrome закрыли, следующий вызов подключается заново или запускает Chrome; при остановке пакета запущенный им Chrome закрывается.

## Разработка

```sh
go test ./...                                     # коннектор — на sdk-go/hosttest, воркер — на фейковом CDP
gate4ai connectors pack .                         # пакет под каждую платформу из manifest.platforms + browser-<версия>.platforms.json
gate4ai connectors install . --watch              # поставить в свой daemon из исходников и пересобирать на каждое сохранение
```

Несовместимое изменение действий из `services` — только с повышением `contract` в манифесте (CI проверяет `gate4ai contract diff` с прошлым тегом).
