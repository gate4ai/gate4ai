# Встроенный компонент «Браузер» gate4.ai

Браузерный воркер в выделенном профиле настоящего Chrome (CDP, Stagehand) — часть ядра [gate4ai](https://github.com/gate4ai/gate4ai) (`runtime: builtin`): Go-код daemon на PDK коннекторов (`sdk-go/connector`), с теми же функциями хоста и проверкой манифеста, что у WASM (адаптер `internal/connectors/wasm/builtin.go`). Работает с правами пользователя; в магазине его нет, daemon регистрирует его при старте рядом с Файлами. Сайты и режим доступа задаёт список доступа Браузера (`access.sites` конфигурации; Web UI → Доступ → Браузер; `gate4ai access sites set <сайт> <режим>`): `allowed_domains` / `blocked` / `mode` компонент получает от pipeline производными от списка (всё, кроме `deny`; строка `*` — режим `blocklist`), а решение allow / ask / deny по строке pipeline принимает до вызова.

- **Агенту без сеанса:** `read` (текст страницы), `screenshot` (снимок элемента — доказательство), `extract` (данные по инструкции, модель задаёт владелец) на открытых сайтах списка доступа (адреса этого компьютера и локальной сети закрыты всегда). Итоговый адрес проверяется и после редиректов. Каждый такой вызов открывает временную вкладку того же профиля Chrome (те же cookies) и закрывает её после действия: открытый сеанс агента (страница, адрес, состояние) не меняется, поэтому `read` работает и при открытом сеансе. Одновременно — не больше 4 временных вкладок; сверх этого вызов ждёт до 5 с и получает `limit_exceeded` с альтернативой (`get --session <id> --url …` или `open --session <id> --url …` в своём сеансе).
- **Агенту в сеансе** (исследовать сайт, писать по нему коннектор): `open` без `session` начинает сеанс и возвращает его id (переход ждёт до 5 с, пока сеть успокоится, иначе `still_loading: true`; `wait_for_selector` / `wait_for_text` / `wait_for_url` у `open`, `observe` и `reload` — дождаться нужного блока или адреса до `timeout_ms` (по умолчанию 10 с, до 60 с): не дождались — `not_found` с состоянием страницы (`url`, `title`, `ready_state`, `pending_requests`, начало текста), страница ушла на страницу или сайт входа — сразу `redirected`), дальше на той же странице — `observe` (текст; `selector` — только внутри элемента, `elements: true` — видимые поля, кнопки и ссылки (`kind`) с однозначным CSS-селектором — по `data-testid`, `name`, `placeholder`, `aria-label`, несгенерированному `id`, иначе короткий путь от ближайшего такого предка; у полей — начало значения (200 символов), `value_length` и `checked`, у пароля значения нет; ссылки рекламных и трекинговых сетей (adfox, doubleclick, yclid…) и кнопки в рекламных блоках не показываются; самописные виджеты — элементы с обработчиком click / mousedown, `cursor: pointer`, ролями `option` / `listbox` / `combobox`, `[tabindex]` — тоже, а иконки без текста внутри них (крестик выбранного значения) — с `icon: true` и именем из aria-label, title или текста рядом; `kinds: [fields, buttons, links]` — только эти виды; `outline: true` — структура контейнеров), `act` (класс `write`, по селектору и видимому тексту — самый внутренний видимый элемент с этим текстом среди элементов по селектору и вложенных в них; не найден — ответ называет видимые элементы с этим текстом и их селекторы: `click` — как мышью: pointerdown, mousedown, pointerup, mouseup, click; `fill` — заменить значение поля, `append` — дописать в конец, `paste` — заменить вставкой как из буфера обмена: событие `paste` с `text/plain`, редакторы сами разбирают Markdown; `value` — до 262144 символов (256 КБ), из CLI длинный текст — `--value_file`; ответ — `value` с длиной, началом (1000 символов) и концом (200) итогового значения; `type` — ввести текст посимвольно настоящими нажатиями (на каждый символ keydown / keypress / input / keyup, по CDP `Input.dispatchKeyEvent`; запятые и пробелы — тоже клавиши, текст не разбирается), до 4096 символов, `delay_ms` — пауза между символами (до 1000), `submit` — клавиша в конце (`Enter`): поле тегов, создающее тег по запятой или Enter, заполняется одним вызовом; `press` — клавиша, любой одиночный символ (`,`, `;`, буква, цифра) или сочетание: Enter, Tab, Escape, Backspace, Delete, Space, Home, End, PageUp, PageDown, стрелки с модификаторами Ctrl, Shift, Alt, Meta (`Ctrl+A` — выделить всё, `Ctrl+Z` / `Ctrl+Y` — отмена и повтор, `Ctrl+Enter`, `Shift+Tab`); ответ `type` и `press` — `value` поля в фокусе и `changes`: какие элементы рядом с полем появились и пропали (`added` / `removed`: тег, роль, видимый текст — до 10 в списке), какие списки, меню и диалоги открылись и закрылись (`opened` / `closed`), у каких элементов сменился `aria-expanded` (`expanded` / `collapsed`); текст пропавших — только из снимка видимого текста до действия; на странице с введённым секретом `type`, как `fill`, — `secret_on_page`; системный буфер обмена не используется — он общий с человеком, `Ctrl+C` / `Ctrl+X` / `Ctrl+V` отклоняются; `wait`; `expect_selector` / `expect_text` / `expect_url_change` — без ожидаемого результата ответ `not_found`, а не ok, и в сообщении — путь к снимку окна; `screenshot: true` — снимок окна после действия в ответе (`screenshot.file`) и в доказательствах), `reload` — перезагрузить страницу (адрес проверяется снова), `handoff {session, message, until_url_change | until_selector, timeout_ms}` — передать страницу человеку: хост уведомляет его (Web UI → Подтверждения, рабочий стол, Telegram, push) словами агента и ждёт, пока он сам сделает шаг в окне Chrome (вход без учётки, капча, SMS) — до смены адреса (по умолчанию) или появления элемента, не дольше 9 минут; ответ — `done` или `timeout`, уведомление уходит только после проверки сеанса, `network` (fetch / XHR страницы к разрешённым сайтам по CDP Network — метод, адрес, статус, начало ответа JSON; `all_sites` — и к чужим; токены, пароли, ответы входа и `redact_params` скрыты, тела запросов не пишутся, странице ничего не подменяется), `get` / `head` (класс `read`) и `post` / `put` / `patch` / `delete` (класс `write`) — запрос к API сайта изнутри страницы сеанса (cookies и origin пользователя; `url` — по списку сайтов до и после редиректов, запрос с эффектом редиректу не следует; `headers` — JSON-объект, `body` — до 262144 символов; ответ — `status`, `url`, `headers` без cookies и авторизации, `json` или `body` с `content_type`, `size`, `truncated`; `max_chars` — до 1000000 символов, по умолчанию 200000 у JSON и `max_text_chars` (30000) у прочего текста; обрезанное тело — с `hint`: сколько в нём символов и какой `max_chars` вернёт его целиком, обрезанный JSON не разбирается; токены и `redact_params` скрыты, как в `network`; квитанция — метод, адрес, статус, размер), `download` — скачать файл (см. ниже), `page_extract`, `page_screenshot` (элемент — первый видимый по `selector`, видимое окно — `viewport`, по умолчанию, вся страница — `full_page`; PNG пишется в `browser-shots/<сеанс>-<n>.png` каталога данных gate4ai, рядом с `browser-steps` (`steps_file`), путь — в `file`, размер — `width`, `height`, `bytes`; снимки старше суток удаляются; из CLI `--out <путь>` сохраняет картинку из ответа на стороне агента — daemon сам по путям агента не пишет; изображение — и в `content`, и в доказательствах журнала; поля пароля и поля с введённым секретом на снимках закрашены всегда; элемент не найден — сказано, совпал ли селектор с чем-нибудь и почему совпавшие скрыты: `display:none`, `visibility:hidden`, нулевой размер, вне страницы); страница не HTML (JSON, текст) в `read` и `observe` — тело как прислал сервер (`body`, `content_type`, без просмотрщика Chrome; `max_chars` и `hint` — как у `get`); `close` освобождает страницу и коротко отвечает `{session, closed: true, steps: N}`: `steps: true` — список шагов (действие, аргументы без пустых, статус), `save_steps: true` — полная запись в файл `browser-steps/<сеанс>.json` каталога данных gate4ai (`steps_file`) — фикстура для `hosttest.Replay` (`close --all` — все свои сеансы, если id потерян; идущее действие отменяется, страница освобождается после него). Сеанс привязан к агенту, который его открыл, и к его экземпляру — сессии Claude Code или процессу агента (`agent_instance` от хоста; у всех сессий Claude Code имя агента одно — `claude-code`): другой агент или другая сессия того же агента с тем же id получает «сеанс закрыт или неизвестен», а её `close --all` чужой сеанс не закрывает. Экземпляр неизвестен (удалённый CLI, скрипт с токеном, владелец `--as`) — видны сеансы всех экземпляров агента. У каждого сеанса и каждой страницы коннектора — своя вкладка (первая — стартовая вкладка Chrome), не больше 4 одновременно; сверх этого `open` ждёт 5 с (`wait_for_browser: 10m` — до 9 минут в очереди) и получает `busy` — чьи сеансы, с какого времени, когда закроются по простою; `read` / `screenshot` / `extract` без `session` работают во временной вкладке. Свой закрытый сеанс отвечает, кто, когда и почему его закрыл (`browser.close`, `close --all`, простой, Chrome закрыт или упал). Сеанс без действий закрывается через 10 минут; прерванный вызов прерывается и в пакете.

  У каждого действия сеанса — срок целиком, включая переход: `timeout_ms` (у `act` — плюс `expect_timeout_ms`), иначе 45 с (`handoff` — свой срок, `page_extract` — 3 минуты); по истечении — `timeout` с состоянием страницы. Пока действие идёт, другой вызов того же сеанса через 5 с получает `session_blocked` (какое действие и с какого времени), а не висит. JS-диалоги (`Page.javascriptDialogOpening`, при движке Stagehand — через отдельное подключение CDP к вкладке): `beforeunload` при `open` / `reload` принимается — переход попросил вызывающий; alert / confirm / prompt (и `beforeunload` от клика) прерывают действие ответом `dialog_open {type, message}`, и до ответа все действия отвечают им сразу; ответ — `dialog {session, accept | dismiss, text}`. Во временных вкладках диалоги закрываются сами. Адрес проверяется после стабилизации: тихий вход через SSO не обрывает страницу. Одноразовые коды и токены в адресах (`?code=…`, `#access_token=…`, в том числе после `login` / `fill_secret`) в ответах и шагах скрыты.
- **Политика:** первый уровень — строка сайта в списке доступа (`allow` — всё без вопроса, `read` — действия класса `read` без вопроса, остальные с подтверждением, `connector` — только коннекторам магазина, `ask`, `deny`); для действий сеанса без `url` pipeline спрашивает у компонента адрес открытой страницы (`PageURL`). Сайт вне списка — `capability_denied` с подсказкой владельцу (`gate4ai access sites set <сайт> read`, Web UI → Браузер) и агенту (`change_policy` с `set_site_access`). Шаблон правила `browser.*` (и `*`) не покрывает `post` / `put` / `patch` / `delete`, `login` и `fill_secret` — их разрешает только правило, которое называет действие; без него они спрашивают владельца.
- **Вход по учётке** (`credentials` в конфигурации gate4ai): `login {session, account}` вводит поля учётки (константы и секреты Vault) на открытой странице входа и отправляет форму — `logged_in`, `submitted` или `still_on_login`; `fill_secret {account, field, selector}` — одно поле без отправки (для коннекторов входа), `source: human` — код, который ввёл человек. Поле задаёт владелец: `selector` вызывающего заменяет селектор поля учётки только у коннектора входа этой учётки (`via`); если владелец селектор не задал — вызывающий выбирает поле, но только `input[type=password]`; иначе `bad_request`. Значения хост передаёт пакету только в этих действиях; они не попадают в ответ, шаги сеанса, ошибки и лог. Проверки до ввода: origin страницы — из `bind` учётки (`wrong_origin`), поля найдены, видимы и нужного типа — секрет только в `input[type=password]`, если у поля нет `type: text` (`form_mismatch`). После ввода секрета страницу нельзя читать (`observe`, `network`, `page_extract`, `fill`, `type` — `secret_on_page`) до перехода верхнего документа; `click`, `press`, `wait`, `fill_secret` и `page_screenshot` (поля секрета и пароля закрашены) работают, но `text` в ответе `act` пустой, а `text` / `expect_text` / `wait_for_text` не сопоставляются со значениями полей и текстом редактируемых элементов. Значение поля пароля не отдаётся и не сопоставляется никогда. Страница может быть на сайте входа доступной учётки вне списка сайтов (редирект на вход её не закрывает), а ответы `open` / `observe` / `network` там подсказывают `login_required`. Учётку со сложным входом (`via`) ведёт коннектор входа — его вызывает хост.
- **Загрузки файлов.** Воркер держит своё подключение DevTools к браузеру (`Browser.setDownloadBehavior`), поэтому системный диалог «Сохранить как» в окне Chrome gate4ai не появляется никогда и сеанс из-за него не зависает: файл, скачанный кликом `act` или человеком в окне, молча ложится в папку загрузок пользователя (`XDG_DOWNLOAD_DIR` / `~/Downloads`, настройка `download_dir`). Чтобы файл получил агент — `download {session, selector [, text] [, response_url_contains] | url, timeout_ms}` (класс `write`: это клик по странице, как `act`; `untrusted`): на время действия загрузки идут во временную папку под guid загрузки (`allowAndName`), элемент для клика ждётся до 10 с (нет его — сразу `not_found` с похожими элементами), затем воркер ждёт `Browser.downloadWillBegin` / `downloadProgress: completed` (`timeout_ms`: по умолчанию 30 с, до 120 с), читает файл и удаляет его. Поведение загрузок у Chrome одно на весь браузер, поэтому файл сессии — загрузка, начатая в кадре её вкладки (`frameId` события — верхний кадр или iframe вкладки, `Page.getFrameTree`); загрузки других сессий за это время не перехватываются: закончившись, они переносятся из временной папки в папку пользователя под своим именем (занято — «имя (1)»), как без `download` (у движка `stagehand` кадров нет — своя первая начавшаяся). Ответ — `name` (имя от сайта; без расширения — с расширением по типу), `mime_type` (заголовок, расширение или содержимое), `size`, `sha256`, `url` (адрес файла; `blob:` и `data:` не показываются), `via` и сам файл двоичным `resource` (как `files.read`; CLI `--out <файл>` пишет его на диск агента, права 0600); копия файла — доказательство (evidence) в журнале, квитанция — имя, размер и sha256. Сайт, который не скачивает файл, а показывает его (fetch → blob во вкладке): `response_url_contains` — файл берётся из ответа страницы на её собственный запрос (CDP Fetch, стадия Response: страница получает ответ как обычно, её заголовки и токены вроде `X-Access-JWT` агенту не видны; адрес запроса — из `network`); нужен движок `cdp`. `url` — GET изнутри страницы сеанса с её cookies (без её заголовков; адрес — по списку сайтов до и после редиректов). Пределы: файл до 20 МБ (`max_download_bytes` владельца — меньше), типы — `download_types` владельца (`application/pdf`, `image/*`, `.csv`; пусто — любые): больше — `limit_exceeded`, другой тип — `capability_denied`. Клик без загрузки — `not_found` с подсказкой про `response_url_contains`. Двоичное содержимое не маскируется (как у `files.read`).
- **Другим коннекторам** (`service_call`, контракт 1): `open`, `observe`, `act`, `dialog`, `download`, `page_extract`, `page_screenshot`, `login`, `fill_secret` (учётка — алиас или слот коннектора). Страница — одна на корневое действие агента; сайты — строки `sites` коннектора (`connectors.<имя>.sites`, из его манифеста) в пределах списка Браузера: pipeline передаёт их в `Caller.Params` (`{mode, domains, blocked}`), после каждого действия адрес проверяется снова. Клиент — `gate4ai contract gen internal/connectors/builtin/browser/manifest.yaml`.

Сеанс записывает шаги `reload` и `handoff` так же, как остальные; проверка хоста перед уведомлением (`precheck`) шагом не считается. Лимит вызова пакета — 600 с (`limits.timeout_s`): дольше всех ждёт `handoff`.

## Настройки

Устанавливать нечего: компонент встроен в `gate4ai`. Прежний пакет `browser` из магазина daemon удаляет при старте, а его `allowed_domains` / `blocked` / `mode` переносит в список доступа (`internal/daemon/migrate.go`).

Настройки — `connectors.browser` в конфигурации gate4ai: `engine` (stagehand | cdp), `cdp_url`, `chrome_path`, `profile_dir`, `model`, `model_key` (алиас Vault: значение хост передаёт компоненту по `capabilities.reveal`), `max_text_chars`, `redact_params` (параметры адресов и поля JSON с личными идентификаторами сайта — `network` их скрывает), `download_dir`, `download_types`, `max_download_bytes`. Сайты — не настройка, а список доступа (`access.sites`).

Chrome запускается с `--disable-blink-features=AutomationControlled` (иначе с портом отладки `navigator.webdriver = true`, и антифрод сайтов видит автоматизацию), одной вкладкой (вкладки сеансов открываются от неё); для `engine: stagehand` — ещё с `--remote-allow-origins=*` (расширению Stagehand нужно подключиться к DevTools; порт слушает только 127.0.0.1). Если окно Chrome закрыли, следующий вызов подключается заново или запускает Chrome; при остановке пакета запущенный им Chrome закрывается.

## Разработка

```sh
go test ./...                                     # компонент — на sdk-go/hosttest, воркер — на фейковом CDP
go build ./cmd/gate4ai                            # компонент собирается вместе с daemon; пакета .g4c у него нет
```

Несовместимое изменение действий из `services` — только с повышением `contract` в манифесте (CI проверяет `gate4ai contract diff` с прошлым тегом по `internal/connectors/builtin/*/manifest.yaml`).
