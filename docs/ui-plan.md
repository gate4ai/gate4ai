# Web UI: пользовательские пути и план доработки

Исследование от 2026-10-15. Разобран Web UI на `http://127.0.0.1:7431/` (свежий daemon `gate4ai 0.3.0`, конфигурация версии 1) и его код: `internal/front/webui/webui.go`, `internal/front/webui/templates/*.html`, API владельца `internal/daemon/api.go`, `internal/daemon/connectors.go`, `internal/approval/*`, `internal/relayclient/attach.go`, `internal/state/*`, `internal/connectors/store/*`. Сверено со [specification.md](specification.md), [architecture.md](architecture.md), [connector-architecture.md](connector-architecture.md), [secret-architecture.md](secret-architecture.md), [cli-ux.md](cli-ux.md).

Разделы 1–3 описывают состояние до доработки, раздел 4 — план, раздел 5 — противоречия с документацией, раздел 6 — что сделано и как проверено.

## 1. Что есть сейчас

Шесть страниц, все отрисовываются на сервере шаблонами Go, без JavaScript. CSP: `default-src 'self'`.

| Страница | Маршрут | Что умеет |
|---|---|---|
| Подтверждения | `/` | очередь `pending` с кнопками «Разрешить / Отклонить», таблица «Недавние» |
| Агенты | `/agents` | список агентов из `agents:` конфигурации; «Выдать токен», «Подключить (remote MCP)» (код подключения), «Отозвать все токены»; таблица токенов |
| Журнал | `/journal`, `/journal/{hash}` | фильтр по агенту, действию, решению; квитанция — сырой JSON |
| Политики | `/policy` | textarea с YAML всей конфигурации; симулятор (агент, действие, аргументы JSON); версии и откат |
| Секреты | `/vault` | список алиасов с местами использования (Telegram-бот подтверждений, relay, Egress Proxy, коннектор X — по разобранной конфигурации и возможностям манифестов) или «не используется»; форма «алиас + значение» |
| Вход | `/login` | «выполните `gate4ai ui`» |

На свежей установке все страницы пустые, а политика содержит только комментарий `# gate4ai: no agents yet. Install connectors (gate4ai connectors install files), then write your policy… gate4ai policy set config.yaml`.

Чего в Web UI нет совсем, хотя бэкенд или спецификация это предусматривают:

- **коннекторов**: ни каталога магазина, ни установленных, ни их настроек (API `GET/POST /v1/connectors/*` есть, но только для CLI);
- **добавления агента**: «Новый агент добавляется в разделе „Политики“ (agents:)» — через YAML;
- **каналов подтверждений**: включаются только в YAML (`approvals.channels`, `approvals.telegram`), статуса нет нигде;
- **relay**: регистрация только `gate4ai relay register`, адрес по умолчанию зашит в CLI (`https://relay.gate4.ai`), в UI адреса устройства нет; код подключения говорит «добавьте адрес устройства `…/mcp`», но какой это адрес — не сказано;
- **настроек**: автозапуск, relay, таймаут подтверждений, магазин — только в CLI и YAML;
- **следов работы агента**: когда агент последний раз обращался, через какой канал — нигде не хранится;
- **шаблонов правил, конструктора условий** — спецификация («Как редактируются») обещает блоки и шаблоны, есть только YAML.

## 2. Кто пользователь

Спецификация: «Основной пользователь — не программист. Политики настраиваются в Web UI; файл конфигурации доступен, но нужен только техническим пользователям». Сейчас любой путь, кроме нажатия «Разрешить», требует YAML или терминала. Технический пользователь справится, обычный застрянет на первом же шаге.

Типичный пользователь хочет:
1. чтобы его агент (Claude Code, Claude Desktop, Cursor, Claude.ai…) получил доступ к заметкам / почте / браузеру;
2. чтобы опасное спрашивалось у него в Telegram или уведомлением, а безопасное шло само;
3. видеть, что агент делал и что сейчас происходит.

## 3. Пользовательские пути и где трудно

Обозначения: **Б** — блокер (без терминала или YAML не пройти), **Т** — трудно (непонятно, много шагов), **Н** — неудобно.

### П1. Первый запуск

1. Установил, `gate4ai ui` → браузер открыл `/`: «Нет запросов, ожидающих подтверждения». **Т** — пустая страница не говорит, что делать дальше; нет ни чек-листа, ни ссылок «поставьте коннектор → добавьте агента → подключите его».
2. Перешёл в «Агенты»: пусто, «Новый агент добавляется в разделе „Политики“ (agents:)». **Б** — надо знать модель YAML.
3. «Политики»: комментарий отсылает к `gate4ai connectors install` и README. **Б** — терминал.
4. Ссылка входа живёт 2 минуты и одноразовая; закладка `127.0.0.1:7431` после истечения сессии (12 ч) ведёт на «выполните `gate4ai ui`». **Н** — в трее есть «Открыть Web UI», но страница входа о трее говорит только словами.

### П2. Установка коннектора

1. В Web UI негде. **Б**.
2. В CLI: `gate4ai connectors install files` → диалог согласия с возможностями `files ${setting:roots}/**`. **Т** — шаблон `${setting:roots}` непонятен: какие папки?
3. После установки коннектор не виден ни одному агенту, пока его не впишут в `profiles.<p>.connectors` YAML. **Б**.

### П3. Настройка коннектора (папки, почтовый ящик, сайты)

1. Настройки — раздел `connectors.<имя>` YAML, ключи (`roots`, `imap.host`, `allowed_domains`…) нигде в UI не перечислены. **Б**.
2. Пароль почты — отдельно в «Секретах» (алиас), затем ссылка `"@mail.work"` в YAML. Связь алиаса и коннектора не видна. **Т**.

### П4. Подключение локального агента (Claude Code, Claude Desktop, Cursor, VS Code, Codex, Gemini CLI)

1. Агент должен быть в `agents:` (YAML). **Б**.
2. «Выдать токен» → токен показан один раз с подсказкой «Передайте агенту как `GATE4AI_TOKEN`». **Т** — куда именно его вписать для конкретного клиента, не сказано; README даёт один JSON для `mcpServers`, а у VS Code ключ `servers`, у Codex — TOML.
3. После подключения непонятно, работает ли: нет «последнего обращения», нет проверки. **Т**.
4. Skill (`gate4ai skill`) для Claude Code — только из терминала. **Н**.

### П5. Подключение облачного агента (Claude.ai, ChatGPT)

1. Нужен публичный адрес: `gate4ai relay register` в терминале. **Б**.
2. Адрес relay взять неоткуда: в UI его нет, по умолчанию в CLI зашит `https://relay.gate4.ai`. **Т** (замечание из запроса).
3. «Подключить (remote MCP)» выдаёт код, но адреса `https://<device>.relay.gate4.ai/mcp` на странице нет — «…/mcp». **Т**.

### П6. Настройка правил

1. Только YAML + CEL. **Б** для основного пользователя.
2. Готовых шаблонов нет; спецификация их обещает («безопасная почта», «платежи только с подтверждением»). **Б**.
3. Симулятор просит аргументы JSON-объектом, хотя схема аргументов известна из манифеста. **Т**.
4. Ошибка проверки YAML показывается над формой, текст сохраняется — хорошо. Но комментарии YAML при правках из других мест (`relay register`) теряются. **Н**.

### П7. Подтверждение действия

1. На компьютере: уведомление ОС (если `desktop` в `approvals.channels`), страница `/`. Работает. **Н** — в «Недавних» нет предпросмотра и причины, нет ссылки на квитанцию; flash-сообщение — `approved a3f9…` техническим языком.
2. В Telegram — только если вручную настроено (П8).
3. С телефона — только через `gate4ai ui --remote` (нужен relay) с одноразовой ссылкой, которую надо как-то перенести на телефон. **Т**.
4. «Разрешать так всегда» (спецификация: создаёт предложение правила) — нет. **Т** — после третьего одинакового вопроса пользователь хочет кнопку.

### П8. Настройка уведомлений (Telegram, рабочий стол, браузер)

1. Каналы — `approvals.channels` в YAML; Telegram — BotFather, токен в Vault (`gate4ai vault set telegram.bot`), свой Telegram ID (где взять?), `approvals.telegram` в YAML. **Б**.
2. Статуса канала нет: если токен неверный, daemon пишет `WARN` в лог, UI молчит. **Т**.
3. Статистики (сколько запросов ушло, где решено) нет. **Н**.
4. Браузерного push нет. **Т** — с телефона без Telegram подтвердить нечем.

### П9. Агенту отказано — что делать

1. Журнал показывает `deny` и `rule_ids`. **Т** — по `id` правила не перейти к самому правилу, нет кнопки «разрешить это» (создать правило).

### П10. Журнал и проверка

1. Фильтры работают. **Н** — квитанция — сырой JSON, нет ссылок на агента и правило, нет экспорта из UI.

### П11. Самонастройка через агента

1. Агент не может ничего предложить: инструментов нет (спецификация это и требует). Пользователь, работающий в Claude Code, вынужден идти в UI и писать YAML сам, хотя агент мог бы подготовить правило. **Т**.

### П12. Инцидент: агент делает лишнее

1. «Отозвать все токены» есть. **Н** — нет «приостановить агента» с возвратом и нет подтверждения перед отзывом; после отзыва авто-подключённый клиент продолжает слать запросы со старым токеном.

### П13. Настройки приложения

1. Автозапуск — `gate4ai service install` в терминале. **Т**.
2. Адрес relay, таймаут подтверждений, магазин, сроки хранения — YAML. **Т**.
3. Кнопки «Настройки» нет (замечание из запроса).

### П14. Обновление и отзыв коннекторов

1. `gate4ai connectors update` / `refresh` — только CLI; если версия отозвана, коннектор молча выгружается, в UI не видно. **Т**.

### П15. Секреты

1. Можно добавить алиас, но нельзя удалить и нельзя увидеть, где он используется. **Н**.

## 4. План

Приоритеты: **P0** — снимает блокер основного пути, **P1** — заметно облегчает, **P2** — удобство. Порядок работ — раздел 4.10.

### 4.1. Каркас Web UI (P0)

- Навигация: **Обзор · Подтверждения · Агенты · Коннекторы · Правила · Журнал · Секреты · Настройки**. Счётчик ожидающих подтверждений рядом с пунктом меню.
- Маленький `static/app.js` с того же origin (CSP не ослабляется): копирование в буфер, раскрытие блоков, подтверждение опасных кнопок, автообновление очереди. Всё работает и без JS — формы остаются серверными.
- Язык интерфейса — русский, как сейчас; технические идентификаторы (`files.read`) — моноширинным рядом с человеческим названием.
- Сообщения flash — человеческим языком («Разрешено: claude-code → files.append, квитанция #a3f9c21e»).

### 4.2. Обзор — первый экран (P0, пути П1, П7)

`GET /` — новая главная; очередь подтверждений переезжает на `/approvals`.

- **Чек-лист первого запуска** (пока не пройден): 1) поставьте коннектор → `/connectors`; 2) добавьте агента → `/agents/new`; 3) агент обратился к gate4ai (по «последнему обращению»); 4) включите канал подтверждений → `/approvals#channels`; 5) (для облачных агентов) включите relay → `/settings#relay`. Каждый пункт — галочка по фактическому состоянию.
- Полоса состояния: daemon, relay (онлайн / нет / не настроен), каналы подтверждений, версия политики, целостность журнала.
- Блоки: «Ждут решения» (кратко, со ссылками), «Предложения агентов», «Последние действия» (10 из журнала), «Агенты» с последним обращением.

### 4.3. Агенты (P0, пути П4, П5, П12; запрос «agents»)

Бэкенд:
- **Последнее обращение:** таблица `agent_seen(agent, ts, via, calls)` в State Store; обновляется при опознании агента по токену (сокет агентов, `/v1/*` на публичном адресе, `/mcp`), не чаще раза в 10 секунд на агента. `TokenInfo.LastUsed` — по токену.
- **Структурные правки конфигурации** `internal/config/edit.go`: добавить/удалить агента, сменить профиль, создать профиль, добавить/удалить/переставить правило, задать список, настройки коннектора, каналы подтверждений, relay, магазин. Каждая правка — новая версия через `Config.Put` с комментарием («web: add agent claude-code»).
- **Автоподключение клиентов** `internal/front/agentsetup`: для Claude Code, Claude Desktop, Cursor, VS Code / Copilot, Codex CLI, Gemini CLI — где лежит конфигурация на каждой ОС, в каком формате (JSON `mcpServers`, JSON `servers` у VS Code, TOML `[mcp_servers.*]` у Codex), запись записи `gate4ai` (`command` — путь к бинарнику `gate4ai`, `args: [mcp]`, `env.GATE4AI_TOKEN`) с резервной копией файла и сохранением прочих ключей; отключение — удаление записи и отзыв токена. Для Claude Code дополнительно skill в `~/.claude/skills/gate4ai/SKILL.md`. Определение «клиент установлен» — по наличию каталога конфигурации / бинарника.

Экраны:
- `/agents` — карточки: имя, профиль (ссылка на правила), **последнее обращение** («3 мин назад через MCP»; «ни разу» — подсветка), активные токены, подключённые клиенты; кнопки «Подключить ещё клиент», «Отозвать доступ» (с подтверждением).
- `/agents/new` — мастер: 1) **кто агент** — плитки клиентов (Claude Code, Claude Desktop, Cursor, VS Code / Copilot, Codex CLI, Gemini CLI, Claude.ai / ChatGPT, «другой — CLI/скрипт»); 2) имя (подставляется по клиенту) и **профиль**: существующий или новый из шаблона (раздел 4.5) с галочками коннекторов; 3) подключение.
- `/agents/{name}` — подробности и подключение:
  - **кнопка «Подключить автоматически»** для локального клиента: выдаёт токен, пишет конфигурацию клиента, показывает путь файла и резервной копии, просит перезапустить клиент; ниже — **ручная инструкция** для того же клиента (готовый фрагмент с токеном, кнопка «Копировать»);
  - **облачный агент**: адрес `https://<device>/mcp` (из relay или `--public`), кнопка «Получить код подключения», пошаговая инструкция для Claude.ai и ChatGPT; без публичного адреса — ссылка «Включить relay» в настройки;
  - CLI / скрипт: `export GATE4AI_TOKEN=…`, `gate4ai skill`, `GATE4AI_URL` для другого компьютера;
  - токены с последним использованием и отзывом по одному; журнал этого агента.

### 4.4. Коннекторы — магазин (P0, пути П2, П3, П14; запрос «магазин»)

Бэкенд:
- `GET` каталога: индекс registry из кэша (`registry-index.json`), обновление — `RefreshIndex`; объединение с установленными (версия, доверие, доступно обновление, отозван).
- **Установка в один клик**: кнопка «Установить» открывает подтверждение с возможностями коннектора человеческим языком (`files ${setting:roots}/**` → «файлы в папках из настройки „roots“»), классами действий и уровнем доверия; «Установить» на этом экране = согласие (`consent` = возможности плана). После установки — автоматически: коннектор добавляется в выбранные профили (галочки «дать доступ агентам: …»), переход к настройкам коннектора.
- **Настройки коннектора**: поля из шаблонов `${setting:…}` в возможностях манифеста (`roots`, `imap.host`, `allowed_domains`…) плюс известные подсказки для официальных коннекторов (тип: список / строка / число / алиас секрета); секретное поле — ввод значения прямо здесь, сохраняется в Vault под алиасом `<коннектор>.<поле>`, в конфигурацию пишется `@алиас`.
- Обновление, удаление (с предупреждением, если правила ссылаются на действия), обновление индекса.

Экраны:
- `/connectors` — вкладки «Магазин» (карточки: название, описание, издатель и доверие, лицензия, ссылка на исходник, кнопка «Установить» / «Установлен» / «Обновить») и «Установленные» (версия, загружен ли, профили, где используется, «Настроить», «Удалить»).
- `/connectors/{name}` — описание, действия с классами (`read`/`write`/`external`/`money` человеческим языком), настройки (форма), профили с доступом (галочки), возможности.

### 4.5. Правила — конструктор и шаблоны (P0, путь П6, П9; запрос «policy»)

Модель не меняется: те же `profiles.<p>.rules` (`action`, `when` CEL, `effect`, `reason`) и `limits`. UI генерирует CEL, как требует спецификация («Web UI собирает условия из блоков… и генерирует CEL»).

- `/policy` — профили (вкладки). В профиле: доступные коннекторы (галочки), **таблица правил** человеческим языком («Почта → отправить письмо: **спрашивать**, если получатель не из списка „доверенные“»), действия «изменить», «удалить», «выше/ниже»; лимиты; итог по каждому действию коннекторов профиля — «что будет по умолчанию» (`read` → разрешено, остальное → спросить).
- **Добавить правило** (`/policy/rule`): 1) действие — выпадающий список из каталога (с классом и описанием) или «все действия коннектора»; 2) решение: разрешить / спрашивать / запретить; 3) условия — блоки по типу аргумента из `input_schema`:
  - строка / массив адресов → «из списка» (`x in lists.L` / `x.all(v, v in lists.L)`), «равно»;
  - путь → «внутри папки» (`glob(path, "P/**")`);
  - URL → «сайт из списка» (`domain_matches(url, [...])`);
  - число → «не больше / не меньше»;
  - «значение пришло из входящего письма или страницы» (`'untrusted_content' in provenance.x`);
  - каждое — с отрицанием «не»; несколько — через «и»;
  - «Свой CEL» — поле для технических пользователей;
  4) причина (показывается агенту и в подтверждении). Перед сохранением — предпросмотр сгенерированного правила и проверка на симуляторе.
- **Шаблоны** (`/policy/templates`): применяются к профилю, показывают, какие правила добавятся; набор зависит от установленных коннекторов:
  - «Только чтение» — запрет всех действий не-`read`;
  - «Спрашивать обо всём» — `ask` на все действия, включая чтение;
  - «Безопасная почта» — отправка доверенным без вопроса, адресаты из входящих писем — запрет, остальное — спросить; список `contacts_trusted`;
  - «Только черновики» — запрет `email.send`;
  - «Заметки в папке» — чтение и дописывание в папке без вопроса, запись — спросить, вне папки — запрет;
  - «Сайты по списку» — браузер только на доменах списка;
  - «Не больше N действий в день» — лимит `per_day`;
  - «Деньги — всегда с подтверждением» — `ask` на класс `money` (готов к коннекторам банка).
- **Списки** (`lists`): редактор строк.
- **Симулятор** — форма по `input_schema` действия вместо JSON; показывает решение и сработавшее правило со ссылкой.
- **YAML** — вкладка «Для технических пользователей» (текущий редактор, без изменений).
- **Из журнала и подтверждения**: у отказа/запроса — «Создать правило на основе этого» → форма добавления с подставленными действием и аргументами (спецификация: «разрешать так всегда… создаёт предложение правила»).
- Версии и откат — без изменений; у версии — кто автор (`web`, `cli`, `agent-proposal:<агент>`).

### 4.6. Подтверждения и каналы уведомлений (P0/P1, пути П7, П8; запрос «подтверждения»)

Бэкенд:
- **Статистика каналов**: обёртка над `pipeline.Notifier` считает по каналу «отправлено», «ошибок», последнюю ошибку и время; решения по каналам — из `approvals.channel`. Хранится в State Store (`kv`), отдаётся `GET /v1/approvals/channels`.
- **Telegram — мастер**: 1) ссылка на @BotFather и что нажать; 2) поле токена → `getMe` (проверка, имя бота), токен в Vault `@telegram.bot`; 3) «Напишите боту /start» → кнопка «Найти меня» (`getUpdates`, показывает отправителей — выбрать себя) → `owner_id`; 4) «Отправить тестовое сообщение»; 5) включить канал. Режим вебхука — галочка, если есть публичный адрес.
- **Уведомления на рабочем столе**: включить/выключить, «Тест».
- **Браузерный push** (новый канал `webpush`, P1): ключи VAPID устройства (в keychain), подписки браузеров (State Store); подписка — со страницы удалённого Web UI на адресе relay (`/ui/`, HTTPS обязателен для Service Worker) и с локального; уведомление — кратко «claude-code хочет files.append #a3f9c21e», шифрование RFC 8291 (aes128gcm), нажатие открывает `/ui/approvals`. Решение принимается только на странице с сессией, как и сейчас.
- **Удалённый вход с телефона**: кнопка «Ссылка для телефона» в Web UI — одноразовая ссылка `/ui/login?t=…` (то же, что `gate4ai ui --remote`) с QR-кодом (SVG генерируется в Go).

Экран `/approvals`:
- очередь: карточки с «что», «почему» (причина и правило со ссылкой), «кто», сроком, предпросмотром; «Разрешить» / «Отклонить» / «Разрешить и создать правило»;
- **Каналы уведомлений** (`#channels`): таблица — канал, статус (включён / выключен / ошибка: текст), отправлено, решено через канал, последнее событие; у каждого «Настроить» / «Тест» / «Включить»; инструкции раскрываются на месте; таймаут и действие по таймауту;
- история с фильтром по статусу и ссылкой на квитанцию.

### 4.7. Самонастройка через агента (P1, путь П11; запрос «самонастройка»)

Решение владельца (2026-10-15): это **такая же политика, как остальные** — только вместо внешнего сервиса коннектор `gate4ai` меняет сам gate4ai. Отдельного механизма предложений нет.

- Встроенный коннектор `gate4ai` (как `egress`, `runtime: builtin`, доступен любому профилю):
  - `gate4ai.change_policy` (класс `write`) — аргументы `summary`, `reason`, `changes[]` типизированных правок: `add_rule`, `remove_rule` (любого профиля — поле `profile`, по умолчанию профиль агента), `add_list_items`, `remove_list_items`, `add_connector`, `connector_settings`, `install_connector`. Исполнение применяет правки новой версией политики (автор `owner:gate4ai`, комментарий с агентом и `summary`); `install_connector` ставит коннектор с возможностями, перечисленными в запросе подтверждения;
  - `gate4ai.policy_summary` (`read`) — профиль агента, остальные профили и списки.
- Решение — обычная политика: без правил `write` → подтверждение владельца в **любом** канале (Web UI, трей, Telegram, push, удалённый `/ui/`); правило может разрешить или запретить (шаблон «Агентам нельзя менять настройки gate4.ai»).
- До решения политики ядро проверяет правки (хук `Pipeline.Describe`): форма, запрет секретов (алиасы Vault и секретные поля — `invalid_arguments`), корректность итоговой политики (CEL, ссылки). Тот же хук даёт текст запроса подтверждения: правки человеческим языком и возможности устанавливаемых коннекторов.

### 4.8. Настройки (P0, путь П13; запрос «Настройки»)

`/settings`, только локально:
- **Relay**: адрес relay — поле с значением по умолчанию `https://relay.gate4.ai` и пояснением «сервер, через который облачные агенты достучатся до этого компьютера; свой — `gate4ai-relay`»; кнопка «Подключить устройство» (регистрация, как `gate4ai relay register`); статус (онлайн / офлайн / не настроен), адрес устройства, адрес MCP. Если daemon запущен с `--public` — показывается этот адрес.
- **Автозапуск**: включён ли (systemd --user / LaunchAgent / Run), кнопки «Включить» / «Выключить» (код `gate4ai service` переносится в общий пакет `internal/platform/autostart`).
- **Подтверждения**: таймаут, действие по таймауту.
- **Магазин**: адрес индекса и ключи registry.
- **Самонастройка**: «Агенты могут предлагать изменения».
- **Хранение журнала**: сроки.
- О программе: версия, каталог данных, лог daemon.

### 4.9. Прочее, найденное по путям (P1–P2)

- **Журнал** (П10, П9): квитанция человеческим языком (агент, действие, аргументы, решение со ссылкой на правило, подтверждение — кто и где, проверка), сырой JSON — под спойлером; «Создать правило на основе этого»; экспорт архива кнопкой.
- **Секреты** (П15): удаление с подтверждением; «где используется» (поиск `@алиас` в конфигурации).
- **Вход** (П1): на странице входа — «Откройте из трея: значок gate4.ai → Открыть Web UI» и команда; ссылка входа с трея и CLI без изменений.
- **Пустые состояния**: на каждой странице — что здесь будет и одна кнопка, с которой начать.
- **Отзыв агента** (П12): подтверждение; для авто-подключённого клиента — убрать запись из его конфигурации.
