# Архитектура коннекторов gate4.ai

> Версия 0.3, 2026-10-15. Дополняет раздел «Коннекторы» в [спецификации](specification.md). Секреты, учётки и auth-модули — в [secret-architecture.md](secret-architecture.md).

> **Статус:** сейчас разрабатывается только `runtime: wasm`. `runtime: native` будет разработан, когда упрёмся в ограничения WASM; до этого всё, что описано про native, — проектное намерение, а не план работ.

## Зачем отдельная архитектура

Магазин коннекторов, где коннектор выполняет произвольный код на компьютере пользователя, повторит историю маркетплейсов навыков (сотни вредоносных skills в ClawHub). Поэтому:

1. **Одна модель прав для всех коннекторов**, включая наши (почта, файлы). Коннектора с «полным доступом» нет ни одного.
2. **Права объявляются в манифесте и обеспечиваются средой исполнения**, а не честным словом коннектора.
3. **Коннектор не видит секреты** — он называет слот учётки, а значение подставляет ядро (шаблоны, формы браузера) или auth-модуль, знающий протокол; вывести значение они могут только к адресу привязки учётки.
4. **Коннектору не доверяют в самоописании**: политика проверяет аргументы до запуска, результат помечается как недоверенный, результат действия с эффектом проверяется по факту (`verify`).

## Хост и коннекторы

Привилегированный код — только **хост** (daemon `gate4ai daemon` и его службы). Это инфраструктура, которая предоставляет коннекторам функции, а не коннекторы:

| Служба хоста | Что даёт коннекторам |
|---|---|
| Egress Proxy | исходящие HTTP / TLS-соединения по allowlist |
| Vault | учётки по слотам: шаблоны, ввод в формы, auth-модули — без передачи значений коннектору |
| Песочница auth-модулей | протоколы аутентификации (IMAP, OAuth, SSH, подписи) отдельными пакетами, вне ядра |
| Браузерный воркер (Stagehand, выделенный профиль Chrome) | функции `browser_*` |
| Файловая служба | доступ к разрешённым путям |
| Хранилище коннектора | изолированное KV с квотой |
| Журнал | запись доказательств и логов |
| Планировщик | события и расписание (целевое) |

Коннектор — модуль, который реализует действия из своего манифеста, пользуясь только этими функциями.

```
                 Action Pipeline (политики до запуска, подтверждение, журнал)
                                      │ execute / verify
          ┌───────────────────────────┴───────────────────────────┐
   runtime: wasm  (разрабатывается)                 runtime: native  (позже)
   wazero / Extism внутри daemon                    sandbox-runtime / контейнер
   только функции хоста (ABI ниже)                  сеть — только Egress Proxy
          └───────────────────────────┬───────────────────────────┘
                                      │ вызовы функций хоста / сеть
     Egress Proxy · Vault · браузерный воркер · файлы · KV · журнал · планировщик
```

## Манифест

Единый для всех коннекторов. К текущим полям (`connector`, `version`, `actions` с `class`, `input_schema`, `output_schema`, `verify`, `evidence`, `untrusted`, `sensitive`) добавляются среда исполнения, возможности, слоты учёток и лимиты:

```yaml
connector: mosenergosbyt
version: 1.2.0
runtime: wasm                      # wasm | native (native — позже)

capabilities:
  network:
    - { host: lk.mosenergosbyt.ru, port: 443, scheme: https }
  browser:
    domains: ["lk.mosenergosbyt.ru"]
  files: []                        # пути — шаблоны от настроек: "${setting:root}/**"
  storage: { quota_mb: 5 }
  events: []                       # подписки на события (целевое)

credentials:                       # слоты учёток; заполняет пользователь в экземпляре коннектора
  - { slot: login, types: [login], form: true, bind: ["https://lk.mosenergosbyt.ru"] }
  - { slot: otp,   types: [gate4ai/totp], module: gate4ai/auth-totp@1, form: true, bind: ["https://lk.mosenergosbyt.ru"] }

limits:
  memory_mb: 64
  timeout_s: 30
  verify_deadline_s: 86400         # общий срок отложенной проверки (verify_after)

actions:
  - name: submit_readings
    class: external
    input_schema:                  # аргументы — подмножество JSON Schema (как inputSchema MCP)
      type: object
      properties:
        account: { type: string }
        readings:
          type: array
          items:
            type: object
            properties: { meter: { type: string }, value: { type: number, minimum: 0 } }
            required: [meter, value]
      required: [account, readings]
    output_schema:                 # структурированный результат (как outputSchema MCP), необязательно
      type: object
      properties: { accepted_at: { type: string } }
      required: [accepted_at]
    verify: readings_history
  - name: pay_bill
    class: money
    verify: payment_status             # для money проверка обязательна

# только для runtime: native (позже)
native:
  justification: "нужен нативный криптопровайдер для подписи"
  sandbox: srt                     # srt | container
```

Правила:
- Любая возможность, не объявленная в манифесте, недоступна: функция хоста вернёт ошибку `capability_denied`.
- Политика пользователя может только **сузить** возможности манифеста, но не расширить.
- Учётки объявляются только слотами (`credentials`): способ (шаблон, форма, auth-модуль) и привязка — шаблон от настроек; хост раскрывает её при создании экземпляра (`<коннектор>.<имя>`), а пользователь заполняет слот своей учёткой. У одного коннектора может быть несколько экземпляров со своими учётками; агент выбирает экземпляр аргументом `account`.
- Изменение `capabilities` или `credentials` в новой версии требует повторного согласия пользователя; без согласия обновление не ставится.
- Аргументы и результат описываются подмножеством JSON Schema (см. «Близость к MCP»): у объектов лишних полей нет, порядок полей задаёт порядок флагов CLI и полей форм.
- Для `class: money` проверка результата (`verify`) обязательна.

## runtime: wasm

### Среда исполнения

- **wazero** (чистый Go, без CGO, одинаково на macOS / Linux / Windows), поверх — **Extism** Go SDK для функций хоста и обмена данными. Встроенные HTTP-функции Extism отключены: сеть только через наши функции хоста.
- Коннекторы пишутся на стандартном Go (`GOOS=wasip1`, `//go:wasmexport`), TinyGo, Rust, JS/TS (QuickJS) и других языках с PDK Extism. Совместимость Extism PDK со стандартным Go — проверить при реализации.
- Изоляция: у модуля нет доступа к файлам, сети, процессам и переменным окружения хоста; память модулей разных коннекторов не пересекается.
- Лимиты на вызов: память (`limits.memory_mb`), время (`limits.timeout_s`, отмена через контекст).

### Экспорты модуля

| Экспорт | Назначение |
|---|---|
| `manifest()` | манифест (сверяется с подписанным манифестом пакета) |
| `execute(req)` | исполнение действия: `action`, `args` (нормализованные по `input_schema`), экземпляр, несекретные `settings`; результат — см. ниже |
| `verify(req)` | отложенная проверка результата, если `execute` не смог проверить его сам |
| `on_event(ev)` | обработка подписанного события (целевое) |

### Близость к MCP

Коннектор — не MCP-сервер: граница песочницы — статический подписанный манифест и функции хоста, без сессий, уведомлений и динамического списка инструментов (каталог согласуется при установке). Из MCP взяты формы данных, чтобы MCP Front отдавал их агенту без перекодирования:

| gate4.ai (ABI v2) | MCP |
|---|---|
| `input_schema` действия | `inputSchema` инструмента |
| `output_schema` действия | `outputSchema` (обёрнут в ответ gate4ai, поле `result`) |
| `content`: `text`, `image`, `resource`, `resource_link` | блоки `content` результата инструмента |
| `structured` | `structuredContent.result` |
| `class` | `annotations` (`readOnlyHint`, `destructiveHint`, `openWorldHint`) |

Своё у gate4.ai и в MCP не отображается: `class`, `verify` / `verify_after`, `evidence`, `untrusted` / `source`, `sensitive`, `capabilities`, `credentials`. Агент видит первым блоком ответ gate4ai (статус решения, квитанция, `verified`, метка недоверенного контента), за ним — блоки коннектора; блоки недоверенного действия помечены `_meta["gate4.ai/untrusted"]`.

Коннектору не доверяют и здесь: хост проверяет блоки и сверяет `structured` с `output_schema`; не прошедший проверку результат агенту не отдаётся (`invalid_result`, действие — «не подтверждено»).

### Результат действия и проверка

По умолчанию действие проверяет себя само, синхронно: `execute` возвращает либо ошибку, либо подтверждённый результат. Это нормальный случай — например, после отправки показаний коннектор тут же видит их в истории.

`execute(req)` возвращает одно из:

| Результат | Значение |
|---|---|
| `error` | действие не выполнено (с причиной) |
| результат (`content` / `structured`, доказательства) | действие выполнено; если у действия есть `verify`, хост сразу вызывает `verify(req)` |
| результат с `verify_after_s: x` | действие отправлено, но синхронно проверить нельзя (платёж в обработке, письмо ещё не дошло); проверка — через `x` секунд |

Если `execute` вернул `verify_after(x)`, хост через `x` секунд вызывает `verify(req)` (`req` — то же действие и то, что `execute` сохранил для проверки, например номер операции). `verify` возвращает два статуса:

1. **Статус самого вызова** — `ok` (проверка отработала) или `error` (проверить не удалось: сеть, таймаут, сбой сервиса). При `error` хост повторяет `verify` по своему расписанию с отступом; после исчерпания попыток действие получает статус «не проверено» и уходит человеку.
2. **Статус действия** (только при `ok`):

| Статус | Значение |
|---|---|
| `verified` | действие подтверждено |
| `not_confirmed` | действие не подтверждено (не прошло, отклонено) — тревога и уведомление человеку |
| `verify_after(x)` | пока не ясно; повторить `verify` через `x` секунд |

Хост ограничивает цепочку `verify_after` общим сроком проверки (`limits.verify_deadline_s`); по его истечении действие получает статус «не проверено». Все промежуточные статусы пишутся в журнал.

### Функции хоста (ABI v2)

| Функция | Что делает | Ограничение |
|---|---|---|
| `http_request(req)` | HTTP(S)-запрос через Egress Proxy; `auth: {slot}` — заголовки ставит шаблон или auth-модуль слота (заголовок целиком), он же проверяет подпись ответа; `capture` — сохранить значение из ответа в учётку | `capabilities.network`; для `auth` — адрес привязки слота; ответ маскируется |
| `conn_open(slot, params)` / `conn_read` / `conn_write` / `conn_close` | соединение (IMAP, SMTP, SSH и т.п.); TLS — у хоста, аутентификацию проходит auth-модуль слота, коннектор получает уже аутентифицированный поток | адрес привязки слота |
| `conn_open_plain(host, port, tls)` | соединение без учётки | `capabilities.network` |
| `conn_write_secret(conn, field, prompt)` | ввести пароль в интерактивный запрос (`sudo`) через auth-модуль — только если последний вывод совпал с `prompt` | слот соединения |
| `fs_read` / `fs_write` / `fs_append` / `fs_list` / `fs_stat` | работа с файлами | `capabilities.files` + политика пользователя |
| `browser_open` / `browser_observe` / `browser_act` / `browser_extract` / `browser_screenshot_element` | действия в профиле Chrome экземпляра через браузерный воркер | `capabilities.browser.domains`; `browser_act` принимает только наблюдённое действие (селектор + метод), проходит через Executor; при секрете на странице `observe` / `extract` / `act` на естественном языке запрещены (`secret_on_page`) |
| `browser_fill_secret` / `browser_login` / `browser_capture_secret` | ввод учётки в поле (пароль — только в `type=password`, текст — по подписи формы), атомарный вход по сценарию, сохранение значения со страницы | привязка `form` слота; сохранение — с подтверждением человека |
| `secret_info(slot)` / `secret_commit` / `secret_discard` | метаданные учётки слота (тип, публичные поля, версия), фиксация или отмена черновой версии (сгенерированный пароль) | только свои слоты |
| `kv_get` / `kv_set` / `kv_delete` | собственное хранилище коннектора | `capabilities.storage.quota_mb` |
| `evidence_add(name, mime, data)` | доказательство в журнал | маскирование по `sensitive` |
| `log(level, msg)` | диагностический лог | секреты отфильтровываются |
| `time_now`, `random` | через WASI | — |

Секреты не передаются коннектору ни в `settings`, ни в ответах функций хоста. Исключение — `reveal` для нативных коннекторов с отдельным согласием пользователя (secret-architecture.md).

### Наши коннекторы на wasm

| Коннектор | Как реализуется |
|---|---|
| `files` | `fs_*` |
| `mail` | `conn_open` со слотом, аутентификация — auth-модули `gate4ai/auth-imap` / `gate4ai/auth-smtp`, разбор писем — в коннекторе |

| сервисы (ЖКХ, банк) | `browser_*` (вход — `browser_login`) + `http_request` со слотом; подпись банка — auth-модуль |

## runtime: native (позже)

Разрабатывается, когда упрёмся в ограничения WASM. Ожидаемые случаи:
- нативные библиотеки и бинарники: OCR, тяжёлый разбор PDF, экосистема Python;
- оборудование и криптопровайдеры: электронная подпись на токене (например, КриптоПро для Госуслуг и налоговой) — как нативный auth-модуль, а не коннектор;
- автоматизация десктопных приложений (банк-клиент, 1С) через API доступности ОС;
- готовые CLI-инструменты, которые дешевле запустить, чем переписать.

Намерение:
- тот же манифест и те же права; меняется только механизм обеспечения — процессная песочница (sandbox-runtime) или контейнер;
- сеть — только через Egress Proxy, секреты подставляются на выходе по привязкам слотов;
- `native.justification` обязателен, ревью строже, при установке — отдельное предупреждение.

## Магазин и цепочка поставок

- **Виды пакетов:** коннекторы (`kind: connector`) и auth-модули (`kind: auth`, имя `<издатель>/auth-<протокол>`; видят значения учёток, поэтому ставятся только с уровнями «проверен gate4.ai» и «проверенный издатель»; модуль сообщества — с явным согласием и предупреждением).
- **Пакет:** `.wasm` + манифест + подпись (Sigstore / cosign); воспроизводимая сборка из открытого исходника (лицензия коннекторов магазина — совместимая с AGPL-3.0, исходник обязателен).
- **Согласие при установке:** понятный список возможностей («запросы к lk.mosenergosbyt.ru, учётка для входа на lk.mosenergosbyt.ru, класс money»).
- **Уровни доверия:** «проверен gate4.ai» (ревью кода и возможностей), «проверенный издатель», «сообщество» (с предупреждением; по умолчанию — только действия класса `read`).
- **Версии зафиксированы;** автообновление — только в пределах уже согласованных возможностей.
- **Отзыв:** список отозванных версий доставляется через relay; отозванный коннектор отключается у всех.
- **Автопроверка при публикации:** анализ манифеста (подозрительные домены, `money` без проверки), сравнение возможностей между версиями.

## Текущее состояние и переход

Сделано (этапы 16–19, 23, 26 в PLAN.md): SDK `sdk-go` с манифестом и ABI v2 (формы данных MCP), WASM-хост на wazero, коннекторы `files`, `mail`, `browser`, `tbank` — WASM-модули, браузерный воркер — служба хоста, секреты в `Settings` не передаются, магазин с подписанными пакетами. `browser_act` — методы `click` / `fill` / `press` / `wait` по CSS-селектору и видимому тексту элемента (`text`, `value`, `timeout_ms`); после действия итоговый адрес снова проверяется по `capabilities.browser.domains`.

Расходится с этим документом в браузере: проверка, что селектор `browser_act` взят из `observe`, и режим «секрет на странице» не делаются — вместе с `browser_fill_secret` / `browser_login` (этап 12). До них в банк человек входит сам в выделенном профиле Chrome.

Расходится с целевой моделью секретов ([secret-architecture.md](secret-architecture.md)):
- `http_request` подставляет плейсхолдеры `{{secret:@alias}}` по `capabilities.secrets[].bind` → заменяется на `auth: {slot}` и `credentials`;
- `tls_dial` выполняет вход IMAP / SMTP хостом (`netauth` в sdk-go) → `conn_open(slot)` с auth-модулями `gate4ai/auth-imap` / `gate4ai/auth-smtp`;
- нет экземпляров коннекторов, слотов, браузерного ввода учёток.

Расходится с этим документом в проверке: `verify_after` хост принимает (статус `pending`, агенту — «отправлено, не подтверждено»), но отложенный вызов `verify` по расписанию, повторы при ошибке и `limits.verify_deadline_s` пока не делаются (решение человека 2026-10-15).

Переход — этап 12 в PLAN.md.
