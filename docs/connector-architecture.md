# Архитектура коннекторов gate4.ai

> Версия 0.6, 2026-10-19. Дополняет раздел «Коннекторы» в [спецификации](specification.md). Секреты, учётки и auth-модули — в [secret-architecture.md](secret-architecture.md).

> **Статус:** `runtime: wasm` — для любого кода, в том числе стороннего; `runtime: native` (этап 28) — только для пакетов проверенного издателя (сейчас — только gate4.ai), первый — браузер. Файлы — часть ядра (встроенный коннектор `files`).

## Зачем отдельная архитектура

Магазин коннекторов, где коннектор выполняет произвольный код на компьютере пользователя, повторит историю маркетплейсов навыков (сотни вредоносных skills в ClawHub). Поэтому:

1. **Одна модель прав для всех коннекторов**, включая наши. Недоверенный код — только WASM: у него есть лишь объявленные возможности. Нативный код без песочницы (с правами пользователя) — только от проверенного издателя и с явным согласием владельца; нативные пакеты сторонних издателей пока не принимаются — если вы хотите его создать, свяжитесь с нами, мы к этому благосклонны.
2. **Права объявляются в манифесте и обеспечиваются средой исполнения**, а не честным словом коннектора.
3. **Коннектор не видит секреты** — он называет слот учётки, а значение подставляет ядро (шаблоны, формы браузера) или auth-модуль, знающий протокол; вывести значение они могут только к адресу привязки учётки.
4. **Коннектору не доверяют в самоописании**: политика проверяет аргументы до запуска, результат помечается как недоверенный, результат действия с эффектом проверяется по факту (`verify`).

## Хост и коннекторы

Привилегированный код — только **хост** (daemon `gate4ai daemon` и его службы). Это инфраструктура, которая предоставляет коннекторам функции, а не коннекторы:

| Служба хоста | Что даёт коннекторам |
|---|---|
| Egress Proxy | исходящие HTTP / TLS-соединения по allowlist |
| Vault | учётки по слотам: шаблоны, ввод в формы, auth-модули — без передачи значений коннектору |
| Песочница auth-модулей | протоколы аутентификации (IMAP, OAuth, SSH, подписи) отдельными пакетами, вне ядра |
| Файловая служба | доступ к разрешённым путям (`fs_*`); на ней же — встроенный коннектор `files` |
| Надзор за нативными пакетами | запуск, перезапуск и остановка процессов `runtime: native` |
| Маршрутизатор вызовов | `service_call`: вызов действия другого коннектора через Action Pipeline |
| Хранилище коннектора | изолированное KV с квотой |
| Журнал | запись доказательств и логов |
| Планировщик | события и расписание (целевое) |

Коннектор — модуль, который реализует действия из своего манифеста, пользуясь только этими функциями.

```
                 Action Pipeline (политики до запуска, подтверждение, журнал)
                                      │ execute / verify
          ┌───────────────────────────┴───────────────────────────┐
   runtime: wasm  (любой издатель)                  runtime: native  (проверенный издатель)
   wazero внутри daemon                             дочерний процесс, JSON-RPC по stdio
   только функции хоста (ABI ниже)                  права пользователя, без песочницы
          └───────────────────────────┬───────────────────────────┘
                                      │ функции хоста · service_call
     Egress Proxy · Vault · файлы · KV · журнал · маршрутизатор вызовов · планировщик

   runtime: builtin — коннекторы ядра (files, gate4ai, egress): Go-код daemon
```

## Манифест

Единый для всех коннекторов. К текущим полям (`connector`, `version`, `actions` с `class`, `input_schema`, `output_schema`, `verify`, `evidence`, `untrusted`, `sensitive`) добавляются среда исполнения, возможности, слоты учёток и лимиты:

```yaml
connector: mosenergosbyt
version: 1.2.0
runtime: wasm                      # wasm | native (только проверенный издатель) | builtin (ядро)
contract: 1                        # мажор контракта действий из services (для поставщиков)
services: [readings_history]       # действия, которые другие коннекторы могут вызвать через service_call

capabilities:
  network:
    - { host: app.example.org, port: 443, scheme: https }
  browser:
    domains: ["app.example.org"]
  files: []                        # пути — шаблоны от настроек: "${setting:root}/**"
  storage: { quota_mb: 5 }
  events: []                       # подписки на события (целевое)
  services:                        # действия других коннекторов (service_call)
    - target: browser
      contract: 1
      actions: [open, observe, act]
      params: { sites: { domains: ["app.example.org"] } }   # передаются поставщику как разрешение

credentials:                       # слоты учёток; сейчас — {slot, bind}, связь — connectors.<имя>.credentials
  - { slot: login, types: [login], form: true, bind: ["https://app.example.org"] }
  - { slot: otp,   types: [gate4ai/totp], module: gate4ai/auth-totp@1, form: true, bind: ["https://app.example.org"] }

limits:
  memory_mb: 64
  timeout_s: 30
  verify_deadline_s: 86400         # общий срок отложенной проверки (verify_after)

actions:
  - name: submit_readings
    class: external
    input_schema:                  # аргументы — подмножество JSON Schema (как inputSchema MCP)
      type: object
      properties:
        account: { type: string }
        readings:
          type: array
          items:
            type: object
            properties: { meter: { type: string }, value: { type: number, minimum: 0 } }
            required: [meter, value]
      required: [account, readings]
    output_schema:                 # структурированный результат (как outputSchema MCP), необязательно
      type: object
      properties: { accepted_at: { type: string } }
      required: [accepted_at]
    verify: readings_history
    calls: [browser.open, browser.act]   # подвызовы действия (service_call); покрыты его разрешением
  - name: pay_bill
    class: money
    verify: payment_status             # для money проверка обязательна

# только для runtime: native
platforms: [linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, windows/amd64]
```

Правила:
- Любая возможность, не объявленная в манифесте, недоступна: функция хоста вернёт ошибку `capability_denied`.
- Политика пользователя может только **сузить** возможности манифеста, но не расширить.
- Учётки объявляются только слотами (`credentials`): способ (шаблон, форма, auth-модуль) и привязка — шаблон от настроек; хост раскрывает её при создании экземпляра (`<коннектор>.<имя>`), а пользователь заполняет слот своей учёткой. У одного коннектора может быть несколько экземпляров со своими учётками; агент выбирает экземпляр аргументом `account`.
- Изменение `capabilities` или `credentials` в новой версии требует повторного согласия пользователя; без согласия обновление не ставится. В согласие входят также `runtime: native` («работает без песочницы»), действия классов `write` / `external` / `money` (по классам) и лимиты выше значений по умолчанию; их изменение — тоже согласие заново. Согласия, записанные прежними версиями gate4ai (без этих строк), остаются действительными для того же пакета.
- Лимиты: `memory_mb` не больше 4096 (предел линейной памяти WASM) и `timeout_s` не больше 3600 — иначе манифест не принимается; для новой установки и обновления — не больше 1024 МБ и 600 с. По умолчанию — 128 МБ и 60 с.
- Аргументы и результат описываются подмножеством JSON Schema (см. «Близость к MCP»): у объектов лишних полей нет, порядок полей задаёт порядок флагов CLI и полей форм.
- Для `class: money` проверка результата (`verify`) обязательна.
- `services` и `contract`: действия из `services` может вызвать другой коннектор, у которого они объявлены в `capabilities.services` с тем же мажором `contract`. Несовместимое изменение их схем (удалённое или переименованное поле, новое обязательное поле, сужение типа) — только с повышением `contract`; это проверяет `gate4ai contract diff` в CI коннектора и registry.
- `calls` у действия — его подвызовы `<поставщик>.<действие>`: каждый должен быть в `capabilities.services`. Из действия хост пропускает только объявленные у него подвызовы (в том числе из `verify`), класс подвызова не выше класса действия (порядок `read` < `write` < `external` < `money`). Подвызовы входят в описание действия, запрос подтверждения и список возможностей на экране согласия; их изменение требует согласия заново.
- `platforms` обязателен для `runtime: native`: пакет собирается под каждую платформу из списка.
- `title` (коротко, по-английски: «Files», у действия — «Read a file») и `i18n` (`{ru: {title, description}}` у коннектора и у действий) — человеческие названия и переводы для Web UI; основной язык — английский. Ключ языка — две строчные латинские буквы. Поля необязательны; без них Web UI показывает имя и описание. Daemon до 0.8 разбирает манифест строго и пакет с этими полями не поставит — официальные коннекторы добавят их, когда прежние версии выйдут из обращения (спецификация, «Технический долг»); пока их переводы — в каталоге Web UI ядра.

## runtime: wasm

### Среда исполнения

- **wazero** (чистый Go, без CGO, одинаково на macOS / Linux / Windows) со своим ABI (`sdk-go/abi`): импорты модуля — только `gate4ai.host_call` / `gate4ai.host_result` и WASI без файлов, окружения и аргументов; Extism не используется.
- Коннекторы пишутся на стандартном Go (`GOOS=wasip1`, `//go:wasmexport`) на PDK `sdk-go/connector`; другой язык возможен, если он реализует тот же ABI.
- Модуль обязан экспортировать свою линейную память и функции ABI; иначе он не загружается. Ошибки загрузки и паники хоста на неожиданном модуле не роняют daemon: коннектор помечается незагруженным.
- Изоляция: у модуля нет доступа к файлам, сети, процессам и переменным окружения хоста; память модулей разных коннекторов не пересекается.
- Каждый вызов — новый экземпляр модуля; инициализатор (`_initialize`) выполняется в контексте этого вызова, поэтому функции хоста доступны уже в нём (с теми же проверками возможностей).
- Лимиты на вызов: память (`limits.memory_mb`), время (`limits.timeout_s`, отмена через контекст). Одновременных экземпляров одного коннектора — не больше 8: память коннектора ограничена 8 × `memory_mb`, остальные вызовы ждут в пределах своего срока.

### Экспорты модуля

| Экспорт | Назначение |
|---|---|
| `manifest()` | манифест (сверяется с подписанным манифестом пакета) |
| `execute(req)` | исполнение действия: `action`, `args` (нормализованные по `input_schema`), экземпляр, несекретные `settings`; результат — см. ниже |
| `verify(req)` | отложенная проверка результата, если `execute` не смог проверить его сам |
| `on_event(ev)` | обработка подписанного события (целевое) |

### Близость к MCP

Коннектор — не MCP-сервер: граница песочницы — статический подписанный манифест и функции хоста, без сессий, уведомлений и динамического списка инструментов (каталог согласуется при установке). Из MCP взяты формы данных, чтобы MCP Front отдавал их агенту без перекодирования:

| gate4.ai (ABI v2) | MCP |
|---|---|
| `input_schema` действия | `inputSchema` инструмента |
| `output_schema` действия | `outputSchema` (обёрнут в ответ gate4ai, поле `result`) |
| `content`: `text`, `image`, `resource`, `resource_link` | блоки `content` результата инструмента |
| `structured` | `structuredContent.result` |
| `class` | `annotations` (`readOnlyHint`, `destructiveHint`, `openWorldHint`) |

Своё у gate4.ai и в MCP не отображается: `class`, `verify` / `verify_after`, `evidence`, `untrusted` / `source`, `sensitive`, `capabilities`, `credentials`. Агент видит первым блоком ответ gate4ai (статус решения, квитанция, `verified`, метка недоверенного контента), за ним — блоки коннектора; блоки недоверенного действия помечены `_meta["gate4.ai/untrusted"]`.

Коннектору не доверяют и здесь: хост проверяет блоки и сверяет `structured` с `output_schema`; не прошедший проверку результат агенту не отдаётся (`invalid_result`, действие — «не подтверждено»).

### Результат действия и проверка

По умолчанию действие проверяет себя само, синхронно: `execute` возвращает либо ошибку, либо подтверждённый результат. Это нормальный случай — например, после отправки показаний коннектор тут же видит их в истории.

`execute(req)` возвращает одно из:

| Результат | Значение |
|---|---|
| `error` | действие не выполнено (с причиной) |
| результат (`content` / `structured`, доказательства) | действие выполнено; если у действия есть `verify`, хост сразу вызывает `verify(req)` |
| результат с `verify_after_s: x` | действие отправлено, но синхронно проверить нельзя (платёж в обработке, письмо ещё не дошло); проверка — через `x` секунд |

Если `execute` вернул `verify_after(x)`, хост через `x` секунд вызывает `verify(req)` (`req` — то же действие и то, что `execute` сохранил для проверки, например номер операции). `verify` возвращает два статуса:

1. **Статус самого вызова** — `ok` (проверка отработала) или `error` (проверить не удалось: сеть, таймаут, сбой сервиса). При `error` хост повторяет `verify` по своему расписанию с отступом; после исчерпания попыток действие получает статус «не проверено» и уходит человеку.
2. **Статус действия** (только при `ok`):

| Статус | Значение |
|---|---|
| `verified` | действие подтверждено |
| `not_confirmed` | действие не подтверждено (не прошло, отклонено) — тревога и уведомление человеку |
| `verify_after(x)` | пока не ясно; повторить `verify` через `x` секунд |

Хост ограничивает цепочку `verify_after` общим сроком проверки (`limits.verify_deadline_s`); по его истечении действие получает статус «не проверено». Все промежуточные статусы пишутся в журнал.

### Функции хоста (ABI v2)

| Функция | Что делает | Ограничение |
|---|---|---|
| `http_request(req)` | HTTP(S)-запрос через Egress Proxy; `auth: {slot}` — заголовки ставит шаблон или auth-модуль слота (заголовок целиком), он же проверяет подпись ответа; `capture` — сохранить значение из ответа в учётку | `capabilities.network`; для `auth` — адрес привязки слота; ответ маскируется |
| `conn_open(slot, params)` / `conn_read` / `conn_write` / `conn_close` | соединение (IMAP, SMTP, SSH и т.п.); TLS — у хоста, аутентификацию проходит auth-модуль слота, коннектор получает уже аутентифицированный поток | адрес привязки слота |
| `conn_open_plain(host, port, tls)` | соединение без учётки | `capabilities.network` |
| `conn_write_secret(conn, field, prompt)` | ввести пароль в интерактивный запрос (`sudo`) через auth-модуль — только если последний вывод совпал с `prompt` | слот соединения |
| `fs_read` / `fs_write` / `fs_append` / `fs_list` / `fs_stat` | работа с файлами | `capabilities.files` + политика пользователя |
| `service_call(target, action, input)` | действие другого коннектора: вход и выход сверяются со схемами поставщика, мажор контракта — с `capabilities.services`; вызов проходит Action Pipeline с политикой агента корневого действия: разрешение родительского действия покрывает объявленные у него подвызовы (`calls`), явное правило `deny` на действие поставщика отклоняет вызов, правило `ask` на него во вложенном вызове не действует (подвызов показан в подтверждении родителя); квитанция — с `parent`; глубина вложенности — до 4, циклы запрещены, срок — остаток срока вызывающего | подвызов объявлен в `calls` вызывающего действия и в `capabilities.services`; класс не выше класса действия; `params` передаются поставщику (`ExecRequest.caller`) |
| `secret_info(slot)` / `secret_commit` / `secret_discard` | метаданные учётки слота (тип, публичные поля, версия), фиксация или отмена черновой версии (сгенерированный пароль) | только свои слоты |
| `kv_get` / `kv_set` / `kv_delete` | собственное хранилище коннектора | `capabilities.storage.quota_mb` |
| `evidence_add(name, mime, data)` | доказательство в журнал | маскирование по `sensitive` |
| `log(level, msg)` | диагностический лог | секреты отфильтровываются |
| `time_now`, `random` | через WASI | — |

Секреты не передаются коннектору ни в `settings`, ни в ответах функций хоста. Исключение — `reveal` для нативных коннекторов с отдельным согласием пользователя (secret-architecture.md).

Браузер — нативный пакет `browser`, а не функции хоста: прежние `browser_*` заменены действиями пакета через `service_call` (`open`, `observe`, `act`, `page_extract`, `page_screenshot`; страница — одна на корневой вызов, освобождается по `end_call`; сайты — `params.sites` вызывающего). Те же действия доступны агенту в сеансе (`session` из `open`, плюс `network` и `close`) — см. [connector-authoring.md](connector-authoring.md). Ввод учёток в формы (`fill_secret`, `login`, `capture_secret`) — тоже действия пакета; значение он получает от daemon только для origin привязки слота.

### Наши коннекторы

| Коннектор | Как реализуется |
|---|---|
| `files` | встроен в ядро (`runtime: builtin`) поверх файловой службы; корни — `connectors.files.roots` (по умолчанию `~/Documents`; скрытые файлы и папки ниже корня, ключи и данные приложений закрыты всегда — `allow_hidden`, `allow_paths`), в профиле `default` — правило `ask` на каждое действие |
| `mail` | `conn_open` со слотом, аутентификация — auth-модули `gate4ai/auth-imap` / `gate4ai/auth-smtp`, разбор писем — в коннекторе |
| `browser` | нативный пакет: браузерный воркер (выделенный профиль Chrome, CDP, Stagehand), действия агента `read` / `screenshot` / `extract` и сеанс страницы (`open` → `observe` / `act` / `network` / `page_extract` / `page_screenshot` → `close`), те же действия со страницей для других коннекторов через `service_call` |
| сервисы (ЖКХ, банк) | действия `browser` через `service_call` (вход — `browser.login`) + `http_request` со слотом; подпись банка — auth-модуль |

## runtime: native

Для кода, которому нужны ресурсы ОС, недоступные из WASM: браузер (Chrome, CDP), позже — OCR, тяжёлый разбор PDF, криптопровайдеры (КриптоПро — как нативный auth-модуль), автоматизация десктопных приложений, готовые CLI.

**Доверие.** Нативный пакет работает без песочницы, с правами пользователя: его проверки (сайты, пути) — код, которому приходится верить. Поэтому:
- ставится только от издателя с уровнем «проверен gate4.ai» (сейчас — только сам gate4.ai); пакет другого издателя магазин отклоняет с ошибкой «нативные пакеты сторонних издателей пока не принимаются — свяжитесь с нами, мы благосклонны»;
- на экране согласия — отдельная строка «работает без песочницы, с правами пользователя»;
- песочница ОС (sandbox-runtime + Egress Proxy, как у `gate4ai run`) — позже, как усиление.

**Пакет.** На каждую платформу из `platforms` — свой `.g4c`: `manifest.yaml`, бинарник `connector` (`connector.exe` на Windows) и `package.json` с платформой, дайджестом и подписью издателя; дайджест — sha256 от `gate4ai-connector-native-v1\n` + sha256 манифеста + платформа + sha256 бинарника. Сборка воспроизводимая (`CGO_ENABLED=0 -trimpath`, Go из `go.mod`). В индексе registry у версии — по артефакту на платформу (`platforms: {"linux/amd64": {url, sha256, digest}}`); daemon скачивает только свой.

**Процесс.** Daemon запускает бинарник при первом вызове и держит его запущенным; одна копия на коннектор. Окружение процесса — минимальное: системные переменные (`PATH`, `HOME`, язык, `TMPDIR`, дисплей, `XDG_*`, профиль пользователя Windows) и `GATE4AI_NATIVE=1`, без прочих переменных daemon (токенов, ключей). Обмен — JSON-RPC 2.0 построчно через stdin/stdout, stderr — в лог daemon (секреты вырезаются):

| Метод | Кто вызывает | Что |
|---|---|---|
| `initialize {protocol}` | daemon | версия протокола (сейчас 1); ответ — манифест, он сверяется с манифестом пакета |
| `execute` / `verify` | daemon | то же, что экспорты WASM-модуля; в `execute` для вызова через `service_call` — `caller` (коннектор, корневой вызов, `params`) |
| `end_call {call}` | daemon | корневой вызов закончился — освободить его состояние (например, сессию браузера) |
| `host {call, fn, req}` | пакет | функция хоста (`log`, `kv_*`, `evidence_add`, `service_call`, …) в рамках вызова `call` — с той же проверкой возможностей, что у WASM |
| `shutdown` | daemon | завершиться (обновление, удаление, остановка daemon) |

Запись в stdin процесса идёт со сроком: процесс, переставший читать, не задерживает вызов, отмену и остановку (`shutdown` — асинхронно, затем kill по сроку). Упавший процесс daemon перезапускает при следующем вызове; больше 5 падений за минуту — коннектор помечается неисправным до следующего обновления или перезапуска daemon. Обновление и удаление — `shutdown`, замена файлов, запуск; daemon не перезапускается. Несовместимая версия протокола — ошибка установки, а не вызова.

SDK: `sdk-go/native` — `native.Serve(connector)` для тех же `connector.Connector`, что у WASM; `abi.Host` поверх `host`.

## Магазин и цепочка поставок

- **Виды пакетов:** коннекторы (`kind: connector`) и auth-модули (`kind: auth`, имя `<издатель>/auth-<протокол>`; видят значения учёток, поэтому ставятся только с уровнями «проверен gate4.ai» и «проверенный издатель»; модуль сообщества — с явным согласием и предупреждением).
- **Пакет:** `.wasm` (или бинарник под платформу для `runtime: native`) + манифест + подпись издателя (Ed25519 над дайджестом пакета, `package.json`; Sigstore / cosign не используются); воспроизводимая сборка из открытого исходника (лицензия коннекторов магазина — совместимая с AGPL-3.0, исходник обязателен).
- **Согласие при установке:** понятный список возможностей («запросы к app.example.org, учётка для входа на app.example.org, класс money»).
- **Уровни доверия:** «проверен gate4.ai» (ревью кода и возможностей), «проверенный издатель», «сообщество» (с предупреждением; по умолчанию — только действия класса `read`). Пакет из файла, подписанный ключом издателя из registry, получает уровень издателя, только если его версия есть в индексе и совпадает с записью (дайджест и возможности); иначе — только как своя сборка (`--dev`, уровень `local`).
- **Имена:** `data`, `gate4ai`, `egress`, `secret` и имена коннекторов ядра зарезервированы (каталог KV коннекторов, действия ядра): такой коннектор не ставится, а в индексе registry его быть не может.
- **Данные коннектора (KV)** лежат в `connectors/data/<имя>` с меткой издателя; после удаления они остаются, но коннектор другого издателя (или своя сборка) под тем же именем их не получает: при установке они стираются, план установки об этом предупреждает.
- **Индекс registry** не может откатиться: хост помнит последний принятый индекс и не принимает индекс со старшей отметкой `updated` (или с той же отметкой, но без отзыва, который уже был), а также просроченный (`expires`, если поле задано; registry задаёт его, только когда версии gate4ai без поддержки поля выйдут из употребления — они отвергают индекс с неизвестными полями).
- **Версии зафиксированы;** автообновление — только в пределах уже согласованных возможностей.
- **Отзыв:** список отозванных версий доставляется через relay; отозванный коннектор отключается у всех.
- **Автопроверка при публикации:** анализ манифеста (подозрительные домены, `money` без проверки), сравнение возможностей между версиями.

## Текущее состояние и переход

Сделано: SDK `sdk-go` с манифестом и ABI v2 (формы данных MCP), WASM-хост на wazero, встроенный коннектор `files` (на PDK, `Engine.Builtin`), нативные пакеты (`internal/connectors/native`: процесс под надзором, JSON-RPC по stdio, `reveal`, перезапуск и отключение после частых падений; магазин — `.g4c` под платформу и список `.platforms.json`), `service_call` и контракты (`sdk-go/contract`, `gate4ai contract gen|diff`), коннектор `mail` — WASM-модуль (`tbank` удалён 2026-10-18, будет сделан заново), `browser` — нативный пакет, секреты в `Settings` не передаются, магазин с подписанными пакетами. `browser.act` — методы `click` / `fill` / `press` / `wait` по CSS-селектору и видимому тексту элемента (`text`, `value`, `timeout_ms`); после действия итоговый адрес снова проверяется по сайтам вызывающего. Сеанс браузера для агента (с 2026-10-18): `observe` с `elements` (видимые интерактивные элементы с однозначным селектором), `network` (fetch / XHR страницы, токены и ответы входа скрыты), `close` с записанными шагами — фикстурой для `hosttest.Replay`; заготовка коннектора — `gate4ai connectors new`, лог своей сборки — в ответе (`log`) и `gate4ai connectors logs`.

Вход на сайты (этап 12, 2026-10-18): учётки владельца — `credentials` в конфигурации (форма из полей-констант и секретов Vault с отправкой или `via` — коннектор входа; доступ — `use` профилей агентов и `connectors`), действия `browser.login {account}` и `browser.fill_secret` (класс `write`); значения daemon передаёт только нативному `browser` и только в этих действиях (`ExecRequest.Revealed`, форма — `ExecRequest.Login`, учётки вызывающего без значений — `ExecRequest.Accounts`); после ввода секрета страницу нельзя читать до перехода (`secret_on_page`); страница может быть на сайте входа доступной учётки вне сайтов вызывающего, ответ подсказывает `login_required`; учётка с `via` — daemon вызывает коннектор входа вложенным вызовом с тем же `account` (`Caller.Session` — сеанс агента); код от человека — `fill_secret` с `source: human` через вопрос в канале подтверждений; каждое использование — `secret.use` в журнале. Манифест: слоты `credentials: [{slot, bind, types?, fields?}]` (в согласии), связь — `connectors.<имя>.credentials`.

Доработки по прогону «агент пишет коннектор» (2026-10-19): одобренное действие исполняется не в контексте HTTP-запроса одобрения; отмена вызова доходит до нативного пакета (уведомление `cancel`, срок вызова — `limits.timeout_s` и в самом процессе), ответ — `cancelled`; `browser.network` — по CDP Network (тела ответов, странице не видно, только разрешённые сайты, `redact_params`), ожидание — `wait_for_*` у `open` / `observe`, `expect_*` у `act` и «сеть успокоилась» после перехода, адрес проверяется после стабилизации (тихий вход через SSO), `observe` по элементу и `outline`, `close --all`, одна вкладка, `navigator.webdriver` скрыт, Stagehand запускается с `--remote-allow-origins`; при секрете на странице снимки — с закрашенными полями; слоты учёток с `types` (`form` / `via`) и `fields`; `call_reasons` у подвызовов; одноразовые коды в адресах маскируются для всех коннекторов; ошибка действия — в логе коннектора; агент ставит свою сборку через `change_policy` (`install_dev_connector`); MCP по stdio сообщает `tools/list_changed`; `gate4ai fixture scrub`.

Расходится с этим документом в браузере: проверка, что селектор `browser.act` взят из `observe`, не делается; у слотов нет способа `module` (auth-модули).

Расходится с целевой моделью секретов ([secret-architecture.md](secret-architecture.md)):
- `http_request` подставляет плейсхолдеры `{{secret:@alias}}` по `capabilities.secrets[].bind` → заменяется на `auth: {slot}` и `credentials`;
- `tls_dial` выполняет вход IMAP / SMTP хостом (`netauth` в sdk-go) → `conn_open(slot)` с auth-модулями `gate4ai/auth-imap` / `gate4ai/auth-smtp`;
- нет экземпляров коннекторов, слотов, браузерного ввода учёток.

Расходится с этим документом в проверке: `verify_after` хост принимает (статус `pending`, агенту — «отправлено, не подтверждено»), но отложенный вызов `verify` по расписанию, повторы при ошибке и `limits.verify_deadline_s` пока не делаются (решение человека 2026-10-15).
