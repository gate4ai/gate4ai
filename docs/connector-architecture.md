# Архитектура коннекторов gate4.ai

> Дополняет раздел «Коннекторы» в [спецификации](specification.md). Секреты и учётки — в [secret-architecture.md](secret-architecture.md).

`runtime: wasm` — коннекторы магазина, любой код, в том числе сторонний; `runtime: builtin` — компоненты ядра: Браузер и Файлы (`internal/connectors/builtin/`), в магазине их нет. Другой среды исполнения нет: у коннектора магазина нет ни сети, ни процессов — внешний мир только через встроенный браузер (`service_call`), файлы — через `fs_*`.

## Зачем отдельная архитектура

Магазин коннекторов, где коннектор выполняет произвольный код на компьютере пользователя, повторит историю маркетплейсов навыков (сотни вредоносных skills в ClawHub). Поэтому:

1. **Одна модель прав для всех коннекторов**, включая наши. Недоверенный код — только WASM: у него есть лишь объявленные возможности. Код без песочницы (с правами пользователя) — только ядро gate4ai: встроенные Браузер и Файлы.
2. **Права объявляются в манифесте и обеспечиваются средой исполнения**, а не честным словом коннектора. Сайты и папки коннектора — строки с режимом; владелец может их сузить, но не расширить сверх того, что открыто в списках доступа Браузера и Файлов.
3. **Коннектор не видит секреты** — он называет слот учётки, а значения вводит в форму сайта встроенный браузер (`browser.login`, `browser.fill_secret`) и только на origin привязки.
4. **Коннектору не доверяют в самоописании**: политика проверяет аргументы до запуска, результат помечается как недоверенный, результат действия с эффектом проверяется по факту (`verify`).

## Хост и коннекторы

Привилегированный код — только **хост** (daemon `gate4ai daemon` и его службы). Это инфраструктура, которая предоставляет коннекторам функции, а не коннекторы:

| Служба хоста | Что даёт коннекторам |
|---|---|
| Браузер (встроенный) | страницы сайтов из строк `sites` коннектора — через `service_call` |
| Файловая служба | доступ к папкам из строк `folders` коннектора (`fs_*`), в пределах списка доступа Файлов; на ней же — встроенный компонент `files` |
| Маршрутизатор вызовов | `service_call`: вызов действия другого коннектора через Action Pipeline |
| Хранилище коннектора | изолированное KV с квотой |
| Журнал | запись доказательств и логов |
| Vault | учётки по слотам — без передачи значений коннектору |

Коннектор — модуль, который реализует действия из своего манифеста, пользуясь только этими функциями.

```
                 Action Pipeline (списки доступа и политики до запуска, подтверждение, журнал)
                                      │ execute / verify
          ┌───────────────────────────┴───────────────────────────┐
   runtime: wasm  (магазин, любой издатель)         runtime: builtin  (ядро: browser, files, gate4ai)
   wazero внутри daemon                             Go-код daemon на том же PDK и тех же функциях хоста
   только функции хоста (ABI ниже)                  права пользователя (Chrome, диск)
          └───────────────────────────┬───────────────────────────┘
                                      │ функции хоста · service_call
                файлы · KV · журнал · маршрутизатор вызовов → браузер
```

## Манифест

Единый для всех коннекторов:

```yaml
connector: mosenergosbyt
title: Mosenergosbyt                # необязательно: человеческое название для Web UI
i18n: { ru: { title: Мосэнергосбыт } }
description: Meter readings and bills
version: 1.2.0
runtime: wasm                      # wasm (магазин) | builtin (ядро)
contract: 1                        # мажор контракта действий из services (для поставщиков)
services: [readings_history]       # действия, которые другие коннекторы могут вызвать через service_call

sites:                             # сайты коннектора в браузере и режим доступа — умолчания;
  - { domain: app.example.org, access: allow }      # allow | read | ask | deny; домен — шаблон ${setting:…} допустим
folders:                           # папки для fs_* — умолчания; allow | append | read | deny
  - { path: "${setting:root}", access: read }

capabilities:
  storage: { quota_mb: 5 }
  services:                        # действия других коннекторов (service_call)
    - target: browser
      contract: 1
      actions: [open, observe, act, login]

credentials:                       # слоты учёток входа; связь — connectors.<имя>.credentials
  - { slot: login, types: [form], bind: ["https://app.example.org"] }

limits:
  memory_mb: 64
  timeout_s: 30

actions:
  - name: submit_readings
    title: Submit meter readings
    class: external
    input_schema:                  # аргументы — подмножество JSON Schema (как inputSchema MCP)
      type: object
      properties:
        account: { type: string }
        readings:
          type: array
          items:
            type: object
            properties: { meter: { type: string }, value: { type: number, minimum: 0 } }
            required: [meter, value]
      required: [account, readings]
    output_schema:                 # структурированный результат (как outputSchema MCP), необязательно
      type: object
      properties: { accepted_at: { type: string } }
      required: [accepted_at]
    verify: readings_history
    calls: [browser.open, browser.act]   # подвызовы действия (service_call); покрыты его разрешением
    call_reasons: { browser.act: "fills the readings form" }
  - name: pay_bill
    class: money
    verify: payment_status             # для money проверка обязательна
```

Поля действия: `name`, `title`, `description`, `class`, `input_schema`, `output_schema`, `verify`, `evidence`, `untrusted` (результат — недоверенный контент), `sensitive` (аргументы, которые маскируются), `example`, `service_only` (только для других коннекторов), `calls`, `call_reasons`, `i18n`.

Правила:
- Любая возможность, не объявленная в манифесте, недоступна: функция хоста вернёт ошибку `capability_denied`. `capabilities` — только `storage`, `services` и `reveal` (`reveal` — алиасы Vault, значения которых хост передаёт компоненту; принимается только у `runtime: builtin` — ключ модели браузера).
- Политика пользователя и списки доступа могут только **сузить** возможности манифеста, но не расширить.
- `sites` и `folders` — умолчания. При установке daemon копирует их в `connectors.<имя>.sites` / `folders` (`ensureConnectorAccess`), владелец правит на странице коннектора в Web UI или `change_policy` (`set_connector_site`, `set_connector_folder`). Режима `connector` у строк коннектора нет, у папок — и `ask`. Без строки для сайта вызов браузера отклоняется; без строки для папки `fs_*` отвечает `capability_denied`.
- Учётки входа — слотами `credentials` (`{slot, bind, description, types, fields}`); пользователь связывает слот со своей учёткой в `connectors.<имя>.credentials`.
- Изменение `capabilities`, `sites`, `folders` или `credentials` в новой версии требует повторного согласия пользователя; без согласия обновление не ставится. В согласие входят также действия классов `write` / `external` / `money` (по классам), подвызовы и лимиты выше значений по умолчанию; их изменение — тоже согласие заново.
- Лимиты: `memory_mb` не больше 4096 (предел линейной памяти WASM) и `timeout_s` не больше 3600 — иначе манифест не принимается; для новой установки и обновления — не больше 1024 МБ и 600 с. По умолчанию — 128 МБ и 60 с.
- Аргументы и результат описываются подмножеством JSON Schema (см. «Близость к MCP»): у объектов лишних полей нет, порядок полей задаёт порядок флагов CLI и полей форм.
- Для `class: money` проверка результата (`verify`) обязательна.
- `services` и `contract`: действия из `services` может вызвать другой коннектор, у которого они объявлены в `capabilities.services` с тем же мажором `contract`. Несовместимое изменение их схем (удалённое или переименованное поле, новое обязательное поле, сужение типа) — только с повышением `contract`; это проверяет `gate4ai contract diff` в CI gate4ai (`ci.yml`, манифесты `internal/connectors/builtin/*/manifest.yaml` сравниваются с прошлым тегом).
- `calls` у действия — его подвызовы `<поставщик>.<действие>`: каждый должен быть в `capabilities.services`. Из действия хост пропускает только объявленные у него подвызовы (в том числе из `verify`), класс подвызова не выше класса действия (порядок `read` < `write` < `external` < `money`). Подвызовы входят в описание действия, запрос подтверждения и список возможностей на экране согласия; их изменение требует согласия заново.
- `title` (коротко, по-английски: «Files», у действия — «Read a file») и `i18n` (`{ru: {title, description}}` у коннектора и у действий) — человеческие названия и переводы для Web UI; основной язык — английский. Ключ языка — две строчные латинские буквы. Поля необязательны; без них Web UI показывает имя и описание. В индексе магазина названий и переводов нет; названия и русские переводы встроенного браузера для Web UI — в ядре (`i18n_connectors.go`).

## Списки доступа

Первый уровень решения для Браузера и Файлов — общие для всех агентов списки в конфигурации (`sdk-go/access`, `internal/pipeline/access.go`):

```yaml
access:
  sites:
    - { domain: "*.example.com", access: ask }
    - { domain: app.example.org, access: allow }
    - { domain: "*", access: ask }
  folders:
    - { path: "~/Documents", access: ask }
    - { path: "~/Documents/notes", access: append }
```

- Режимы сайтов: `allow` — всё без вопроса; `read` — действия класса `read` без вопроса, остальные с подтверждением; `connector` — только через коннектор магазина (агенту напрямую — отказ); `ask` — всегда спрашивать; `deny` — закрыто. У папок ещё `append`: чтение, список и дописывание без вопроса, перезапись — с подтверждением; `read` у папки — чтение и список без вопроса, остальное — с подтверждением.
- Совпадение: `*.example.org` — поддомены и сам `example.org`, `*` — любой сайт; папка — она сама и всё ниже, в пути допустимы `*` и `**`. Побеждает самая конкретная строка (больше буквальных символов), при равенстве — более строгая.
- Решение по действию: нет строки — отказ; `deny` в списке — всегда отказ; если ни одно правило политики не сработало, режим строки заменяет умолчание класса; явное правило политики (`allow` / `ask` / `deny`) побеждает строку. Для действий сеанса без `url` (`act`, `observe`, …) pipeline берёт адрес открытой страницы у браузера (`PageURL`). Запрос подтверждения несёт сайт или папку (`Decision.Scope`: `site:host` / `folder:dir`), и в Web UI и Telegram кроме «Разрешить / Отклонить» есть «В разрешённые» (действие класса `read` → `read`, иначе `allow`, у папки — `append`) и «В запрещённые».
- Встроенные Браузер и Файлы получают из списков производные настройки: Браузер — `allowed_domains` / `blocked` / `mode` (всё, кроме `deny`; строка `*` — режим `blocklist`), Файлы — `roots` (все папки, кроме `deny`). Владелец их не задаёт.
- Коннектор магазина: вложенный вызов браузера проходит, только если его разрешают и строка коннектора, и строка Браузера (строже из двух; `deny` Браузера закрывает сайт для всех); строка коннектора `ask` останавливает вложенный вызов до решения владельца (в пределах срока вызывающего действия и таймаута подтверждений), одобренный вызов исполняется в контексте вызывающего. Открытые сайты коннектора браузер получает в `Caller.Params` (`domains`, `blocked`, `mode`). `fs_*` проверяют режим строки коннектора по операции (`read` / `list` / `append` / `write`) и список Файлов: папка в нём отсутствует или `deny` — отказ.
- Начальная конфигурация (`cmd/gate4ai/daemon.go`, `emptyConfig`): сайты — `*` `ask`, папки — `~/Documents` `ask`, профиль `default` с `files` и `browser`, правил нет. Старые установки: `internal/daemon/migrate.go` переносит `connectors.browser.allowed_domains` / `blocked` / `mode` и `connectors.files.roots` в списки (`read` / `deny`), удаляет пакеты `browser` / `email` и почту из политики.
- Правка: Web UI (Доступ → Браузер, Файлы), `gate4ai access sites|folders set <значение> <режим>` / `remove`, `gate4ai sites allow <сайт>` (= `access sites set <сайт> read`), API `GET/POST /v1/access`, агентом — `change_policy` с `set_site_access` / `set_folder_access` (всегда с подтверждением владельца).

## runtime: wasm

### Среда исполнения

- **wazero** (чистый Go, без CGO, одинаково на macOS / Linux / Windows) со своим ABI (`sdk-go/abi`): импорты модуля — только `gate4ai.host_call` / `gate4ai.host_result` и WASI без файлов, окружения и аргументов; Extism не используется.
- Коннекторы пишутся на стандартном Go (`GOOS=wasip1`, `//go:wasmexport`) на PDK `sdk-go/connector`; другой язык возможен, если он реализует тот же ABI.
- Модуль обязан экспортировать свою линейную память и функции ABI; иначе он не загружается. Ошибки загрузки и паники хоста на неожиданном модуле не роняют daemon: коннектор помечается незагруженным.
- Изоляция: у модуля нет доступа к файлам, сети, процессам и переменным окружения хоста; память модулей разных коннекторов не пересекается. Сетевых функций хоста нет: сайт доступен только страницей встроенного браузера.
- Каждый вызов — новый экземпляр модуля; инициализатор (`_initialize`) выполняется в контексте этого вызова, поэтому функции хоста доступны уже в нём (с теми же проверками возможностей).
- Лимиты на вызов: память (`limits.memory_mb`), время (`limits.timeout_s`, отмена через контекст). Одновременных экземпляров одного коннектора — не больше 8: память коннектора ограничена 8 × `memory_mb`, остальные вызовы ждут в пределах своего срока.

### Экспорты модуля

| Экспорт | Назначение |
|---|---|
| `manifest()` | манифест (сверяется с подписанным манифестом пакета) |
| `execute(req)` | исполнение действия: `action`, `args` (нормализованные по `input_schema`), несекретные `settings`; результат — см. ниже |
| `verify(req)` | проверка результата действия |

### Близость к MCP

Коннектор — не MCP-сервер: граница песочницы — статический подписанный манифест и функции хоста, без сессий, уведомлений и динамического списка инструментов (каталог согласуется при установке). Из MCP взяты формы данных, чтобы MCP Front отдавал их агенту без перекодирования:

| gate4.ai | MCP |
|---|---|
| `input_schema` действия | `inputSchema` инструмента |
| `output_schema` действия | `outputSchema` (обёрнут в ответ gate4ai, поле `result`) |
| `content`: `text`, `image`, `resource`, `resource_link` | блоки `content` результата инструмента |
| `structured` | `structuredContent.result` |
| `class` | `annotations` (`readOnlyHint`, `destructiveHint`, `openWorldHint`) |

Своё у gate4.ai и в MCP не отображается: `class`, `verify` / `verify_after`, `evidence`, `untrusted` / `source`, `sensitive`, `capabilities`, `sites`, `folders`, `credentials`. Агент видит первым блоком ответ gate4ai (статус решения, квитанция, `verified`, метка недоверенного контента), за ним — блоки коннектора; блоки недоверенного действия помечены `_meta["gate4.ai/untrusted"]`.

Коннектору не доверяют и здесь: хост проверяет блоки и сверяет `structured` с `output_schema`; не прошедший проверку результат агенту не отдаётся (`invalid_result`, действие — «не подтверждено»).

### Результат действия и проверка

По умолчанию действие проверяет себя само, синхронно: `execute` возвращает либо ошибку, либо подтверждённый результат. Это нормальный случай — например, после отправки показаний коннектор тут же видит их в истории.

`execute(req)` возвращает одно из:

| Результат | Значение |
|---|---|
| `error` | действие не выполнено (с причиной) |
| результат (`content` / `structured`, доказательства) | действие выполнено; если у действия есть `verify`, хост сразу вызывает `verify(req)` |
| результат с `verify_after_s: x` | действие отправлено, но синхронно проверить нельзя (платёж в обработке) |

`verify(req)` (`req` — то же действие и то, что `execute` сохранил для проверки, например номер операции) возвращает `verified` (действие подтверждено), `not_confirmed` (не прошло, отклонено — тревога и уведомление человеку) или `verify_after` (пока не ясно). Ошибка вызова `verify` — статус «не проверено». Результат с `verify_after_s` и ответ `verify_after` хост принимает как `pending`: агенту — «отправлено, не подтверждено»; отложенного повторного вызова `verify` по расписанию нет. Статусы пишутся в журнал.

### Функции хоста

Полный список — `sdk-go/abi/abi.go`, реализация — `sdk-go/hostfuncs`:

| Функция | Что делает | Ограничение |
|---|---|---|
| `fs_read` / `fs_write` / `fs_append` / `fs_list` / `fs_stat` | работа с файлами: открываются относительно дескриптора корня строки (`os.Root`), для строки на один файл последний компонент не может быть симлинком | строка `folders` коннектора, режим которой разрешает операцию (`allow` — всё, `append` — чтение, список и дописывание, `read` — чтение и список), и список доступа Файлов (папки нет или `deny` — `capability_denied`) |
| `service_call(target, action, input)` | действие другого коннектора: вход и выход сверяются со схемами поставщика, мажор контракта — с `capabilities.services`; вызов проходит Action Pipeline с политикой агента корневого действия: разрешение родительского действия покрывает объявленные у него подвызовы (`calls`), явное правило `deny` на действие поставщика отклоняет вызов, правило `ask` на него во вложенном вызове не действует (подвызов показан в подтверждении родителя), а строка сайта коннектора `ask` — действует (вызов ждёт владельца); квитанция — с `parent`; глубина вложенности — до 4, циклы запрещены, срок — остаток срока вызывающего | подвызов объявлен в `calls` вызывающего действия и в `capabilities.services`; класс не выше класса действия; для браузера — сайт в строках коннектора и Браузера |
| `kv_get` / `kv_set` / `kv_delete` | собственное хранилище коннектора | `capabilities.storage.quota_mb` |
| `evidence_add(name, mime, data)` | доказательство в журнал | маскирование по `sensitive` |
| `log(level, msg)` | диагностический лог | секреты отфильтровываются |
| `time_now`, `random` | через WASI | — |

Секреты не передаются коннектору ни в `settings`, ни в ответах функций хоста. Исключение — `capabilities.reveal` у `runtime: builtin` (secret-architecture.md).

Браузер — встроенный компонент `browser`, а не функции хоста: другие коннекторы вызывают его действия через `service_call` (`open`, `observe`, `act`, `dialog`, `download`, `page_screenshot`, `login`, `fill_secret`; страница — одна на корневой вызов, освобождается по `end_call`; сайты — строки `sites` коннектора в пределах списка Браузера). Те же действия доступны агенту в сеансе (`session` из `open`, плюс `network`, запросы со страницы `get` / `head` (класс `read`) и `post` / `put` / `patch` / `delete` (`write`) — метод в имени действия, чтобы класс и правила политики различали чтение и изменения, — и `close`) — см. [connector-authoring.md](connector-authoring.md). Ввод учёток в формы (`login`, `fill_secret`) — тоже действия браузера; значение он получает от daemon только в них и только для origin привязки учётки. Проверки, что селектор `browser.act` взят из `observe`, нет.

Страницы браузера не делятся между вызовами: первая сессия (сеанс агента или корневой вызов коннектора) занимает стартовую вкладку Chrome, следующие — свои вкладки того же профиля, не больше 4 одновременно (`worker.MaxSessions`); одноразовые `read` / `screenshot` — во временных фоновых вкладках (до 4). Когда места нет, `open` отвечает `limit_exceeded` с тем, чьи это сеансы (агент и его клиент — сессия Claude Code или процесс, `ExecRequest.Client`), с какого времени и когда они закроются по простою; `--wait_for_browser 10m` ждёт в очереди. `close --all` закрывает только сеансы вызывающего клиента; закрытый сеанс на свой id отвечает, кто, когда и почему его закрыл (`browser.close`, `close --all`, простой 10 минут, Chrome закрыт или упал).

Каждое действие сеанса ограничено сроком целиком, включая переход: `timeout_ms` (для `act` — плюс ожидание результата), иначе 45 с; по истечении — `timeout` с состоянием страницы. Пока действие идёт, другие вызовы того же сеанса через 5 с отвечают `session_blocked` (какое действие, с какого времени), а не ждут. JS-диалоги вкладки (`Page.javascriptDialogOpening`) воркер видит по CDP: `beforeunload` при `open` / `reload`, о которых попросил вызывающий, принимается сам; alert / confirm / prompt прерывают действие ответом `dialog_open {type, message}`, и до ответа `browser.dialog --accept | --dismiss [--text]` все действия сеанса отвечают тем же сразу; во временной вкладке диалоги закрываются сами. Живость Chrome проверяется запросом к браузеру (`Browser.getVersion`), а не к странице: открытый диалог не выдаётся за падение.

`observe --elements` кроме ссылок, кнопок, полей и ролей видит самописные виджеты: элементы с обработчиком click / mousedown (их отмечает скрипт, который ставится в каждый документ вкладки до скриптов страницы), с `cursor: pointer`, `[tabindex]`, роли `option` / `listbox` / `combobox`, а также иконки без текста внутри интерактивных элементов (крестик удаления выбранного значения: `icon: true`, имя — aria-label, title или текст рядом). `act --text` берёт самый внутренний видимый элемент с этим текстом среди элементов по селектору и их потомков; клик — последовательность pointerdown / mousedown / pointerup / mouseup / click; не найдя элемент, `act` называет видимые элементы с этим текстом и их селекторы.

### Компоненты ядра и коннекторы магазина

| Компонент | Как реализуется |
|---|---|
| `files` | встроен в ядро (`runtime: builtin`) поверх файловой службы; папки и режим — список доступа Файлов (`access.folders`; в начальной конфигурации `~/Documents` — `ask`); скрытые файлы и папки ниже корня, ключи и данные приложений закрыты всегда (`allow_hidden`, `allow_paths`) |
| `browser` | встроен в ядро (`runtime: builtin`, `internal/connectors/builtin/browser`): браузерный воркер (выделенный профиль Chrome, CDP), действия агента `read` / `screenshot` и сеанс страницы (`open` → `observe` / `act` / `network` / `get` … `delete` / `page_screenshot` → `close`), те же действия со страницей для других коннекторов через `service_call`; сайты и режим — список доступа Браузера (`access.sites`) |
| коннекторы к сайтам (магазин, WASM) | действия `browser` через `service_call` (вход — `browser.login`), сайты — `sites` манифеста; заготовка — `gate4ai connectors new`, см. [connector-authoring.md](connector-authoring.md); пример — `e2e/testconnector` к тестовому сайту `e2e/testsite` |

## Магазин и цепочка поставок

- **Пакет:** `.wasm` + манифест + подпись издателя (Ed25519 над дайджестом пакета, `package.json`; Sigstore / cosign не используются); только `runtime: wasm` — другой пакет магазин не принимает; воспроизводимая сборка из открытого исходника (лицензия коннекторов магазина — совместимая с AGPL-3.0, исходник обязателен).
- **Согласие при установке:** понятный список возможностей («сайт app.example.org: allow, учётка для входа на app.example.org, класс money»).
- **Уровни доверия:** «проверен gate4.ai» (ревью кода и возможностей), «проверенный издатель», «сообщество» (с предупреждением; по умолчанию — только действия класса `read`). Пакет из файла, подписанный ключом издателя из registry, получает уровень издателя, только если его версия есть в индексе и совпадает с записью (дайджест и возможности); иначе — только как своя сборка (`--dev`, уровень `local`).
- **Имена:** `data`, `gate4ai`, `egress`, `secret` и имена компонентов ядра (`files`, `browser`) зарезервированы (каталог KV коннекторов, действия ядра): такой коннектор не ставится, а в индексе registry его быть не может.
- **Данные коннектора (KV)** лежат в `connectors/data/<имя>` с меткой издателя; после удаления они остаются, но коннектор другого издателя (или своя сборка) под тем же именем их не получает: при установке они стираются, план установки об этом предупреждает.
- **Индекс registry** не может откатиться: хост помнит последний принятый индекс и не принимает индекс со старшей отметкой `updated` (или с той же отметкой, но без отзыва, который уже был), а также просроченный (`expires`, если поле задано).
- **Версии зафиксированы;** обновление — `gate4ai connectors update` или Web UI, с согласием заново, если возможности изменились.
- **Отзыв:** список отозванных версий — в индексе registry; отозванная версия не ставится и выгружается при обновлении индекса.
- **Проверка при публикации:** манифест (в том числе `money` без `verify`), `gate4ai registry check` (с `--fetch` — каждый пакет против своей записи), `gate4ai contract diff` для контрактов.
