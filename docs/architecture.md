# Устройство кода

Один репозиторий `gate4ai/gate4ai` и один Go-модуль `github.com/gate4ai/gate4ai`: ядро (`cmd/`, `internal/`; Браузер и Файлы — `internal/connectors/builtin/`), `sdk-go/` (Apache-2.0), `relay/`, `e2e/`. Каталога `connectors/` в репозитории нет: коннекторы магазина — отдельные репозитории издателей. Направление зависимостей проверяет CI (`scripts/deps-check.sh`: прямые импорты пакетов и их тестов под linux, darwin, windows и wasip1; только этот модуль — `GOWORK=off`, ошибка `go list` — провал): `sdk-go` — только сам себя; `relay` — сам себя и `sdk-go`; ядро — себя и `sdk-go`, `relay` — только в тестах; `e2e` — что угодно, но его не импортирует никто. Остальные репозитории проекта и их лицензии — [repo-structure.md](repo-structure.md).

План рефакторинга — [refactoring-plan.md](refactoring-plan.md); технический долг (структурные этапы) — [tech-debt.md](tech-debt.md).

## Журнал: что можно менять

Записи журнала неизменяемы: обновление gate4ai не переписывает журнал задним числом, а журнал любой прошлой версии открывается новой без ручных действий.

- **Версия схемы** — `PRAGMA user_version`; миграции — упорядоченный список в `internal/audit/schema.go`. При открытии журнал старше программы копируется рядом (`journal.db.v<N>-<время>.bak`, `VACUUM INTO`) и мигрирует одной транзакцией. Журнал новее программы не открывается: ошибка «update gate4ai», файл не меняется. Журналы до версионирования (v0.7.5 и раньше) — версия 0, миграция 1 приводит их к общей схеме.
- **Миграция только добавляет**: таблицы, индексы, колонки с `DEFAULT`. Нельзя: менять или пересчитывать `hash`, `prev_hash`, `body`, подписи и `prev` чекпоинтов; удалять, переименовывать и менять тип колонок; править выпущенную миграцию — изменение схемы всегда новая миграция в конце списка (и строка в `TestMigrationsAppendOnly`).
- **Формат квитанции** (`receipts.format`, в архиве экспорта — `format`, без него — 1) задаёт правила хэша. Формат 1: sha256 канонического JSON (RFC 8785) записанного документа квитанции. Хэш проверяется по самому документу, а не по пересборке из `Receipt`, поэтому новые поля в `Receipt` (лучше с `omitempty`) старые записи не задевают. Другой способ сериализации или хэширования — новый номер формата; запись формата N всегда проверяется по правилам N, неизвестный формат — ошибка «update gate4ai». Подписываемые байты чекпоинта (`SignedBytes`) тоже не меняются: новый формат чекпоинта — новый `type`.
- **Наследие прежних версий** проверка принимает только в рамках того, что те версии писали: чекпоинты v0.7.2 и раньше без `prev` — только в начале списка (после первого связанного все связаны); квитанции, отредактированные до `journal.redact`, при первой миграции покрываются одной записью `journal.redact` с `legacy: true` — дописывается новая квитанция, старые не меняются.
- **Защита**: `internal/audit/testdata/journal-v*` — журналы, ключи и архивы экспорта, записанные настоящим кодом выпущенных версий; `TestGoldenJournals` открывает их, мигрирует, проверяет цепочку и чекпоинты, побитное совпадение прежних строк, дописывает новые записи и проверяет старый архив. Золотые журналы не пересоздают; новый формат журнала — новый каталог рядом (сгенерированный кодом того релиза).
