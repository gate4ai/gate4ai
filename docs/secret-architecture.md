# Архитектура секретов gate4.ai

> Дополняет разделы «Vault (секреты)» и «Изоляция локальных агентов» в [спецификации](specification.md) и [connector-architecture.md](connector-architecture.md).

## Инварианты

Спецификация, «Принципы дизайна»:
- агент никогда не видит значения секретов;
- коннектор не видит значения (исключение `reveal` — только с согласием пользователя, см. ниже);
- секрет уходит только туда, куда привязан;
- значения не попадают в журнал, вывод, доказательства и тесты.

## Кто видит значение

| Кто | Видит значение | Что делает |
|---|---|---|
| **Ядро** (daemon) | да | хранилище, привязки и их проверка, передача значений встроенному браузеру, маскирование, журнал `secret.use` |
| **Встроенный браузер** `browser` (часть ядра, `runtime: builtin`) | только поле учётки, которое вводит, и только для origin привязки | ввод в форму входа (`browser.login`, `browser.fill_secret`), режим «секрет на странице» |
| **Коннекторы магазина** (WASM) | нет | называют слот учётки или алиас в `browser.login` / `fill_secret`; получают ответы страницы после маскирования |

```
 Агент ──MCP/CLI──▶ Action Pipeline ──▶ Коннектор (без значений)
                                           │ service_call(browser.login | browser.fill_secret)
                                           ▼
 ┌─ Ядро ──────────────────────────────────────────────────────────────────┐
 │ Vault (keychain) · привязки · маскирование ответов · журнал secret.use  │
 └──────────────────────────────┬──────────────────────────────────────────┘
                                ▼
                    встроенный браузер: ввод в форму
                    на origin привязки учётки (ExecRequest.Revealed)
```

## Модель угроз

| Кто | Чего опасаемся | Чем закрыто |
|---|---|---|
| Агент (prompt injection) | выманить секрет: подставить его в другое место, прочитать из DOM, скриншота или ответа | место подстановки задаёт привязка; режим «секрет на странице»; маскирование |
| Коннектор | получить значение и вывести его в ответ или на чужой сайт | значение есть только у ядра (и у встроенного браузера при вводе); у коннектора нет сети, страницы — только в его сайтах; ответ он получает после маскирования |
| Коннектор на том же сайте | попросить ввести пароль в поле, которое видят другие (заголовок темы форума) | секрет — только в `input[type=password]`, в текстовое поле — только по явному `type: text` поля в учётке; каждый ввод в журнале |
| Веб-страница | собрать автозаполнение скрытыми полями, подменить origin через iframe | проверка origin документа и фрейма, видимости и типа поля |
| Сервер назначения | отразить секрет обратно в ответе | маскирование ответа, включая производные формы |

**Остаточный риск, который принимаем.** Значение вводится только в поле формы на origin привязки. Если на этом сайте есть место, видимое другим, утечка через него возможна. Ядро делает этот канал узким (только `input[type=password]`, иначе явный `type: text` у поля) и видимым (`secret.use` в журнале), но не закрывает его до конца.

## Хранилище (Vault)

- Значения — в keychain ОС, по записи на алиас и индекс алиасов; временная ошибка keychain не выкидывает алиас из индекса (значение читается позже).
- Без keychain (`gate4ai daemon --keystore file`) значения лежат в `keys.json` (0600, каталог 0700, атомарная запись с fsync) **открытым текстом**; daemon, однажды работавший с keychain, не переключается на файл молча.
- Значения задаёт только владелец: Web UI (раздел **Пароли и учётки**) и `gate4ai vault set <alias>` (скрытый ввод, stdin или `--from-env`). Список — `gate4ai vault list`, удаление — `gate4ai vault rm`. В Web UI у каждого алиаса видно, где он используется (Telegram-бот, relay, Egress Proxy, коннектор, учётка).
- Инструментов для чтения, создания и изменения значений у агента нет. Исключение — `add_credential` в `gate4ai.change_policy`: только новая учётка входа с новыми алиасами, всегда с подтверждением человека, значения задаёт владелец (спецификация, «Безопасность самого шлюза»). Любую правку `change_policy` (учётки, правила, списки доступа) подтверждает владелец: правило `allow` на неё не действует (`policy.OwnerOnly`).

## Секреты коннекторов

У коннекторов магазина нет сети и нет собственных секретов: манифест не объявляет ни алиасов, ни адресов. Единственный путь секрета к сайту — учётка входа, которую вводит в форму встроенный браузер (`browser.login`, `browser.fill_secret`, ниже). Коннектор называет слот учётки или алиас; подстановки в заголовки HTTP и входа в протоколы (IMAP, SMTP) нет.

- **Маскирование** (ответы и лог коннектора, текстовые доказательства, ответы агенту) — за один проход по всем значениям (пересекающиеся участки закрываются целиком, порядок значений не важен) и их производным формам: base64 и base64url (во всех выравниваниях), URL-, JSON- и HTML-экранирование, hex, другой регистр.
- Значения в `Settings` коннектора не передаются; в настройках — только алиасы.

### Исключение `reveal`

`capabilities.reveal: [алиас | ${setting:…}]` — хост передаёт компоненту значение алиаса в запросе (`ExecRequest.Revealed`). Манифест с `reveal` принимается только у `runtime: builtin` (`manifest.Validate`); сейчас встроенные компоненты его не объявляют (ключа модели у Браузера больше нет). У коннекторов магазина (WASM) `reveal` нет: такой манифест не проходит проверку.

## Учётки входа на сайты

Учётка входа (`credentials` в конфигурации) — метаданные в конфигурации (с её версиями и откатом), значения секретных полей — в Vault по алиасам. Вход — одно действие без логики: ни ветвлений, ни LLM, ни записи траекторий.

Простую учётку заводит Web UI (**Пароли и учётки → Добавить учётку**): адрес страницы входа, логин и пароль. Учётка получает имя по хосту (`@login.example.com`), пароль — в Vault под `<учётка>.password`, поле логина — `input[type=email], input[autocomplete=username], input[name*=login i], input[name*=user i], input[type=text]`, пароль — `input[type=password]`, отправка — Enter; доступ — выбранным агентам (`use`). Сложный вход (несколько шагов, коды, свои селекторы) — в YAML:

```yaml
credentials:
  "@emias":
    bind: ["https://login.mos.ru"]          # точные origin, где разрешён ввод
    form:
      fields:
        - { selector: "#login",    value: "+79001234567" }       # константа: видна в конфигурации и журнале
        - { selector: "#password", secret: "@emias.password" }   # секрет из Vault
        - { name: sms, selector: "#sms", type: text }            # поле кода, который вводит человек
      submit: { selector: "#bind" }         # или { press: Enter } в последнем поле
      success: { url_prefix: "https://lk.emias.mos.ru/" }
    login_page: { selector: "#login" }      # признак страницы входа (необязательно)
    use: [connector-dev]                    # профили агентов
    connectors: [lk_emias]                  # коннекторы (вход из их действий)
    prompts: { sms: "Код из SMS" }          # вопросы человеку для fill_secret с source: human
  "@bank":
    bind: ["https://id.bank.example"]
    via: { connector: bank_login, action: login }   # сложный вход — коннектор входа
```

- У учётки либо `form`, либо `via`. Секрет по умолчанию вводится только в `input[type=password]`; в поле другого типа — только с явным `type: text` у поля (логин, PIN в текстовом поле) — это видно владельцу. Правило поля задаёт владелец, подписи форм не записываются.
- **`browser.login {account}`:** origin верхнего документа ∈ `bind` (иначе `wrong_origin`); все поля найдены, видимы (ненулевой размер, не прозрачны, в пределах страницы), редактируемы, нужного типа (иначе `form_mismatch`, ничего не вводится); ввод (`Input.insertText`), документ помечается; отправка; ожидание ухода со страницы входа или признака успеха (до 15 с). Ответ: `logged_in` / `submitted` / `still_on_login` (капча, SMS, неверный пароль — человек завершает вход сам — в окне Chrome gate4ai или в просмотре сеанса в Web UI, «Браузер»). Значений, текста страницы и DOM в ответе нет. Поле кода (без `value` и `secret`) `browser.login` пропускает.
- **Сложный вход** (несколько шагов, выбор способа, SMS, «запомнить устройство») — не в ядре и не во встроенном браузере, а в **коннекторе входа**: обычный WASM-коннектор с действием `login {account}`, который проходит шаги действиями браузера (`observe` до ввода секретов, `act`, `fill_secret`, `wait`) и возвращает `{status}`. Агент и другие коннекторы всегда вызывают `browser.login(account)`; если у учётки `via`, daemon сам вызывает `<коннектор>.<действие>` с тем же `account` вложенным вызовом (тот же корень и страница, в сеансе агента — его страница). Коннектор входа значений тоже не видит; поля, которые он вводит, — `via.fields` (константа или секрет Vault).
- **`browser.fill_secret {account, field, selector, source}`** — одно поле учётки в элемент страницы, без отправки (примитив коннекторов входа): те же проверки origin и поля. `selector` вызывающего принимается только у коннектора входа учётки (`via`); для учётки с `form` поле задаёт владелец (селектор поля в учётке), а если селектор не задан — только `input[type=password]`. `source: human` — код от человека: вопрос (владельца из `prompts` учётки, иначе — от коннектора входа, одной строкой, не длиннее 200 символов) приходит в канал подтверждений (уведомление, Web UI, Telegram — ответ сообщением, сообщение с кодом бот удаляет; `gate4ai approvals answer <id>`); ответ сразу идёт в поле и в маскирование ответов, коннектору не возвращается. Текст, присланный агентом, человеку не показывается (нейтральный «a one-time code»); кто спрашивает и для какого сайта — показывает канал.
- **Значения.** daemon передаёт встроенному браузеру значения только в этих двух действиях — в `ExecRequest.Revealed`, форму — в `ExecRequest.Login`, учётки вызывающего без значений — в `ExecRequest.Accounts`.
- **Доступ:** агенту — если его профиль в `use`; коннектору — если он в `connectors`, это коннектор входа учётки (`via`) или его слот связан с учёткой (`connectors.<коннектор>.credentials: {login: "@emias"}`, а `bind` учётки — в `bind` слота из манифеста). Иначе `secret_denied` и запись в журнал. Можно ли вызвать `browser.login` вообще, решает политика (класс `write`, в CEL доступен `account`): разрешает его только правило, которое называет действие (`action: browser.login` / `browser.fill_secret`), — шаблон `browser.*` или `*` вход не покрывает, и без такого правила вход спрашивает владельца (`policy.ExplicitOnly`).
- **Слоты в манифесте:** `credentials: [{slot, bind, description, types, fields}]` (`types`: `form` — учётка с формой, `via` — с коннектором входа; учётка другого вида слоту не подходит; `fields` — поля, которые коннектор вводит сам); слоты показываются в согласии. Коннектор передаёт в `browser.login` / `fill_secret` имя слота или алиас.
- **Сайты:** страница может находиться на origin из `bind` учёток, доступных вызывающему, даже вне его сайтов (строк `sites` коннектора и списка доступа Браузера) — редирект на вход страницу не закрывает. Но вложенные вызовы коннектора на такой странице (`browser.login`, `observe`, `act`) проверяются по его строкам `sites` (`pipeline.accessOf`), поэтому коннектор, который входит сам, перечисляет сайт входа в `sites`. На таком origin (а с `login_page` — только на странице входа) ответы `open` / `observe` / `network` содержат `login_required: {account}` — подсказку вызвать `login`.
- **Журнал:** каждое использование — событие `secret.use`: алиас, поле, origin страницы, агент или коннектор, `parent` — квитанция действия. Значение не записывается никогда.

### Режим «секрет на странице»

Действует до навигации верхнего документа:
- `observe` и `network` запрещены (`secret_on_page`);
- разрешены `click`, `press`, `wait` и `fill_secret`; ввод текста (`fill`, `append`, `paste`, `type`) запрещён; ответ `act` в этом режиме — без текста элемента, значения поля и изменений страницы (`changes`);
- `text`, `expect_text` и `wait_for_text` не сопоставляются со значениями полей (иначе значение подбиралось бы по ответам «да/нет»);
- значение `input[type=password]` не читается никогда — ни в этом режиме, ни вне его;
- скриншоты делаются с закрашенными полями секрета и пароля (поля пароля закрашиваются на любом снимке, и вне этого режима: снимки уходят в журнал доказательствами и в файлы).

## Политики и подтверждения

- **Одно подтверждение на действие.** Учётка используется только внутри действия агента — других учёток коннектору не достать. Поэтому её использование отдельно не подтверждается: его покрывает решение по самому действию (`allow` или подтверждённый `ask`). Пример: «перевести через Т-Банк» спрашивается один раз, второго вопроса «отдать ли пароль от Т-Банка» нет.
- Запрос подтверждения перечисляет учётки, которые действие может использовать: «войдёт с учёткой @amazon на https://www.amazon.com».
- `secret.use` — событие журнала со ссылкой на квитанцию действия (`parent`), а не отдельное решение pipeline.
- Вход коннектором входа (`via`) ядро вызывает внутри того же действия от имени того же агента: политика проверяется (`deny` — вход не состоялся), а `ask` покрыт подтверждением исходного действия; в журнале — с `parent`.

## Ключи агентов

Ключ агента — не секрет сервисов, а его имя для daemon: он не даёт ничего сверх профиля агента.

- **Где лежит.** Каталог ключей — `<данные gate4ai>/agents/<агент>.json` (`paths.AgentKeys()`, `GATE4AI_HOME` переопределяет), права 0600, по файлу на агента: имя, тип агента (`claude-code`…), ключ, каталог привязки, адрес устройства (агент на другом компьютере), пока владелец не решил — id запроса и код. Файл пишет CLI агента при спаривании или Web UI при автоподключении; daemon хранит только sha256 ключа (таблица `tokens`; привязка к каталогу — `token_dirs`).
- **Спаривание.** CLI создаёт ключ сам и отправляет только его хэш (`POST /v1/pair`); код для сверки придумывает daemon; одобрение (Web UI, Telegram) превращает хэш в токен агента. Ждущих запросов — не больше 10 на канал (сокет агентов, публичный адрес), срок — 15 минут.
- **Кто может прочитать.** Файлы ключей читает любой процесс того же пользователя ОС — как и прежний токен в `~/.claude/settings.json`. Ключ с привязкой к каталогу daemon принимает только от агента, запущенного в этом каталоге (по процессу-собеседнику сокета), удалённо — никогда; это защищает от чужой сессии и случайного использования, но не от процесса, который нарочно отвязался от агента. Агенту в песочнице (`gate4ai run`) каталог ключей не виден: у запуска свой токен.
- **Отзыв.** Отзыв агента в Web UI отзывает и его ключи; CLI с отозванным ключом получает `unauthorized` с путём файла ключа.

## Агенты в песочнице

Egress Proxy подставляет секреты в HTTPS-запросы агентов, запущенных через `gate4ai run`:
- **Настройка:** `egress.secrets[]` — `{domain, header, env, placeholder, secret, agents}`. `domain` — точный хост (origin `https://<хост>:443`) или точный https-origin, без wildcard. `agents` — агенты, которым доступна подстановка (пусто — всем агентам, у которых домен разрешён профилем).
- **Заглушки** — всегда **одноразовые на запуск** (`env` обязателен): `gate4ai run` получает от daemon свою заглушку `<placeholder или gate4ai>-<32 hex>` в переменной `env` (окружение агента, в контейнере — env-file), и прокси принимает только заглушку этого запуска (учётные данные прокси определяют запуск).
- **Расшифровка.** HTTPS расшифровывается собственным CA песочницы (передаётся агенту через `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE`, `GIT_SSL_CAINFO`). Подстановка — только в HTTPS, в обычный HTTP — никогда (заглушка в нём — `403 secret_denied`).
- **Подстановка.** Значение заголовка — заглушка целиком (можно со схемой: `Bearer <заглушка>`), его заменяет настоящий ключ; заглушка в URL или другом заголовке — `secret_denied`; заглушка в теле не проверяется (секрет туда не подставляется). `Host` внутреннего запроса должен совпадать с хостом CONNECT (иначе `421`: ключ не уходит на чужой хост за тем же фронтом).
- **Ответы.** Маскируются (значения и производные формы, заголовки и тело) и отдаются потоком (SSE); сжатие у сервера не запрашивается (`Accept-Encoding: identity`), gzip/deflate распаковываются до маскирования, прочее — `502`.
- **Локальные адреса.** Соединения на адреса этой машины и частных сетей (loopback, private, link-local, multicast, unspecified — проверяется IP, с которым действительно соединяемся, после резолва) запрещены, если хост (имя или IP) не указан явно, без wildcard, в `allow_domains` / `ask_domains` профиля.
- **Срок запуска.** Запуск живёт, пока его продлевает `gate4ai run` (`POST /v1/runs/{id}/keepalive` каждые 5 минут): токен запуска выдаётся на 30 минут и продлевается, учётные данные прокси без продления перестают действовать — если CLI убит, запуск гаснет сам. Токен запуска и пароль прокси не попадают в argv (`srt` — окружение, контейнер — env-file, `--microvm` — `-e ИМЯ` со значением в окружении процесса docker) и в вывод `--dry-run`.

## Тесты

Только на фейках: страница с формой, скрытым полем и iframe чужого origin, фейковый CDP, HTTPS-сервер с эхо заголовков для Egress Proxy.
