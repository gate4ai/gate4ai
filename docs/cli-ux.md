# Интерфейс владельца: CLI `gate4ai`, трей и Web UI

Как владелец и агент работают с `gate4ai`, `gate4ai-tray`, установщиком и Web UI. Поведение команд — по `gate4ai --help` (`usage` в `internal/front/cli/cli.go`); устройство кода — [architecture.md](architecture.md).

## 1. Как устроено

- Один бинарник `gate4ai`. `gate4ai daemon` — долгоживущий процесс; остальные команды, кроме офлайн-команд (раздел 2), — тонкие клиенты к daemon через сокет.
- Сокет владельца — `paths.OwnerSocket()`:
  - Linux: `$XDG_RUNTIME_DIR/gate4ai/gate4ai.sock` (обычно `/run/user/<uid>/gate4ai/gate4ai.sock`), без `XDG_RUNTIME_DIR` — `~/.local/state/gate4ai/run/gate4ai.sock`; клиент ищет сокет по обоим путям (`paths.FindOwnerSocket`);
  - macOS: `~/Library/Application Support/gate4ai/run/gate4ai.sock`;
  - Windows: named pipe `\\.\pipe\gate4ai-<SID>` (агентский — `gate4ai-agent-<SID>`: SID пользователя, а не короткое имя, иначе у `PC\alex` и `CORP\alex` канал общий).

  Если задан `GATE4AI_HOME`, сокет лежит в `$GATE4AI_HOME/run/`. Явный путь задают `GATE4AI_SOCKET` и `GATE4AI_AGENT_SOCKET`. Длина пути сокета проверяется до запуска (предел 108 байт на Linux, 104 на macOS).
- Токен агента в `GATE4AI_TOKEN` переключает клиента на сокет агентов, а вместе с `GATE4AI_URL` — на HTTPS к публичному адресу устройства.
- Без токена CLI сам узнаёт агента (`internal/platform/agentid`): `GATE4AI_AGENT` (имя), признаки в окружении (`CLAUDECODE=1`, `CODEX_SANDBOX`, `GEMINI_CLI`…), процессы-предки (`claude`, `codex`…; корень — самый внешний агент, каталог — его каталог запуска). Тогда он берёт ключ агента из каталога ключей (`paths.AgentKeys()` = `<данные>/agents/<агент>.json`, 0600; `internal/platform/agentkeys`): по имени, иначе по типу — сначала ключ с привязкой к каталогу агента (самый глубокий), затем общий ключ типа. Ключа нет — агентская команда (`tools`, `status <id>`, `skill`, `mcp`, `pair`, действия) создаёт ключ и запрос на подключение (`POST /v1/pair` на сокете агентов или публичном адресе, только хэш ключа) и отвечает `{"status": "pending", "code": "K7Q-4FM", "error": {"code": "pairing_required", …}}`, выход `3`; повтор до решения — тот же код; подтверждение — `GET /v1/pair/{id}` (`?wait=` — долгий опрос). Команда владельца от агента без ключа запроса не создаёт: daemon отвечает `agent_required`. `gate4ai mcp` проверяет подключение при каждом вызове, пока владелец не подтвердит. `GATE4AI_OWNER_CHECK=off` (тестовый стенд, который запустил агент) — агента не искать ни в CLI, ни в daemon; действует только в сборке с тегом `gate4ai_devstand` (`agentid.CheckOff`), в выпускаемых бинарниках переменная не действует: иначе агент перезапустил бы daemon с ней и вошёл на сокет владельца. e2e, запущенные агентом, собирают бинарники с этим тегом.
- `gate4ai pair [--here] [--name <агент>] [--wait 5m]` — подключить агента явно; `--here` — ключ только для агента из каталога запуска (имя по умолчанию — `<тип>-<папка>`); с `GATE4AI_URL` ключ запоминает адрес устройства.
- Коды выхода (`internal/front/cli/client.go`): `0` ok, `1` ошибка, `2` отказ политикой, `3` ждёт подтверждения, `4` проверка не прошла, `5` usage / 400 / 404, `6` daemon недоступен, `7` вызывающему нельзя (`unauthorized`, `owner_only`, `agent_required`). От формата вывода не зависят.
- Строковый аргумент действия — из файла: `--<имя>_file путь` (`-` — stdin, до 16 МБ); `--help` действия показывает варианты, длину и диапазон каждого аргумента.

## 2. Команды

| Команда | Кто | Нужен daemon |
|---|---|---|
| `help`, `version` | все | нет |
| `ui [--print] [--remote] [--start\|--no-start]` | владелец | да (в терминале запускает его сам) |
| `status` / `status <id> [--wait 10m] [--out f]` | владелец / агент | да |
| `daemon [флаги]`, `daemon start \| stop \| restart \| status` | владелец | — |
| `service install [--no-tray] [-- флаги daemon] \| uninstall \| status` | владелец | нет |
| `tools [--json] [--as agent]`, `<connector> <action> [--arg v] [--wait] [--json] [--as] [--out f]`, `skill`, `mcp` | агент / владелец | да |
| `pair [--here] [--name agent] [--wait 5m]` | агент | да |
| `log`, `show`, `export`, `journal verify` | владелец | да |
| `verify file [--pubkey] [--passphrase-env]` | все | нет |
| `agents`, `policy`, `approvals`, `vault`, `access [sites \| folders [set <v> <режим> \| remove <v>]]`, `sites allow \| remove` (= `access sites set <сайт> allow`), `relay`, `connectors list \| install \| update \| remove \| logs \| refresh` | владелец | да |
| `connectors new \| pack \| verify \| keygen`, `registry check \| sign \| add`, `fixture scrub`, `contract gen \| diff` | автор / издатель / registry | нет (`registry check --fetch` ходит в сеть) |
| `run <agent> [--workspace --container --microvm --image --engine --dry-run] [-- cmd]`, `egress` | владелец | да |
| `doctor` | все | частично |

- Неизвестное первое слово CLI считает именем коннектора и запрашивает каталог у daemon. Опечатку в команде, коннекторе или действии CLI поправляет подсказкой ближайшего имени (Дамерау — Левенштейн), в том числе без daemon.
- `--help` у любой подкоманды и действия — справка и код 0.
- Картинки и файлы в ответе действия и `status <id>` CLI не печатает base64 (вместо него — `bytes`, у файла и `sha256` с подсказкой `hint` про `--out`); `--out файл` сохраняет первую картинку или файл ответа (двоичный `resource` — `browser.download`, `files.read`; права 0600) в файл на стороне агента, путь — в `result.file` и у блока; sha256 записанного файла сверяется с `result.sha256` (не совпал — `io_error`); ни картинки, ни файла в ответе нет — ошибка (`page_screenshot` и без `--out` отдаёт файл в каталоге данных gate4ai, `browser-shots`).
- `--out` переживает подтверждение: с `--wait` файл пишется после решения; ответ `pending` (выход `3`) несёт `hint` с точной командой `gate4ai status <id> --wait 10m --out <абсолютный путь из исходного --out>`, и `status <id> --out f` сохраняет файл итога.
- `gate4ai skill` печатает навык для текущего каталога и заодно заменяет установленный навык Claude Code прежней версии (`~/.claude/skills/gate4ai/SKILL.md` с полным текстом) обёрткой «выполни `gate4ai skill`»; то же делает daemon при старте.
- Опции `--json`, `--wait`, `--as`, `--out` команды действия ставятся в любом месте (`gate4ai files list --path ~/x --json`), если у действия нет аргумента с таким именем; `--json` без значения — вывод JSON.
- Пустые состояния (`tools`, `log`, `agents`, `connectors list` на свежем daemon) печатают в stderr подсказку, что делать дальше.
- `gate4ai access` печатает оба списка доступа (сайты Браузера, папки Файлов) с режимом строки; `set` и `remove` отвечают новой версией политики. Браузер и Файлы встроены: в `connectors list` и в магазине их нет.
- `connectors install` спрашивает согласие на возможности в терминале; без терминала нужен `--yes`, отказ виден в выводе.

## 3. Человек или скрипт

По тому, куда подключены потоки (`term.IsTerminal` из golang.org/x/term: `ioctl TCGETS` на Linux, `TIOCGETA` на macOS, `GetConsoleMode` на Windows; `/dev/null` терминалом не считается):

- **формат вывода** — по stdout: терминал — таблицы (агенты, подтверждения, коннекторы, хранилище, версии политики, состояние daemon, relay и автозапуска) и текстовые ошибки с подсказкой; pipe или файл (`| jq`, `$(…)`, агенты, cron, CI) — JSON. `--json` или `GATE4AI_OUTPUT=json` дают JSON и в терминале, `GATE4AI_OUTPUT=table` — таблицы везде;
- **подсказки** в stderr — только если stderr — терминал;
- **запуск daemon из `gate4ai ui`** — только если stdin и stderr — терминал и нет `--print`.

Псевдотерминал (`ssh -t`, `script`, `expect`, CI с pty) выглядит как человек — для него `--json` или `GATE4AI_OUTPUT=json` и `gate4ai ui --no-start`.

## 4. Ошибки

Ответ в JSON — единый конверт `{"status", "result"?, "error"?: {"code", "message", "hint"?, "detail"?}}`: у результата действия (`internal/pipeline` — `Result.MarshalJSON`), ошибки CLI и API daemon (`WriteError`) одна форма; `error` есть у любого статуса, кроме `ok`. Ошибка: короткое `message` без дубля кода, `hint` — что делать, `detail` — техническая причина (`internal/front/cli/errors.go`: `Explain`, `UnavailableError`).

Daemon недоступен (`unavailable`, exit 6) — по причине:

| Причина | message | hint |
|---|---|---|
| сокета / pipe нет | daemon is not running | `gate4ai daemon start` / `gate4ai service install` |
| `ECONNREFUSED` на оставшемся сокете | it stopped or crashed, the socket is left over | то же + путь к `daemon.log` |
| путь сокета длиннее предела | the daemon socket path is too long (длина и предел) | задать `GATE4AI_SOCKET` короче или `GATE4AI_HOME` |
| сокет другого пользователя | socket belongs to another user | запускать от того же пользователя |
| удалённый агент (`GATE4AI_URL`) | device is offline | агент повторяет позже |

Агенту (токен или ключ) подсказка другая: «попросите владельца запустить gate4ai». `unauthorized` с ключом из каталога ключей называет файл ключа (отозван, неизвестен или не для этого каталога); с токеном — подключить агента заново или `gate4ai agents token <agent>` у владельца. `agent_required` у агента — подключиться своим ключом (или назвать себя `GATE4AI_AGENT`), у команды владельца — готовая команда для владельца, у владельца без `--as` — назвать агента. `pairing_rejected` (выход `7`) — владелец отклонил подключение, не повторять.

Пример — скрипт без daemon:

```
$ gate4ai ui --no-start | cat
{
  "error": {
    "code": "unavailable",
    "detail": "no socket at /run/user/1000/gate4ai/gate4ai.sock",
    "hint": "start it: gate4ai daemon start (in the background) or gate4ai service install (also at every login); gate4ai daemon runs it in this terminal",
    "message": "gate4ai daemon is not running"
  },
  "status": "error"
}
```

## 5. Запуск daemon и вход в Web UI

- `gate4ai ui` в терминале без запущенного daemon поднимает его в фоне, ждёт `GET /v1/health` до 5 секунд, печатает адрес Web UI и открывает браузер (`xdg-open` / `open` / `rundll32`):

  ```
  $ gate4ai ui
  Starting gate4ai daemon in the background (log: ~/.local/state/gate4ai/daemon.log)…
  gate4ai daemon is running. Stop it: gate4ai daemon stop. Start it at every login: gate4ai service install
  Web UI:
  http://127.0.0.1:7431/
  ```

  Без графической сессии (`ssh`) — подсказка `gate4ai ui --remote` (нужен relay или `--public`) или проброс порта `ssh -L 7431:127.0.0.1:7431`.
- `gate4ai daemon start | stop | restart | status` — фоновый daemon, журнал `<home>/daemon.log`; остановка — `POST /v1/shutdown`. `gate4ai daemon` без подкоманды работает в этом терминале.
- Повторный daemon проверяет сокет владельца раньше, чем открывает Web UI и публичный адрес: `already running (socket …)`.
- `gate4ai status` без id — состояние daemon (health, relay, число ожидающих подтверждений).

## 6. Автозапуск и установщик

`gate4ai service install | uninstall | status` (`internal/platform/autostart`, тот же механизм — в Web UI, Настройки):

| ОС | Механизм |
|---|---|
| Linux | systemd user unit `~/.config/systemd/user/gate4ai.service` (`Restart=on-failure`, `systemctl --user enable --now`); без systemd — `~/.config/autostart/gate4ai.desktop`; трей — `gate4ai-tray.desktop` в autostart |
| macOS | LaunchAgent `~/Library/LaunchAgents/ai.gate4.daemon.plist` (`RunAtLoad`, `KeepAlive`) и отдельный для трея |
| Windows | ключ `HKCU\…\Run`, без прав администратора |

Состояние автозапуска — три варианта: служба работает / включена, но daemon сейчас запущен не службой / выключена.

Установщик (`curl -fsSL https://gate4.ai/install.sh | sh`, `install.ps1`) кладёт бинарники, по умолчанию включает автозапуск (`GATE4AI_NO_START=1` — не включать) и в графической сессии сам открывает Web UI — мастер первого запуска (`GATE4AI_NO_OPEN=1` — не открывать); «Next steps» — одна строка `gate4ai ui`.

## 7. Трей

`gate4ai-tray` раз в 5 секунд опрашивает `GET /v1/tray/state` через тот же клиент, что и CLI: статус, уведомления, быстрые «Разрешить / Отклонить» (`gate4ai.*` — только в Web UI), «Открыть Web UI». Когда daemon недоступен — пункт «Запустить daemon» и строка с причиной; уведомление об ошибке — `message` и `hint`. Язык — русский при русской локали (`GATE4AI_LANG`, затем `LC_ALL`, `LC_MESSAGES`, `LANGUAGE`, `LANG`), иначе английский. На macOS трей собирается только с cgo, на Windows — с `-H windowsgui`; уведомления на Linux — через D-Bus.

## Web UI

Страницы отрисовываются на сервере шаблонами Go (`internal/front/webui`) и работают без JavaScript; небольшой `static/app.js` с того же origin добавляет копирование, окна, подтверждение опасных кнопок и живую очередь подтверждений. Действие «в процессе»: сразу после нажатия — до ответа сервера — кнопка любой POST-формы (и ссылка или GET-форма с `data-busy`, например «Установить» у коннектора) показывает спиннер и текст из `data-busy` («Установка…», «Сохранение…»; без него — прежний текст), кнопки формы выключены, второе нажатие не отправляет ничего; итог показывает ответ сервера — плашка успеха или окно ошибки. CSP: `default-src 'self'`, `form-action 'self'`, `frame-ancestors 'none'`; `Referrer-Policy: same-origin` (с `no-referrer` браузер отправлял бы формы с `Origin: null`, а проверка Origin их отклоняет).

- **Адрес:** `http://127.0.0.1:7431/` на этом компьютере; удалённо — `<публичный адрес>/ui/` (relay или `--public`). Удалённо доступны только главная, подтверждения и журнал (и подписка на push); страницы настройки показывают «только на этом компьютере».
- **Вход:** защита входа — в спецификации («Защита входа в Web UI»); код — `protect.go`. `gate4ai ui`, трей, `--remote` и QR-код в Настройках дают только адрес Web UI: сессию даёт пароль (попытка входа — cookie на 5 минут). Сессии — в памяти daemon: после перезапуска нужен новый вход. Сброс защиты — `gate4ai daemon --reset-ui-login` (уведомление в Telegram, если бот подключён).
- **Меню из 7 разделов:** Главная (очередь подтверждений, агенты с последним обращением, последние действия, состояние) · Агенты · Доступ (Браузер, Файлы, Коннекторы, Правила, Готовые правила — вкладками) · Браузер · Пароли и учётки · Журнал · Настройки (Основные, Уведомления, Вход; «Расширенные»: Доступ из интернета, Магазин и журнал). На телефоне меню — нижней панелью.
- **Мастер первого запуска** `/setup`: ассистент (найденные на компьютере — сверху) → что можно (папки, сайты, решения по группам действий «читать / менять / отправлять / платить»: разрешать · спрашивать · запрещать; папки записываются строками в список доступа Файлов с режимом по выбранным решениям — `accessMode`: обе «разрешать» → `allow`, чтение без вопроса → `read`, чтение с вопросом → `ask`, запрет → `deny`; у Браузера одна группа «Сайты из списка» — её решение и есть режим строк списка сайтов; правил на них не пишется) → проверка (фраза для ассистента, живая лента обращений и первое подтверждение, каналы на телефоне, автозапуск). Свежая установка без агентов открывает его сама; новый агент добавляется через него.
- **Агенты:** последнее обращение («3 мин назад через MCP»), автоподключение клиентов (Claude Code, Claude Desktop, Cursor, VS Code, Codex CLI, Gemini CLI) с резервной копией файла конфигурации клиента и ручная инструкция (без секрета: в `env` — только `GATE4AI_AGENT`, ключ — в каталоге ключей), облачный агент — адрес устройства и код подключения, токены (с каталогом привязки), отзыв и удаление с подтверждением.
- **Запросы на подключение** (Главная, Подтверждения, Агенты): агент, крупный код для сверки с чатом агента, каталог привязки, процессы и сессия, предупреждения (ещё запросы того же агента, доступ уже отзывался), выбор прав нового агента (по умолчанию — права агента того же типа или новые пустые); «Разрешить подключение» / «Отклонить» — только локально (удалённо — подсказка: на компьютере или в Telegram). Telegram — то же сообщением с кнопками, уведомление на рабочем столе ведёт в Web UI (с `GATE4AI_DESKTOP_NOTIFY=log` у daemon — e2e, стенд — вместо него и других уведомлений на рабочем столе запись `desktop notification` в журнале daemon). В журнале — папка агента (запись журнала: папка, «со слов агента» для удалённого CLI, сессия).
- **Браузер** (`/browser`) **и Файлы** (`/files`): таблица списка доступа — строка (сайт или папка) с выбором режима, удаление, добавление; ниже — настройки компонента и решения по действиям для профиля. `/connectors/browser` и `/connectors/files` ведут на эти страницы.
- **Коннекторы** (`/connectors`): магазин (только WASM) и установленные; установка — экран согласия с возможностями человеческим языком, доступ получают только отмеченные в форме профили; «Поставить не из магазина» — путь к папке или `.g4c` или адрес `https://…/*.g4c`; настройки — поля из шаблонов `${setting:…}` манифеста, секретное поле сохраняется в Vault; «Переустановить» (в карточке и на странице коннектора) — та же версия из того же источника (registry, файл, адрес или папка с исходниками) заменяет установленную копию с прежним согласием, настройки, учётки и правила остаются, изменились возможности — снова экран согласия; решение по каждому действию для профиля; подвызовы и их причины (`call_reasons`); таблица сайтов и папок коннектора (`connectors.<имя>.sites/folders`, из манифеста при установке) с предупреждением, если список Браузера или Файлов закрывает строку (`deny`) или спрашивает (`ask`).
- **Готовые правила:** «Заметки в папке» записывает папку в список Файлов как `append`, «Сайты из списка» — сайты в список Браузера как `allow` (плюс правила `deny` вне папки / списка).
- **Правила:** профили, таблица правил человеческим языком (правила, отличающиеся только последней частью действия, — одной раскрывающейся строкой), форма правила одной фразой с блоками условий (генерирует CEL; сырой CEL — отдельным блоком), готовые правила с предпросмотром, списки, симулятор по схеме аргументов, версии и откат, YAML для технических пользователей.
- **Подтверждения:** запрос человеческим языком (что, почему, сколько осталось, предпросмотр; технические детали — под спойлером); у запроса по сайту или папке (`Decision.Scope`) — «Добавить <сайт> в разрешённые / запрещённые» (сайт → `allow`; папка — по операции: `read` / `append` / `allow`; `deny`), у остальных — «Разрешать всегда в <папке> / на <сайте>»; для `gate4ai.change_policy` — текст запроса из ядра как есть. Живая очередь: `app.js` раз в 3 секунды запрашивает `GET /approvals/live`; решённые в другом канале запросы заменяются строкой «Уже решено…». Счётчик у «Главной» в шапке обновляется тем же опросом на любой странице: без очереди запрашивается только число (`?count=1`). Каналы (рабочий стол, Telegram с мастером подключения, браузерный push) — одним списком со статусом и тестом.
- **Журнал:** фильтры, квитанция человеческим языком (сырой JSON — под спойлером), команда `gate4ai export`.
- **Сообщения после действия** — в сессии (один раз), в адресе только `?msg=<id>`; ошибки — окном, частые сетевые ошибки Go — человеческим языком (`errview.go`).
- **Языки:** основной — английский, русский — перевод (`i18n_ru.go`); переключатель в шапке и в Настройках (cookie `g4a_lang`), по умолчанию — `Accept-Language`.
- **Доступность:** подписи у всех полей, `<nav aria-label>`, `aria-current`, решения — кнопками с `aria-pressed`, ссылка «К содержимому».
