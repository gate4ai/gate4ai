# gate4.ai — страж вашего компьютера для AI-агентов

gate4.ai — страж для вашего компьютера: через него любой AI-агент (Claude.ai, ChatGPT, Claude Code, OpenClaw, Hermes) получает ограниченный и настраиваемый доступ к разнообразным [коннекторам](https://gate4.ai/connectors) — например, к почте, файлам, браузеру и сайтам, у которых нет API.

Вы сами настраиваете, на что именно есть права у каждого AI-ассистента: что разрешено сразу, что запрещено, а что требует вашего подтверждения (уведомление, Telegram, Web UI). Ни AI-ассистент, ни коннекторы и скиллы не знают ваших паролей: секреты подставляет сам gate4ai, а каждое действие попадает в журнал с доказательством.

Одни правила работают для всех ваших агентов: локальных (через CLI или MCP по stdio) и облачных (через relay или ваш HTTPS-адрес). Подробное описание продукта — в [спецификации](docs/specification.md).

## Установка

macOS и Linux:

```sh
curl -fsSL https://gate4.ai/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://gate4.ai/install.ps1 | iex
```

Установщик определяет ОС и архитектуру, скачивает последний релиз, сверяет контрольные суммы и кладёт `gate4ai` и `gate4ai-tray` (значок в трее: статус, «Разрешить / Отклонить», открытие Web UI; изменения настроек gate4ai, которые просит агент, разрешаются только в Web UI, где видны все правки) в каталог из `PATH`. Проверка: `gate4ai --version`.

Вручную — архивы со страницы [Releases](https://github.com/gate4ai/gate4ai/releases) (контрольные суммы подписаны [cosign](https://github.com/sigstore/cosign)) или из исходников: `go install github.com/gate4ai/gate4ai/cmd/gate4ai@latest` (Go 1.27+).

## Первый запуск

### 1. Daemon

```sh
gate4ai ui                 # Web UI в браузере: мастер первого запуска
```

Установщик сам включает автозапуск (daemon сейчас и при каждом входе в систему, трей — тоже; без него — `GATE4AI_NO_START=1`) и, если есть графическая сессия, открывает Web UI (`GATE4AI_NO_OPEN=1` — не открывать). Вручную автозапуск — `gate4ai service install`.

Daemon держит политики, секреты, журнал и коннекторы. Автозапуск: systemd --user (Linux; без systemd — автозапуск рабочего стола), LaunchAgent (macOS), ключ `Run` в реестре пользователя (Windows); убрать — `gate4ai service uninstall`, проверить — `gate4ai service status`.

Без автозапуска: `gate4ai daemon start` — в фоне до выхода из системы (`gate4ai daemon stop` — остановить), `gate4ai daemon` — в этом терминале (остальные команды — в другом). `gate4ai ui`, запущенный в терминале, сам поднимает daemon в фоне, если он не работает; `gate4ai status` — работает ли daemon и та ли у него версия (после обновления старый процесс — предупреждение); `gate4ai daemon restart` — перезапустить с теми же флагами. `install.sh` при обновлении перезапускает работающий daemon сам. Журнал фонового daemon — `daemon.log` в каталоге данных.

Ссылку входа из `gate4ai ui` может получить и агент, запущенный на этом же компьютере. В **Настройки → Вход** выберите способы входа (кнопки в строке каждого способа; «Включить» подтверждение в Telegram без подключённого бота открывает мастер подключения бота, в конце которого подтверждение входа и включается) — их можно сочетать, нужно пройти все включённые: одноразовая ссылка (по умолчанию — только она), пароль, подтверждение входа в вашем Telegram-боте (на телефоне). Например, пароль без ссылки — входите всегда по адресу `http://127.0.0.1:7431/` и вводите пароль; ссылка + Telegram — после ссылки нажмите «Разрешить вход» в боте. То же действует для входа с телефона: без ссылки откройте сохранённую закладку `https://<адрес устройства>/ui/` и введите пароль. После 5 неверных паролей подряд каждая попытка ждёт вдвое дольше (до 15 минут); у входа с телефона свой счётчик. Забыли пароль — остановите daemon и запустите `gate4ai daemon --reset-ui-login`.

Данные лежат в `~/.local/state/gate4ai` (Linux), `~/Library/Application Support/gate4ai` (macOS), `%LOCALAPPDATA%\gate4ai` (Windows); ключи — в системном keychain. На сервере без keychain: `gate4ai service install -- --keystore file` (или `gate4ai daemon --keystore file`); чтобы служба работала без входа в систему — `loginctl enable-linger $USER`.

Дальше всё можно сделать в Web UI. Свежая установка открывает **мастер первого запуска**: выберите ассистента (найденные на компьютере — сверху: Claude Code, Claude Desktop, Cursor, VS Code / Copilot, Codex CLI, Gemini CLI; облачные Claude.ai и ChatGPT; скрипт), отметьте, что ему можно — папки для файлов, сайты для браузера и по каждой группе действий «разрешать / спрашивать / запрещать», — и gate4.ai сам впишет себя в настройки ассистента. На шаге «Проверка» — фраза, которую можно попросить ассистента, и живая лента: первое обращение, первое подтверждение. Разделы Web UI: **Главная** (запросы, которые ждут решения, агенты, последние действия), **Агенты**, **Доступ** (коннекторы, правила, готовые наборы правил; YAML — для технических пользователей), **Журнал**, **Настройки** (основные, уведомления — рабочий стол, Telegram с мастером, браузерный push; пароли и учётки; вход; доступ из интернета и магазин — в «Расширенных»). Интерфейс на английском и русском: переключатель — в шапке и в Настройках, по умолчанию — язык браузера. В запросе подтверждения кнопка «Разрешать всегда в <папке> / на <сайте>» сразу записывает правило по аргументам запроса. Агент может попросить изменить настройки (`gate4ai.change_policy`: сайты, правила, учётки, коннекторы) — всегда с вашего подтверждения (правило «разрешать» на это не действует); запретить и спрашивать — в Настройках. Правило-шаблон `browser.*` → «разрешать» не покрывает запросы, меняющие данные на сайтах (`browser.post` / `put` / `patch` / `delete`), и вход учётками (`browser.login`, `fill_secret`): их разрешает только правило, где действие названо явно, — `gate4ai policy set` и Web UI об этом предупреждают. Ниже — то же из терминала.

### 2. Политика и магазин коннекторов

Создайте `config.yaml`. Пример ниже подключает магазин коннекторов, заводит одного агента и даёт ему читать заметки в `~/Documents/notes` без вопросов, а дописывать — только с вашего подтверждения:

```yaml
store:
  registry: https://raw.githubusercontent.com/gate4ai/registry/main/index.json
  registry_keys: ["ed25519:yDcbQuNCGqSqHSt08HdvW5/fNyWRW8FIXtKiL91hqtw="]
agents:
  my-agent: { profile: assistant }
profiles:
  assistant:
    connectors: [files]
    rules:
      - id: notes-read
        action: files.read
        when: glob(path, "~/Documents/notes/**")
        effect: allow
      - id: notes-append
        action: files.append
        when: glob(path, "~/Documents/notes/**")
        effect: ask
connectors:
  files:
    roots: ["~/Documents/notes"]
```

Правила ссылаются на действия коннекторов, поэтому сначала поставьте коннекторы, затем примените политику целиком. Файлы (`files`) встроены в gate4ai: в начальной конфигурации они уже в профиле `default` с корнем `~/Documents` и правилом «спросить» (`ask`) на каждое действие; скрытые файлы и папки, ключи и данные приложений закрыты всегда (открыть — `allow_hidden`, `allow_paths` в настройках коннектора). Магазин коннекторов тоже уже подключён, и коннектор `browser` новый daemon ставит из него сам (подпись проверяется, нужна сеть; без сети — при следующей возможности). Любой установленный коннектор daemon добавляет в профиль `default` с правилом `ask` на каждое его действие, включая чтение, — смотрите `gate4ai policy show`; ваши правила на те же действия не трогаются. Сайты (`allowed_domains`) пусты, пока вы их не зададите. Остальные коннекторы ставятся командой:

```sh
# 1) коннекторы: при установке показываются их возможности и спрашивается согласие
gate4ai connectors list                 # files встроен, browser уже стоит
gate4ai connectors install email

# 2) рабочая политика
gate4ai policy set config.yaml -m "первая политика"
gate4ai doctor
```

Свой коннектор ставится прямо из папки с исходниками: `gate4ai connectors install ./my-connector --watch` — собирает, ставит и пересобирает на каждое сохранение (подробнее — [docs/quickstart.md](docs/quickstart.md)). В Web UI то же — **Коннекторы → Поставить не из магазина**: папка с исходниками, файл `.g4c` или адрес сборки `https://…/*.g4c`, дальше — обычный экран согласия на возможности. Коннектор к сайту можно начать с заготовки `gate4ai connectors new <имя> --site <домен>` и писать вместе с агентом: он открывает сайт в сеансе браузера (`gate4ai browser open`, `observe --elements`, `act`, `network`, `close`) и сразу видит ответы — [docs/connector-authoring.md](docs/connector-authoring.md). Входить на сайт агент и коннекторы могут сами, не видя пароля: учётка — в `credentials` политики, пароль — `gate4ai vault set`, вход — `gate4ai browser login --account @имя` (см. [docs/quickstart.md](docs/quickstart.md)).

Если политика уже была задана без раздела `store`, сначала добавьте в неё `store` из примера выше (`gate4ai policy set`), затем ставьте коннекторы.

Пароли и токены в конфигурацию не пишутся: там только алиасы вида `"@mail.work"`, а значения кладутся в хранилище (из stdin, в историю shell не попадают):

```sh
printf %s 'пароль-приложения' | gate4ai vault set mail.work
```

Полная модель конфигурации — почта, браузер, лимиты, Telegram, песочница — в [docs/quickstart.md](docs/quickstart.md) и разделе «Политики» [спецификации](docs/specification.md#политики).

### 3. Подключение агента

**Агент с shell (Claude Code, Codex, Hermes, OpenClaw) — CLI + skill.** Токен вписывать не нужно: агент подключается сам. Первая же его команда `gate4ai` отвечает кодом подключения (выход `3`, `pairing_required`), агент показывает код вам в чате, а вы сверяете его с запросом в Web UI (**Агенты** или **Главная**) или в Telegram-боте и нажимаете «Разрешить подключение». После этого агент сразу работает своим ключом, перезапускать его не нужно. Ключ лежит в каталоге данных gate4ai (`agents/<агент>.json`, права 0600), daemon хранит только его хэш.

```sh
gate4ai tools                          # первый вызов: код подключения; после подтверждения — что разрешено профилю
gate4ai pair --wait 5m                 # то же явно, с ожиданием решения
gate4ai pair --here                    # отдельный ключ только для агента из этой папки проекта (свой профиль)
gate4ai files read --path ~/Documents/notes/todo.md
gate4ai skill > SKILL.md               # инструкция для агента
```

Агента CLI узнаёт по признакам, которые агент ставит своим процессам (`CLAUDECODE=1` и т.п.), и по процессам-предкам; имя можно задать и явно — `GATE4AI_AGENT=<агент>`. По умолчанию все сессии одного агента — один агент (`claude-code`) с одним профилем. Ключ, выпущенный `gate4ai pair --here`, принимается только от агента, запущенного в этой папке (или вложенной): daemon сам смотрит каталог запуска агента, `cd` в его shell этого не меняет. В журнал пишется папка, из которой агент выполнял действие. Агенту, которого узнал gate4ai, сокет владельца отвечает `agent_required`: свои же запросы он не одобрит. Граница честная: процесс того же пользователя ОС, отвязанный от агента и без его признаков, так не опознаётся. Изоляцию даёт только `gate4ai run` (ниже).

Скрипт или CI работают с токеном: `gate4ai agents token my-agent` (показывается один раз), затем `export GATE4AI_TOKEN=g4a_…`.

Коды выхода: `0` ok, `1` прочие ошибки, `2` запрещено политикой (`denied_by_policy`), `3` ждёт подтверждения (`pending_approval`), `4` проверка не прошла (`verification_failed`), `5` неверные аргументы или неизвестное действие, `6` daemon недоступен, `7` вызывающему нельзя: неверный или отозванный ключ / токен (`unauthorized`), команда владельца с ключом агента (`owner_only`), агент на сокете владельца или вызов владельца без `--as` (`agent_required`), владелец отклонил подключение (`pairing_rejected`). Код `3` — и ожидание подключения агента (`pairing_required`, в ответе — `code`). Агенты и скрипты получают JSON. Ответ — JSON в едином конверте: `{"status": "ok" | "denied" | "pending" | "verification_failed" | "error", "result": …, "error": {"code", "message", "hint", "detail"}}` — `result` при успехе, `error` в остальных случаях (у `pending` — что делать дальше). Длинный строковый аргумент — из файла: `--<имя>_file путь` (`-` — stdin), например `gate4ai browser act … --method fill --value_file article.md`; `--help` действия показывает допустимые значения и пределы аргументов. Человеку в терминале (stdout — терминал) списки и состояние показываются таблицей, а ошибки — текстом; JSON и там — `--json` или `GATE4AI_OUTPUT=json`.

**Claude Code.** Подключите его в Web UI (**Агенты → Claude Code**): gate4.ai впишет MCP-сервер в `~/.claude.json`, SKILL.md в `~/.claude/skills/gate4ai/`, ключ агента — в свой каталог ключей (кода тогда сверять не нужно: подключаете вы сами), а в `~/.claude/settings.json` — правило `"Bash(gate4ai *)"` в `permissions.allow`. Правило снимает второй вопрос о том же действии: решает политика gate4.ai, а Claude Code не спрашивает про каждую команду `gate4ai` отдельно. Токен в `env` больше не нужен: из Bash `gate4ai` сам находит ключ агента и работает с его правами, а не с правами владельца, — и в уже открытой сессии тоже. Прежний `GATE4AI_TOKEN` из `env` подключение убирает. Вручную — то же правило в `~/.claude/settings.json`:

```json
{"permissions": {"allow": ["Bash(gate4ai *)"]}}
```

`gate4ai doctor` проверяет это: подключён ли агент (Claude Code, Codex, Gemini CLI) своим ключом или его подключение ждёт подтверждения, есть ли правило в настройках Claude Code, не остался ли там прежний токен и не отстал ли SKILL.md от каталога действий (`gate4ai skill > ~/.claude/skills/gate4ai/SKILL.md`).

**MCP по stdio** (Claude Code, Claude Desktop и др.) — секрета в конфигурации нет, только имя агента:

```json
{"mcpServers": {"gate4ai": {"command": "gate4ai", "args": ["mcp"], "env": {"GATE4AI_AGENT": "claude-code"}}}}
```

**Изолированный локальный агент** — сеть и файлы только через gate4ai:

```sh
gate4ai run claude-code --workspace ~/projects/app
```

**Облачные агенты (Claude.ai, ChatGPT)** — через relay, без открытых портов:

```sh
gate4ai relay register --url https://relay.gate4.ai
gate4ai relay status                   # mcp_url: https://<device-id>.relay.gate4.ai
gate4ai agents connect my-agent        # одноразовый код подключения
```

Добавьте `mcp_url` в агенте как custom connector и введите код на странице авторизации. Свой HTTPS-адрес вместо relay — `gate4ai daemon --public …`, см. [docs/quickstart.md](docs/quickstart.md#3-агенты).

### 4. Подтверждения и журнал

```sh
gate4ai approvals list                 # запросы, которые ждут вашего решения
gate4ai approvals approve <id>         # или кнопки в трее, Telegram, Web UI
gate4ai ui                             # Web UI в браузере
gate4ai log                            # журнал действий
gate4ai journal verify                 # целостность журнала
```
